# Screens

Every canvas screen, the issue that builds it, its lane, route and component. The PNG is the target; the `.dc.html` has exact values. Linear tracks whether an issue is done.

A design PR adds rows for its screens inside their group. A build PR edits a row only when the screen's route or component file changes, so it doesn't add its key to the Issue column.

Route is the `Route` (or `Modal`, menu, banner or `WorkspaceView` state) in `src/shared/types/ui.ts` that shows the screen: `team` is `{ name: 'team', roomId }`, `modal newRoom` is `{ name: 'newRoom' }`, `+ menu pr` sets `ui.menu` to `'pr'`. Component is the file under `src/renderer/src/` that draws it. The lane that owns the row creates or replaces that file, and nobody else edits it. Files that exist today are placeholders or re-export the prototype in `screens/Pages.tsx`, `Floor.tsx`, `Workspace.tsx` or `Modals.tsx` (KERNEL-8). To see a screen, add its fixture to `fixtures/` and run `npm run shots -- <Screen>` then `npm run shots:compare -- <Screen>`.

These PNGs come from the app since KERNEL-97 (D-097), not from the canvas: Main, FloorSent, FloorPlanning, FloorPlan, FloorQuestion, FloorTalk, FloorOverlap, FloorHired, FloorPaused, FloorLimit, FloorOffline, FloorEmpty and FloorFull. Their `.dc.html` still draws the old floor. The floor is hidden (D-104), so they stay as they are, except that Main's PNG was refreshed from the app for the sidebar of D-139 (KERNEL-166). Every other PNG comes from the canvas, QuickAsk included again (D-109): change a template in `design/canvas/source/templates`, run `python3 design/canvas/source/build.py`, then `node design/canvas/source/render.mjs <Screen>` for each page whose markup changed. QuickAskNoSidebar and UpdateReadyNoSidebar come from the app too, rendered with `pnpm shots` (KERNEL-527), and so does PanelCollapsedRunning (KERNEL-529).
