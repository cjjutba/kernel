# Screens

Every canvas screen, the issue that builds it, its lane, route and component. The PNG is the target; the `.dc.html` has exact values. Linear tracks whether an issue is done.

A design PR adds rows for its screens inside their group. A build PR edits a row only when the screen's route or component file changes, so it doesn't add its key to the Issue column.

Route is the `Route` (or `Modal`, menu, banner or `WorkspaceView` state) in `src/shared/types/ui.ts` that shows the screen: `leadNew` is `{ name: 'leadNew', roomId }`, `modal newRoom` is `{ name: 'newRoom' }`, `+ menu pr` sets `ui.menu` to `'pr'`. Component is the file under `src/renderer/src/` that draws it. The lane that owns the row creates or replaces that file, and nobody else edits it. Files that exist today are placeholders or re-export the prototype in `screens/Pages.tsx`, `Workspace.tsx` or `Modals.tsx` (KERNEL-8). To see a screen, add its fixture to `fixtures/` and run `npm run shots -- <Screen>` then `npm run shots:compare -- <Screen>`.

Most PNGs come from the canvas (D-109): change a template in `design/canvas/source/templates`, run `python3 design/canvas/source/build.py`, then `node design/canvas/source/render.mjs <Screen>` for each page whose markup changed. UpdateReadyNoSidebar comes from the app, rendered with `pnpm shots` (KERNEL-527), and so does PanelCollapsedRunning (KERNEL-529).
