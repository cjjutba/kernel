**A PR may merge by itself with no review approving it, only when the user turns on "Merge without a review", and it is off by default.** Amends KERNEL-556, whose rule needed every required kind of review to approve the head commit. With automatic reviews off, that rule never let auto-merge weigh a PR, and the Lead heard nothing: a green PR sat at ready to merge with no word why. `pr.autoMerge.withoutReview` (personal `[merge] without_review`) skips the two approval rules, "None of its reviews is required" and a required kind that hasn't approved. Blockers, an overrule, a review still running, the checks, the line limit and the always-review paths still hold. It is off by default because an auto-merge nobody watches and nobody reviewed has only CI behind it. Like `auto` and `max_lines`, it is the user's own: the shared `.kernel/settings.toml` can't set it, and Kernel ignores it there and warns. KERNEL-1017.

**Kernel weighs a ready PR no review approved when merging without one is on or automatic reviews are off.** Before, an unapproved PR returned early, so the Lead never heard why auto-merge skipped it. Now the Lead gets the merge ("checks passed, 120 lines, no review") or the reason: "No review approved it. Turn on Merge without a review in Settings, Pull requests to merge on green checks." With automatic reviews on and the setting off, nothing changes: a review may still approve, and a refusal posted just before it lands would be wrong. KERNEL-1017.
