**Kernel names a chat itself with Haiku when Claude Code doesn't, and names it again from the whole conversation at turns 1, 3, 10 and 30.** D-089 waited for Claude Code to write a title into the session transcript. Claude Code doesn't always write one. After `/clear`, CJ's first Lead chat got a session with 22 prompts and no title, so its tab said "New chat" for good. Chats that did get a name kept the one Claude Code took from the first prompt, even after the conversation moved on.

CJ's rule is that every chat gets a name, the name follows the whole conversation, and a name the user typed never changes. A chat opened with a placeholder ("New chat", or the Lead's first "Lead" tab) carries `autoTitle`, which records the turn count Kernel last named it at. A workspace's first chat keeps the title it took from the brief, and forks and big terminals keep theirs, so none of them carry it. A chat still called "New chat" without the field counts as auto-named, so chats stuck before this change qualify. Renaming a tab clears the field. A rename that lands while a request is in flight wins, because Kernel saves a name only if the chat still has the title it had when it asked.

Claude Code's title is still the early name. Kernel takes it a few seconds into the first turn, so a long first turn doesn't sit at "New chat". At the end of a turn, Kernel asks Haiku 4.5 for a name when the chat has none, or when its count of finished turns reaches 1, 3, 10 or 30. The request sends the conversation's text (the first message, then the latest messages and replies that fit in 8,000 characters) and the current name, and asks to keep that name unless the subject changed. The gaps grow because a chat's subject settles over time, and a tab that renames itself often is hard to find. After 30 turns the name stays. A request that fails or takes over 30 seconds leaves the name and shows nothing. The next turn end tries again, including a missed refresh at 3, 10 or 30.

The request runs Claude Code with no tools, no settings sources and `persistSession: false`, so it never shows in Claude Code's session list. Each name costs one small Haiku request on the user's plan, at most five per conversation plus retries. `/clear` (a `conversation_reset` with trigger `clear`, or no trigger) puts an auto name back to "New chat" and starts the schedule over. Kernel ignores the old session's title until the new session starts, and drops a name for the old conversation that arrives after the reset, so the old name doesn't come back. Other resets (`plan_mode_exit`, `fresh_session`, `onboarding`) keep the name. On start, Kernel names each open chat still called "New chat" that has a session and a finished turn, one at a time.

Amends D-089. KERNEL-202.
