**A restored chat doesn't wait for setup.** Restoring a worktree workspace held every chat tab until setup passed (KERNEL-77, KERNEL-405), which in a repo with `pnpm install` meant a message sat in main's queue for minutes. A chat with history is the user's conversation, not a teammate's brief that must not go before the environment exists, and waiting hid their message. Restore no longer holds the tabs, including the one it creates when none are left. Setup still runs through `Workspaces.setUpWorkspace` with its log, failed state and Run again, and a failed setup holds nothing, so the chat keeps working and the banner stays. When setup passes, `Sessions.restartIdle` ends the workspace's idle sessions, and a running turn ends when it does. The next message resumes with setup's `$KERNEL_ENV` and copied env files, as after KERNEL-490. A new teammate workspace's brief still waits for setup. Amends KERNEL-77 and KERNEL-430. KERNEL-1016.
