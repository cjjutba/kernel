**The chat hover card always shows an age.** Like the app's other cards, which always pass `when`, the foot has the age on the right in every state. With a wait it is how long that wait has gone. With nothing waiting it is the age of the chat's last activity: the newest line in any of its tabs, or when the chat started if no tab has loaded its transcript. KERNEL-339, from the KERNEL-336 review.

**With two or more waits, the card's line names the one that has waited longest.** The foot counts them all ("3 tabs · 2 need you"), and the age is that longest wait's. Waiting wins over working in the pill and the foot. KERNEL-339, from the KERNEL-336 review.

**Only a question reads "{name} asks {what}".** A plan or a permission uses the line the app already shows for that wait, with the tab or workspace name in front, so there is no new copy: "Client portal login: Plan for T-15 is ready", "Invoice table: Noor wants to run a command". `banners/model.ts`, which the review pointed at, holds no line for a plan or a permission (its banners are about trust, usage, hooks and the like), so the wording comes from where those waits are already shown: Home's needs-you list for a plan and the approval card for a permission. A question that starts "Should we" or "Do you want to" reads "whether to"; any other question is lowercased as asked. KERNEL-339, from the KERNEL-336 review.

**A chat needs you when one of its tabs, or a workspace it started, needs you.** The card and the folded row's icon follow that one rule, so the card never says "Nothing is waiting on you." while the row shows the question icon. The line can name a workspace instead of a tab ("Fix the login redirect asks whether to keep Google sign in."), and the foot's count includes those workspaces. An unfolded chat's row icon counts its tabs only, because each workspace it started shows its own icon in its own row; the card counts them either way. Both read `chatWaits` in `components/sidebar/chatCard.ts`. KERNEL-339, from the KERNEL-336 review.

**Ask Rowan joins the chat you are in.** In the Lead's workspace that is the chat on screen. In a workspace a chat started it is that chat, found by `threadId` or by the tab that handed it off. From Home, the Inbox, a workspace no chat started, or a chat that has closed, it passes no thread and the answer opens as a new chat. ⌘K's New tab joins the chat on screen the same way. KERNEL-339.

**The Grouped PNGs win over the older ones.** WorkspaceContext, WorkspaceNewChat, the palette's "New chat tab" and Settings, Shortcuts still say "New chat" where a tab is meant, and CommandPalette.png's ⌘⇧N for a new workspace is stale. GroupedPalette's "New tab ⌘T" and its ⌘N "New chat in Client A", which matches the app, are the spec. KERNEL-339.
