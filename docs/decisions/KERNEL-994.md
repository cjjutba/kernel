**A process marked stale is replaced before it gets the next message.** A mode switch, Bypass, an agent edit, an account switch or a changed compact window marks a running process stale, with the reason. `dispatch` ends a stale process that isn't running and starts a fresh one, so a queued message, Send now or a message after Stop runs with the chat's current prompt, Kernel tools, Bypass and account. A process held only by background tasks ends the same way, and the chat says the tasks stopped. A switch back to the mode the process started in drops only the `mode` reason, so nothing restarts for no reason. A running turn still finishes in the mode it started in (KERNEL-770). KERNEL-994.

**A plan answered after a switch goes to a fresh process.** The card's waiting turn has the Kernel tools of the mode it started in, so when the chat's mode differs the turn ends and the approval goes out as a new message with the restarted note, which builds the plan in Build here and hands it off in Hand off. KERNEL-994.

**The first message after a switch carries a one-time note.** The history a fresh process resumes holds replies written in the other mode, so the note names the new mode and says to follow it. It lives in the `leadTurnNotes` meta with the PR notes and goes out once. A switch and back leaves none, and a chat with no user message yet gets none.
