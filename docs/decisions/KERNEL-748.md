**Reference folders live in the personal settings file, and Kernel enforces read-only itself.** A room's `references` is a top-level key in `.kernel/settings.local.toml`, absolute paths only, since a sibling project sits at a different path on every Mac. The shared file's key is ignored, and a `shared` save that sets it is refused. Claude sessions get the folders that exist as `additionalDirectories`, so Claude Code reads them without asking. Claude Code would also let an edit there through in Accept edits and Bypass permissions, so Kernel denies Edit, Write, MultiEdit and NotebookEdit under a reference folder in its own PreToolUse hook and in `decide`, in every mode, with symlinks resolved on both sides. Codex sessions get the same folders since KERNEL-790. Their developer instructions list them, and Kernel declines a Codex file change in every mode, Bypass permissions included, when any of its files or its `grantRoot` is under one, with the same note. Codex already reads outside the worktree, so its `writableRoots` stay as they were. Bash is still not covered, on either provider: a command can write there, the same as it can write anywhere else on the Mac. A folder that isn't there is skipped by sessions and the @ menu. Room settings list it in `missingReferences`, and the room log warns about it once per run, since there is no room health screen yet. KERNEL-748.
