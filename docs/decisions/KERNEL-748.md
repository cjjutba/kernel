**Reference folders live in the personal settings file, and Kernel enforces read-only itself.** A room's `references` is a top-level key in `.kernel/settings.local.toml`, absolute paths only, since a sibling project sits at a different path on every Mac. The shared file's key is ignored, and a `shared` save that sets it is refused. Claude sessions get the folders that exist as `additionalDirectories`, so Claude Code reads them without asking. Claude Code would also let an edit there through in Accept edits and Bypass permissions, so Kernel denies Edit, Write, MultiEdit and NotebookEdit under a reference folder in its own PreToolUse hook and in `decide`, in every mode, with symlinks resolved on both sides. Bash is not covered: a command can still write there, the same as it can write anywhere else on the Mac. Codex sessions already read outside the worktree, and their `writableRoots` stay as they were. A folder that isn't there is skipped by sessions and the @ menu. Room settings list it in `missingReferences`, and the room log warns about it once per run, since there is no room health screen yet. KERNEL-748.
