**Files show their VS Code icons in color, and changed files take VS Code's git colors.** Amends the "monochrome surfaces" rule in DESIGN.md, for file icons and file names only. CJ wanted the All files tree to look like VS Code, colors included, and every place Kernel shows a repo file to match it. The icons are Material Icon Theme 5.39.0 (MIT), pinned as a dev dependency. The renderer imports only the lookups it reads from the theme's `dist/material-icons.json` and works out an open folder's icon from the closed one (`folder-src` opens as `folder-src-open`), so the main bundle grows by about 340 KB, not 630. The build emits each of the 1,248 SVGs as its own file, about 1 MB together, fetched the first time one is drawn. A path picks its icon the way VS Code does: by its whole name, then by its extensions from the longest (`a.test.ts` tries `test.ts`, then `ts`), then the plain file icon. A folder goes by its name, open or closed. In the light theme the manifest's light overrides come first.

A changed file's name and letter take VS Code's git colors: `--mod` (VS Code's tan) for modified, `--add` for added, untracked and renamed, `--del` with a line through for deleted. Untracked shows U, as VS Code shows it, not git's `?`. A folder takes the color of the changes inside it, modified over deleted over the rest, so a folder with an edited file never reads red. VS Code also puts a dot on that folder. Kernel leaves it off, because DESIGN.md allows no status dots. Folders that hold only one folder share a row, as VS Code's compact folders do. The Changes tab shows a list or a tree, and localStorage keeps the choice, like the panel toggles. Pasted text, attached images and the folders in Open folder keep their stroke glyphs, since none of them is a file in the repo. Everything else stays monochrome. KERNEL-399.
