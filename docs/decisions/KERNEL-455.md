**ConfirmBypass remembers its answer in the renderer, and every way into Bypass permissions shares one flag.** Bypass is confirmed once, from Settings, a room's override, Shift+Tab, the mode menu and the + menu (KERNEL-435). Only the renderer starts a switch into it, so the flag is `bypassConfirmed()` in `bypassConfirm.ts`, kept in localStorage the way the long-chat banner keeps its dismissals (KERNEL-426), with no new settings key. When localStorage is blocked or cleared, Kernel asks again, which is the safe direction. The onboarding step sets it with `rememberBypassConfirmed()` when Continue is pressed with Bypass picked, as KERNEL-435 says. KERNEL-455.

**A mode no provider can run can't be picked, and one that only some providers run says which.** Settings keeps the row, dims it and shows the reason from `permissions.availability`. A provider's line names it and says what its chats use instead, like "Auto isn't available for Codex agents yet. They use Accept edits instead." A dimmed mode that is already the saved one stays checked, so a policy change never hides what the app is set to. A mode that works on one provider and not the other stays pickable. KERNEL-455.

**The room's mode override is a menu, and Use app default drops the key.** The menu sits above the room's saved commands and tools, and picking Use app default removes `Room.permissionMode`. A room's saved tool rules (`Room.allowTools`) list under its commands with the same Remove button. KERNEL-455.
