**Kernel's four PR texts put the repo's own rules first.** Create PR, Resolve conflicts, Fix checks and Address review each open with a line saying the agent's project instructions and the repo's docs on pull requests come first, and each ends by telling the agent to stop and say what failed when it can't fix a step. Their test steps used to be Kernel's habits ("typecheck", "the full suite"). Now each asks for the checks the repo runs before a push, and the tests that cover the change when the repo names none. Every text says to commit and push, since an agent that stopped before the push left the PR where it was. KERNEL-564

**Kernel names a repo's PR skill or command by path, the way it names the template.** `readConventions` looks for `.claude/skills/<name>/SKILL.md`, `.agents/skills/<name>/SKILL.md` and `.claude/commands/<name>.md` whose name is about pull requests (`create-pr`, `pr-review`, `pull-request`, `open_prs`), and not `issue` or `release`. Each one found, at most 3 in path order, adds a line telling the agent to read it first and to follow it where it differs. Kernel doesn't paste the file in, for the same reason it doesn't paste the template (KERNEL-468): the agent reads the version on its branch, and a long skill doesn't fill the message. KERNEL-564

**Each text is fitted to its workspace when it is Kernel's own.** When the text in force is a generic default, the button sends it with the branch, the base without its remote, the remote and the PR number. Create PR names `git push -u <remote> HEAD` and `gh pr create --base <base>`, with `--draft` when the PR opens as a draft. Resolve conflicts names `<remote>/<base>` to rebase onto. A text the user or the room wrote still goes out as written, as KERNEL-468 decided, and only that text gets the `Open as draft` line, since Kernel's own puts the flag in its command. The four generic defaults are what Settings, Pull requests shows. The texts every launch saved before KERNEL-225 join `SAVED_BEFORE`, which now holds a list per key, so those installs read them as unset and get the new texts. Amends KERNEL-468. KERNEL-564

**Review comments carry their thread id, and the reply command goes with them whatever the text.** The full read asks GitHub for each review thread's `id`, and the address-review block lists each line comment with `[thread <id>]`. After the block comes the `gh api graphql` command that replies in a thread (`addPullRequestReviewThreadReply`), and `gh pr comment` for a review with no thread. Kernel adds that footer whenever it lists comments, so a room's own Address review text gets it too. Before this, the text asked the agent to reply to each comment without giving it any way to find the thread. KERNEL-564
