**Nothing waits for the setup script. It runs alongside the agent, and a run that doesn't pass is an event.** KERNEL-1012 made running alongside the default and kept `workspace.leadWaitForSetup` for anyone who wanted the old hold. The redesign drops the hold. A setup script is optional, and an agent can do most of its work before dependencies land, so holding a brief or a message for it cost more than it saved. The setting is gone from the app's settings, a project's file and both Settings pages. A file that still has it loads without it.

What still waits is the workspace itself. A new chat's message waits until git has made its worktree, and a brief waits until the local files are copied, since the agent needs the project's env files. That queue reason is `worktree`, which replaced `setup`. `Setup.prepare` only copies files now, and every path starts the script with `Setup.runInBackground`. A brief held for a merge still waits for the merge, with setup running meanwhile, and a setup that passes starts the run script only once the brief has gone. The Lead hears a failed setup as the teammate working on without it, or, for a brief held for a merge, as the brief still waiting for the merge.

A setup run that doesn't pass, because it failed, timed out or was stopped by hand, pushes one `setup.failed` with the workspace and chat ids, the kind, the exit code and the last line it printed. A run that an archive or Kernel's own quit stopped pushes none, and the next start pushes one for a run a quit cut short. The workspace keeps `setupRun` for the Session rail, and the window will show the event as a toast with Open Setup tab and Rerun setup. Rerun setup goes through `runInBackground` whatever the agent is doing, so a running session picks up `$KERNEL_ENV` after its turn. `$KERNEL_ENV` counts only once the last run passed, since a run still going, or one that failed, may have written part of it.

A workspace a quit left partway through being made is finished at the next start instead of failed: its brief and the Lead's messages after it go, and setup runs alongside. When git can't make a new chat's worktree, the message stays in the chat, not sent, and `worktree.failed` carries git's line. `workspaces.retryWorktree` makes it again and sends the message. A workspace an older Kernel failed with its brief held for setup keeps Run again and Send anyway, which now send it at once.

Adding a project stops only at a step the rest needs: the clone, the GitHub repo that Code host and push access read, and the agents the first chat needs. Any other step that fails reads `skip`, with its error, the steps after it run, and `project.setupFailed` says which step failed and whether setup went on. Try again starts at the first failed or skipped step.

Amends KERNEL-1012, KERNEL-490, KERNEL-405, KERNEL-430 and KERNEL-128. KERNEL-1086.
