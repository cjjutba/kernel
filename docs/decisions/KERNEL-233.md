**Vercel deploys the website from main only.** Amends D-057, which says the Ignored Build Step setting lives in the Vercel dashboard and not in a `vercel.json`. The step itself stays in the dashboard. `site/vercel.json` now sets `git.deploymentEnabled` to `{ "**": false, "main": true }`. The Vercel GitHub app created a deployment for every push to every branch, and the Ignored Build Step canceled the ones that didn't touch `site/`. A canceled deployment still counts toward the Hobby plan's daily limit, so with several agents pushing branches all day the quota went to builds that never ran. PR #167 touched nothing in `site/` and still got "Deployment rate limited, retry in 24 hours". The pattern is `**` because branch names contain a slash and `*` doesn't match one. When a branch matches more than one rule, Vercel deploys if any of them is true, so main still deploys. On main the Ignored Build Step still skips pushes that don't touch `site/`, so the site builds for release PRs (D-058) and website changes. Site PRs lose their Vercel preview URLs. `.github/workflows/site.yml` still runs on them: it builds, lints and tests the site and runs the e2e tests and the visual comparison with the design renders, whose side-by-side images it uploads as an artifact. Branches cut before this change keep triggering Vercel until they merge main. KERNEL-233.
