**A wait names each workspace in it, and the name opens that workspace.** A note about a wait carries `refs`, the spans of its text that name a target, so "PR #164 by Noor" in "Waiting for PR #164 by Noor to merge." is a button that opens Noor's workspace. Notes written before this have no refs and stay plain text. Work with no PR is named by its issue key, "KERNEL-12 by Noor", because two of one teammate's workspaces both read "Noor's work"; that label is left for work with no issue. The transcript note is a record of when the wait began, so two live lines sit above the box and change as PRs open and merge. A held brief's queued row reads "Queued. Sends when PR #164 by Noor merges." and drops each target once it merges, falling back to KERNEL-361's "the work it waits for" when none is left. The workspace others wait for reads "KERNEL-12 by Kai waits for this to merge." until it merges. Neither line is on the canvas. The label and who-waits rules live in `src/shared/waits.ts`, so the engine's notes and the window's lines can't name the same work two ways. KERNEL-386.
