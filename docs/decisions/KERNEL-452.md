**Room setup flags a repo rule only when it plainly tells agents to work against Kernel, and misses a vague one rather than raise a false alarm.** Most lines in a CLAUDE.md that name main agree with Kernel: "never commit to main", "rebase onto origin/main", "don't run git pull in the main checkout". A list that flags those teaches the user to ignore it. So the matcher has five kinds (commit to main, no branches, no pull requests, push to a protected branch, stacked PRs) and a short list of phrasings for each. A line counts only when the verb starts its clause ("Commit", "Always commit", "You can push", "Feel free to push"), the branch name ends the clause, there is no negation before it or in the rest of the clause, no condition before it in the clause ("if", "before", "only"), and no "only" after it. So "every push to main", "Only maintainers push to main", "Before you push to main", "the main process" and "Work in main only if the user asks" pass. The rest of the clause runs past a colon, which gives the verdict, and a question takes its answer with it, so "Push to main: not allowed" and "Commit to main? Never." pass too. Stacked PRs count only as an instruction ("Stack PRs", "We stack PRs", "Use stacked PRs"). As a subject they are talked about, not asked for: "Stacked PRs: avoid them", "Stacked PRs make review hard". "Used to", "no longer" or "anymore" anywhere in the sentence drops it, since a habit the repo dropped is no rule. Code blocks and HTML comments are skipped. A line gets one row, for its earliest rule, so "Commit straight to main. Skip the PR for small changes." is one commit-to-main row, as RoomSetupConflicts.png draws it. The branches are the room's default branch and Settings, Permissions, Protected branches, the ones the push guard denies. KERNEL-452.

**Kernel reads CLAUDE.md, .claude/CLAUDE.md and AGENTS.md at the repo's root, and never writes them.** Those are the files Claude Code and Codex load for every session in the repo. CLAUDE.local.md is skipped: it is gitignored, so a teammate's worktree doesn't have it. A CLAUDE.md in a subfolder only loads when an agent reads files there, so it is skipped too. A file that links to one already read (CLAUDE.md to AGENTS.md is common) is listed once, under the first name. KERNEL-452.

**The scan runs at room setup, right after the checkout, and is not a step of its own.** It reads at most three small files and can't fail setup, so a setup line for it would only add noise. Running it before the other steps puts the findings on the room before setup reports done. They live on `Room.instructionConflicts`, unset for a room set up before KERNEL-452 and empty when nothing fights. A later edit to the files isn't picked up until `findInstructionConflicts` runs again. "Kernel tells agents" uses RoomSetupConflicts.png's words, with the stacked-PR line naming the base teammates' worktrees really start from (Settings' workspace base, else the room's remote and default branch). KERNEL-452.
