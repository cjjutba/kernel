**The redesign canvas in `design/redesign/` is the spec for the workspace panel, PR states, plan mode, Team update, Ask Rowan and the new chat state.** CJ and Claude designed it on a canvas. It keeps Linear's neutrals and hues and adds tokens for plan mode and the PR bands. The PNGs live next to their artboard sources and a render script. For those surfaces they replace the `design/screens/` PNGs, which stay as the spec everywhere else. The README's "Not built" list is drawn on the canvas but was left out on purpose: a plan-mode button, a bottom-panel collapse and more terminals, an Ask Rowan close button, and a centered new-chat composer. KERNEL-274.

**Every PR state gets a header band, a state label and icon, and the band's tone on its buttons.** Amends D-071. The top of the right panel is grey, green, red or violet by state, from the `--pr-merged-*`, `--pr-ready-*` and `--pr-fail-*` tokens. The neutral band uses the panel's own surfaces. Each state shows a label, even those that used to show only the link (Open, Ready to merge, Merge conflicts), so the header says where the PR stands without reading the button. Changes requested is red, as it already was in the sidebar. While Kernel creates, checks, resolves or merges, the label keeps the state's icon and only the busy button spins. `headerView` returns the label, tone and icon for every state, and its buttons are unchanged. While the right panel is hidden the header moves to the chat (D-071) with no band. There it shows the same label and buttons in neutral colors, except merged, which stays purple as before. That differs from WorkspaceFocus.png, which draws only Create PR. KERNEL-274.

**A busy button in the PR header band keeps the band's tone.** Amends D-086. The rule that every busy button turns surface-3 grey was written for a neutral header. On a green or red band the grey read as a hole cut into it. Inside the band, a busy button takes the band's soft fill and edge, dims its text and colors its spinner with the band. Everywhere else busy buttons are unchanged. KERNEL-274.

**`--needs` also marks what waits on you, in the sidebar and on chat tabs.** Amends D-084. The waiting icon on a workspace, Lead or chat row (a plan to review, a question, an approval) is amber, and so is the same icon on a workspace's chat tab and the Inbox count. That's the color the hover card's "needs you" word already had. Nothing else in the sidebar takes color beyond the diff and PR colors. KERNEL-274.

**Plan mode is a blue composer, not a hatch.** Amends D-092 and D-093. The composer gets a `--plan` border, a soft glow rising from its bottom edge, a blue caret and a blue send button. There's still no chip or label, as D-093 wanted. A waiting plan (D-092) is no longer hatched either. It keeps the blue and puts Copy and Approve in a blue strip on top, with Approve the one blue button. The New workspace modal takes the glow and the caret; its border belongs to the modal shell, and its Create button stays as it is. KERNEL-274.

**The Team update card is an outline with the events as one line.** Amends D-128. The card spans the chat column instead of about 82% of it, with no fill. Its header reads "Team update from Kernel" small and muted. A row's issue key is set apart from its task. The events are one line of text between dots, colored only when something failed (red), merged (violet), or is ready to merge or approved (green). Everything else is grey, or brighter when it needs the Lead, as before. The reply is plain text without the quote rule, still three lines with Show more. A screen reader hears a full stop between events. KERNEL-274.

**Kernel's one-line notes in a chat read as a quiet line.** "PR #42 was merged on GitHub." and the other notes Kernel adds to a transcript sit as muted text with a hairline after it, not in a box. Kernel's own longer messages (KernelNote, KERNEL-120) keep the boxed note, since they can run several lines. The canvas puts the PR's icon before a note, but a note doesn't carry a kind, so the icon is left out. KERNEL-274.
