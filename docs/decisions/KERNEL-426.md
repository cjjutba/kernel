**The long-chat banner gives its count and reason, and one chat can dismiss it.** Amends KERNEL-224. The banner sat under a context popover reading "151k of 1M, 816k free" and said only "Starting a new chat keeps the next turns cheaper", so it read as a contradiction. The rule is unchanged: from 150k tokens (`CONTEXT_LONG`) every turn sends the whole context again and uses more of the plan's limits, whatever the window size. The subtitle now says so, in the popover's token format: "151k tokens. Each turn reads all of it again, so turns use more of your limit." `formatTokens` moved to `composer/formatTokens.ts`, so the banner model can import it without pulling in the ring component.

The banner gets a Dismiss button ahead of Compact now and New tab. Dismissing hides the long-chat banner in that chat and no other, and it stays hidden after a restart. The renderer keeps the chat ids in localStorage (`kernel.longChatDismissed`). Main and the database know nothing about it, and fixture mode keeps them in memory only. `bannerFor` takes `longDismissed` and skips only the `long` branch, so the banner below it (Hooks are disconnected) shows in its place. "Context is almost full" from 90% has no Dismiss and still shows in a chat where the long-chat banner was dismissed.

A dismissal does not expire. A chat that is compacted and grows past 150k again stays quiet, and the ids of deleted chats stay in localStorage, a few bytes each. KERNEL-426.
