**A native view draws above the DOM, so Kernel's own overlays hide it behind a still.** A shared page runs in the view KERNEL-303 made, and Chromium always paints a native view over the page's DOM, so a menu, modal, tooltip or toast over the tab would sit under the page. `PreviewSurface` therefore reads `.sv-frame`'s rect every frame in a `requestAnimationFrame` loop, because a sidebar toggle, a banner or a panel drag moves the frame without resizing anything a ResizeObserver watches, and sends `system.preview.place` only when the rect changes. The frame always holds an `<img class="sv-still">` under the view. When something covers the page, the surface sends `place(null)` first, so the overlay draws over the still in the same frame, and only then asks `system.preview.still` for a fresh capture. The view comes back by itself when nothing covers it. A `MutationObserver` on the body runs the same check as soon as a menu or modal mounts, a frame sooner than the loop would see it. A crashed or unresponsive page is hidden the same way. KERNEL-306.

**What covers the page is a selector list, checked against geometry.** `isCovered` in `shared/cover.ts` takes an overlay when it matches `.scrim, .modal, .menu, .popover, .tooltip, .toast, .hover-card, [role="dialog"], [role="menu"], [role="listbox"], [role="tooltip"]`, sits outside `.sv-stage`, takes up room, is not hidden by display, visibility or opacity, and intersects the view's rect by at least a pixel. Intersecting matters: a toast in the corner or a menu beside the tab leaves the page live. The roles catch what has no class of its own: the composer's @ and / lists, ModelPicker and the link pickers. The list says `.hover-card` where the canvas says `.hovercard`, because the app's card is `.hover-card` and `role="tooltip"`. `test/previewCover.test.ts` fails when `ui/overlays.tsx`, `ui/Tooltips.tsx` or `components/Toasts.tsx` stop using these names, so a rename can't quietly draw an overlay under a live page. A new kind of overlay needs a class or role from this list, or an entry in it. KERNEL-306.

**A PDF has no live view, so its tab opens Kernel's copy in Preview.** The KERNEL-303 spike found Chromium's PDF viewer blank in the in-memory partition, so `system.preview.open` returns no view for a PDF and the tab shows the page capture, with Open in Preview in the toolbar where Reload is for a page. `shared.open` hands Kernel's own copy of a PDF version to the Mac's default PDF app, and refuses every other kind: a shared HTML file or script opened by its default app would run outside the lock. KERNEL-306.

**F6 and the app's shortcuts reach the tab through one push.** Main already pushed `preview.key` for the shortcuts Kernel runs. It now pushes it for F6 too, and the tab puts focus on `.sv-frame` when it sees `F6`; every other key is replayed as a `keydown` on `window`, so the handlers in App, ChatTabs and the Composer run unchanged. Listening for the window's focus event instead would not do: it does not fire in a hidden window, so it could not be checked. KERNEL-306.
