**Each role has its own compact window, 200k or the model's full window, with a default that follows the plan. Amends context-window-follows-model.** Since context-window-follows-model, a Claude chat compacts against its model's full window, near 967k on a 1M model. In 7 days of transcripts on the maintainer's Mac, calls above 200k of context were 32% of calls and 61% of all tokens. So `models.compact` holds one value per role (`lead`, `engineers`, `qa`, `reviewer`): `200k` or `full`. On Pro every role defaults to `200k`. On every other plan, an API key account and a plan Kernel can't read, the Lead and engineers default to `full` and QA and the reviewer to `200k`, because a test run or a review is short. The four keys are plan keys, so a value the user never saved moves with the account's plan and a saved one stays.

At `200k`, `sessionEnv` sets `CLAUDE_CODE_AUTO_COMPACT_WINDOW=200000` on the chat's process, as KERNEL-226 did. At `full` it removes the variable. Kernel's setting decides for Kernel's own chats whatever the Mac exports, the rule D-027 set for agent teams. Helper calls (usage, model, MCP and command probes, titles, plugin agents) and terminal tabs pass no choice and keep the Mac's value. A project's `.env` still can't set it (KERNEL-247).

A chat's role is `Team.roleOf` its agent. A review workspace is always `reviewer`, whichever agent runs it. A chat with no agent is `lead` in a Lead workspace and `engineers` elsewhere. A pinned model changes the model, not the role, and a model change mid-chat keeps the process and its window. Subagents and agent team teammates run in the chat's process and inherit its variable.

A process keeps the window it started with, so a change to any resolved value, from Settings or from a plan change, calls `Sessions.restartProvider('claude')`. An idle process ends now, a busy one when its turn ends, and the next message resumes the chat with the new window.

Checked live on Claude Code 2.1.292 (SDK 0.3.292). Opus 5.5 and Sonnet 5.5 at `200k` report `maxTokens` 200000 and compact at 167k. At `full` they report 1000000 and compact at 967k. A chat resumed at `200k` with 233k or 473k of context did not error. Its first turn tried to compact, bailed ("no assistant messages in summarize set"), and answered against the full context. Its second turn compacted once (`trigger: auto`, 475k down to 3k). So a chat already past 200k compacts one turn later than expected, and that turn still pays for the whole context.
