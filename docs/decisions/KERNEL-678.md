**With plan mode off, Kernel checks the go-ahead, not only the prompt.** the Lead handed off work and filed an issue after a reply that started with "yes" but also asked new questions. A sharper rule helps, but a rule is a request. So `create_workspace` takes a `go_ahead` argument: the user's words that approved the hand-off, quoted from their latest message in this tab. Kernel compares it with that message, ignoring case and whitespace, and refuses with "Not handed off: quote the user's go-ahead from their latest message, or ask them first." when it isn't there. The check can't tell a clean "yes" from "yes, but what about pnpm?", because "yes" is in both. That part stays with the rule. What the check does stop is a hand-off nobody said anything about, and a quote from an older message after the user wrote again. The quote is saved on the workspace as `goAhead`. KERNEL-678.

**What needs no quote.** Plan mode, since the approved plan is the go-ahead. A plan approved in this Lead chat after the user's latest message, which covers the hand-off right after Approve, once plan mode has switched off. A review (`review_of`). A turn Kernel started, such as a team update, in a chat that already has an approved plan or a hand-off, since that is a follow-up on approved work: failed checks, blockers, conflicts. A turn the user started always needs the quote, even after an earlier hand-off, so "also, look at X" can't start new work. The check runs after the "already handed off" refusal, which tells the Lead more. KERNEL-678.
