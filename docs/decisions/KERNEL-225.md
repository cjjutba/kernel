**Defaults follow the Claude plan, and settings.json holds only what the user changed.** Amends D-094, D-027 and D-045. Every install got Max-sized defaults, and Kernel saved the whole settings file on every launch (D-094), so any default saved once was pinned. A Pro user hits the 5-hour and weekly limits partway through one plan, and a default changed later never reached an install that had already saved the old one.

`loadAppSettings` returns `{ saved, resolved }`. `saved` is what the user chose. `resolved` is the app's defaults, then the plan's, then `saved`, with `plan` and `planDefaulted` filled in, and it is what `k.settings` holds, so no reader changed. `settings.get` returns it, and `planDefaulted` lists which of the five plan keys the user never set, for a later Settings row that says "Plan default (Sonnet)". The five are `models.lead`, `models.reviewer`, `models.effort`, `models.agentLimit` and `pr.autoReview`. `Config.setSettings` merges the patch into `saved`, with the values the engine kept (a limit pulled into range), and writes `saved` with a version. A patch can't set `plan` or `planDefaulted`. A choice equal to the default is still a choice. Launch writes nothing, and the hook port moves through the same path.

The plan comes from the account's subscription type, which `readAccount` keeps raw and the window never sees. Kernel saves it under meta `plan` each time the account is read and applies it when it changes, so a start knows it before the account is read. A sign-out keeps the last plan. A login with no subscription, an API key, reads as `unknown`. A plan change moves only the keys the user never set, and writes nothing.

Pro gets Sonnet for the Lead and the reviewer, medium effort, an agent limit of 2 and auto review off. Max, Team, Enterprise and `unknown` keep today's defaults, but the reviewer is Sonnet for everyone, so the base default changed too (used by tests and fixtures). The starter agent files lost their `model:` line, so `team.modelFor` uses these role models. An agent file that has its own `model:` still wins. Existing rooms keep the files they copied.

Migration. A file without the version saved every key on every launch, so a value equal to its default counts as unset, and so does each plan key equal to its old default: opus, opus, high, 0, true. So does the old Address review text (KERNEL-222), which is how its new line reaches existing installs. Anything else stays. A file written since keeps exactly the keys it has, a terminal preset included, so one saved key never pins its group's other defaults. A file written since keeps what it has, so a choice made after this change survives, `effort: 'high'` on Pro included. Known limit: a user who chose Opus for the reviewer before this can't be told from the default Kernel pinned, so they move to the plan default and pick it again. The same goes for agent teams: an old file saved it on, which can't be told from a choice, so it stays on there, and new installs start with it off.

Agent teams. It defaults off, since only the Board used it and the Board is hidden (D-104). The first-run check, its "Turn on for Kernel" fix and `SetupTeamsOff.png` are gone, and D-027's "first-run check" no longer holds. The Models toggle stays, and `sessionEnv` still sets or clears the variable for Kernel's own sessions as D-027 says. The other four Setup PNGs still draw a passing Agent teams row that the app no longer shows.
