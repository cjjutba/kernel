**Both runners decide a step through `services/permissions.ts`, and each runner only turns the answer into its own protocol.** `decide(step, rules)` applies Kernel's rules in one order. Kernel's own tools allow. Network off denies a web tool, a command that reaches the network, or a step that asks for the network. The Bash lists decide a command. The mode comes last. An undefined answer is no opinion, and a runner then asks the user, because Claude's canUseTool and Codex's approval requests only reach Kernel for steps the CLI would ask about.

The mode table keys on `Step.sandbox`. Inside Codex's sandbox (typing into a running terminal, or a file change in the workspace), every mode but Ask accepts. Outside it, the user decides in every mode, as KERNEL-406 set. A Claude step has no sandbox. Claude Code applies Ask or Accept edits itself before it calls canUseTool, so only Bypass in worktrees, in a worktree, lets the rest through, and never a question or a plan. `Rules.mode` is a field of its own, filled from Settings, Permissions for now, so a per-chat mode can replace it without touching either runner.

Claude's PreToolUse hook calls `guardVerdict` alone, with no network check before it. With Network off, the hook still refuses a networked command with "Kernel blocks ... in every room.", where canUseTool and Codex say network access is off. The difference predates this change, and it stays until someone decides it. KERNEL-434.
