**Answers to AskUserQuestion go back in the tool's own `answers` field, one per question.** Kernel used to read only the first question of an AskUserQuestion call and send the reply as a denial, `The user answered: <text>`, so a call with three questions got one answer and the model never heard about the other two. The approval now keeps every question in `questions`, and `canUseTool` returns `allow` with `updatedInput: { ...input, answers }`, keyed by each question's text. That is `AskUserQuestionInput.answers` in the SDK. Claude Code 0.3.292 reads it in the tool's `call()` and writes `"<question>"="<answer>"` for each one into the tool result. An empty `answers` map counts as no map. A text-only answer, like the one-click card or Something else, fills the question when there is only one. When there are several, Kernel keeps the old denial and says the user saw and answered only the first, so the model asks the rest again. The tool's result lists only the questions that have an answer, so pinning the text to the first one would hide that the others went unanswered. `title` and `options` stay the first question's, so the Inbox, notifications and the floor read the approval as before. The Lead's `ask_user` in `kernelMcp.ts` is a different tool and still answers with text. KERNEL-236.
