**A chat whose Claude Code session is gone moves its running turn to a fresh session, matched on Claude Code's exact error.** Claude Code prunes old transcripts, and a user can delete `~/.claude/projects`. Every send and every Restart session then resumed the same missing id and failed, so the chat was dead for good. I ran the pinned CLI (2.1.292, SDK 0.3.292) with `--resume` on a made-up id and on a real session whose `.jsonl` I had deleted. Both answer the same way, with no `init` first. Stderr says `No conversation found with session ID: <id>`, stream-json writes a zeroed `error_during_execution` result whose `errors` is `["No conversation found with session ID: <id>"]` and no `startup_failure_reason`, and the process exits with code 1. The SDK yields that result, then throws `Claude Code returned an error result: No conversation found with session ID: <id>`. Kernel matches the result's `errors` against that text plus the id the process resumed, and only before the process's first `init`, so no other failure can look like a missing session. Then the chat forgets `sessionId` and saves, a note says "Kernel started a new session because the old one is gone. The agent doesn't remember earlier turns in this chat.", the old process is ended, and a fresh one starts from the chat as it is now, so it keeps the model, effort and plan mode. It gets the message that started the turn, and the queue goes after it in order, as after any turn. The turn never ends in between. `setRunning` never sees it stop, so the working journal, `turns.from`, the carry-on flag after a quit and the queue stay as they were. No turn end and no exit reach Kernel, so a teammate that carries on after a relaunch still counts as carrying on in team updates. A fresh session that fails does so like any other session: its error shows, a turn the Lead started ends with an error, or the session dies mid-turn, and either one wakes the Lead. A fresh session never resumes, so it can't hit this again. A chat gets one fresh session until a turn there ends well. If the fresh session got an id, never finished a turn and that id is gone too, the error shows as it is and nothing starts, though the id is still forgotten so the next send starts clean. While Kernel quits nothing new starts. The chat keeps its id and stays in the journal, and the next launch finds the session gone and renews it then. Known limit: in that case the message the quit caught stays in the transcript unanswered, and only the relaunch nudge goes to the fresh session. KERNEL-286.
