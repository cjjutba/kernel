**A chat whose Claude Code session is gone moves its running turn to a fresh session, matched on Claude Code's exact error.** Claude Code prunes old transcripts, and a user can delete `~/.claude/projects`. Every send and every Restart session then resumed the same missing id and failed, so the chat was dead for good. I ran the pinned CLI (2.1.292, SDK 0.3.292) with `--resume` on a made-up id and on a real session whose `.jsonl` I had deleted. Both answer the same way, with no `init` first. Stderr says `No conversation found with session ID: <id>`, stream-json writes a zeroed `error_during_execution` result whose `errors` is `["No conversation found with session ID: <id>"]`, and the process exits with code 1. The SDK yields that result, then throws `Claude Code returned an error result: No conversation found with session ID: <id>`. Kernel matches the result's `errors` against that text plus the id the process resumed, and only before the process's first `init`, so no other failure can look like a missing session. Then the chat forgets `sessionId` and saves, a note says "Kernel started a new session because the old one is gone. The agent doesn't remember earlier turns in this chat.", the old process is ended, and a fresh one starts from the chat as it is now, so it keeps the model, effort and plan mode. It gets the message that started the turn, and the queue goes after it in order, as after any turn. The turn never ends in between. `setRunning` never sees it stop, so the working journal, `turns.from`, the carry-on flag after a quit and the queue stay as they were. No turn end and no exit reach Kernel, so a teammate that carries on after a relaunch still counts as carrying on in team updates, and a team update to a Lead stays Kernel's turn. A fresh session that fails does so like any other session: its error shows, a turn the Lead started ends with an error, or the session dies mid-turn, and either one wakes the Lead. A fresh session never resumes, so it can't hit this again. A chat gets one fresh session until a turn there ends well. If the fresh session got an id, never finished a turn and that id is gone too, the error shows as it is and nothing starts, though the id is still forgotten so the next send starts clean. While Kernel quits nothing new starts. The chat keeps its id and stays in the journal, and the next launch finds the session gone and renews it then. Known limit: in that case the message the quit caught stays in the transcript unanswered, and only the relaunch nudge goes to the fresh session. KERNEL-286.

**The match is pinned to Claude Code 2.1.292 and SDK 0.3.292, and has to be checked again on a bump.** `sdk.d.ts` has no typed signal for a missing session. A result can carry `startup_failure_reason`, but `SDKStartupFailureReason` has no value for it and the CLI leaves the field unset here. So Kernel matches the words, and a new wording fails without a sound: the fallback stops and these chats are dead again. `test/live.test.ts` has a case for it (`-t "live session gone"`), which the live run before an SDK bump covers. KERNEL-286.

**A Stop or a Send now pressed before a gone session answers ends the turn the usual way.** The CLI boots for about a second before it fails, and the user can press Stop in that time. Starting a fresh session then would run a message the user stopped. So Kernel still forgets the id, adds the note and ends the old process, then lets the result end the turn as an interrupted one. Stop drops the queue, and Send now's message starts the fresh session itself, without the interrupted one before it. KERNEL-286.

**A Kernel nudge that moves to a fresh session becomes a fresh-session nudge.** The restart, limit and relaunch nudges tell the agent to pick up where it left off, and a fresh session has nothing to pick up. When the message that moves is one of them, and for any of them still in the queue, the agent gets "Your earlier session in this chat is gone, so you don't remember anything from it.", then the chat's brief, then a line telling it to check git status, git log and any open PR before it carries on. The transcript shows that text in the old nudge's place, so it matches what the agent got. The brief is the chat's first user message that isn't a nudge, as text: its text parts and issue and workspace links. Images, pasted files and skill chips are left out, so a brief made only of those adds no brief line. `isNudge` matches the fresh-session nudge by its first sentence, so a turn it carries on still counts as the turn it picks up. KERNEL-286.
