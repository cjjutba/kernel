**New decisions go in `docs/decisions/`, one file each, named after the Linear issue.** Every PR used to append its entry to the bottom of `docs/DECISIONS.md` and pick the next D-number on its own branch. Any two open PRs conflicted, and the numbers collided too. While #147, #146 and #152 landed D-137, D-138 and D-139 on main, #151 added another D-137, #153 another D-138 and #150 another D-139. Fixing the text conflict alone would have left duplicate numbers on main, so the ID changed as well. A file named after its issue key can't collide, because Linear hands out keys one at a time. A PR with no issue uses its branch name, as release notes do. `merge=union` in `.gitattributes` was rejected: it resolves the conflict by keeping both sides, so two D-137s would land on main without anyone noticing. D-001 to D-139 stay in `docs/DECISIONS.md` as written, since `src/` cites them by number 114 times across 64 files. The rules are in `docs/decisions/README.md`.
