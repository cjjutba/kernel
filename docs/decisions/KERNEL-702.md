**A workspace's `archived` status means the record is archived. Its cleanup may still be running.** `archiveWorkspace` does the quick steps first: it reads the branch, expires plan approvals, stops sessions, terminals, runs and setup, then saves `status: 'archived'` and sends the event. That is where it resolves. The sidebar row folds and ConfirmArchive closes on that event, so the renderer needed no change. The slow steps run after it in the background: waiting for a Lead chat's worktree, the archive script with its trust check and timeout, the `handoff.no_commit` count, the empty Lead branch check, `unpushedCommits`, `detachWorktree`, the folder delete and `overlaps.check`. In a temp repo the archive now resolves in about 6 ms, where it took 50 ms without an archive script and 110 ms with `echo`. Real repos with a remote and real archive scripts take much longer, and that wait is what this removes.

`syncBranch` stays before the save. It costs one git call, and it leaves an archived workspace alone, so the cleanup could not read the branch after.

`archive.cleanedUp(id)` resolves when the cleanup ends, and never rejects. Code that needs the folder and branch gone awaits it: dropping a change for the team, moving the Lead's old worktree, removing a room (which waits for every workspace in the room, archived earlier or not) and restore. The UI paths, auto-archive, the Lead's `archive_workspace` and `threads.archive` don't wait. "Push and archive" still pushes before it archives, so a failed push archives nothing.

While a cleanup runs, the workspace's port block sits in `reservedPorts`, and git still lists its folder, so a new workspace takes neither. `archivingNow` stays true, and a second archive call waits for the cleanup, then deletes the branch if it asked to. The cleanup is saved under the meta key `cleanups` with what it was asked, and a quit leaves it there, so the next start runs it again. Every step can run twice: a folder already moved counts as gone, and a re-run archive script runs again in a folder that is still there.

A cleanup never throws. A failed or timed-out archive script, or any other failure, posts a warning note on the workspace. This amends D-105 for archive: a folder Kernel can't read, or one at the workspace's path that isn't a worktree, no longer fails the archive. The workspace is archived, the folder stays untouched, and the note says why. Removing a room goes ahead in that case too. Restoring such a workspace then fails, because its folder is still there, as it does for any folder back in use. KERNEL-702.
