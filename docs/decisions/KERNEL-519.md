**One PR action runs at a time on a workspace, and its pending signal clears only after the state the action ended in.** `Prs.running` marks the workspace pending and pushes `pr.pending` before the action awaits anything, then clears it in `finally`. Before this, a merge showed nowhere but the pressed button for the seconds it took to sync the branch, read GitHub, wait out GitHub's conflict check and pick the merge method. A second action on a PR that has one running is refused with a sentence naming the first ("Kernel is already merging this pull request."), whether it comes from a button, Merge all or Rowan's merge_workspace. Queueing it instead would run it against a PR the first action just changed.

Merge all reads a PR that can't merge again inside that PR's pending window, not after it. Read after, the band would show Merge for the length of the read before it moved to Conflicting. KERNEL-519.
