**The Lead's workspace carries a `lead` mark, and nothing finds it by its current-branch mode any more.** Kernel used to treat the Lead agent's workspace on the main checkout as the Lead's. That breaks once the Lead gets its own worktree, and the Lead agent already owns worktrees, the ones it inherits when an agent retires. Kernel sets `lead: true` when it makes the Lead's workspace. A one-time startup backfill marks older ones after the agents load: by the Lead agent and current mode, or by the name `lead` in a room whose agents didn't load. The backfill marks archived ones too, and the meta flag `leadWorkspaceBackfill` keeps it from running twice. The shared `isLeadWorkspace(ws, leadId)` answers for open workspaces. It needs the mark and the Lead agent, so a workspace stops counting if another agent becomes Lead. `team.isLeadWorkspace` is the same check without the archived test, because History and comments on an archived Lead's files ask it about archived workspaces.
