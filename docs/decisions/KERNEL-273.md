**The queued row says why a message waits.** The canvas draws one reason, in `WorkspaceOffline.png`: a muted note, "Queued. Sends when you are back online." The other three reasons are not on the canvas, so their copy is ours: capacity "Queued. Sends when an agent slot frees up. Change the limit in Settings, Models.", paused "Queued. Sends when you resume the room.", setup "Queued. Sends when setup passes." A running turn keeps the plain "Queued" label of `WorkspaceQueued.png`. The note is one row above the queued messages, in the transcript's note style, and it replaces the per-message "Queued" label while it shows. The canvas draws the offline message as a transcript bubble with no queue row, but queued messages stay in the queue here so they can still be edited or removed, so the shot differs from the PNG by that row. The renderer follows the reason from the `chat.queue` event and reads `chats.queueReason` once on mount. Send now is hidden for `offline` and `setup`, where it cannot send, and kept for `running`, `capacity` and `paused`. KERNEL-273.
