**The sidebar shows the row of a workspace or chat you arrive on, and opens only the room or chat that hides it.** Opening a workspace from the PRs list, the Inbox, search, the palette, a notification or ⌘1 to ⌘9 changed the main view, but the sidebar stayed where it was, so the current row could sit below the fold. Now the list calls `scrollIntoView({ block: 'nearest' })` on the current row. A row already in view doesn't move, and a hidden one moves only as far as the nearest edge, never to the center or top. If the row's room is collapsed, or it sits under a folded chat, that one room or chat opens first and the other choices of D-077 stay as they are. This amends D-077 for the row you arrive on: a room you closed by hand opens again when you go to a workspace inside it. A click on a row in the sidebar never moves the list, even when the row is cut off by an edge, and neither does a launch, or Settings handing the sidebar back, which scroll to the current row but open nothing. Scrolling is instant, so there is no motion to switch off for `prefers-reduced-motion`.
