**New chat is a page, and the New chat modal is retired.** Every way to start a chat now opens the `leadNew` route: ⌘N, the sidebar's compose button and a room's "+", the room menu's New chat and New chat from..., an issue's New chat, the command palette, and the issue warning's way back. The route carries an optional `source` (an issue arrives as a chip in the box) and `picks` (what the box had chosen when the warning stopped it). The page has the header a chat has: "room > New chat" on top, one New chat tab below with a close button, and nothing on the right. The close button and Esc go back and keep the draft. The `newWorkspace` modal, its From popover and the bare `new-chat` draft are gone. Amends D-131, which made New chat a modal, and KERNEL-366, which drew the page only for a room with no open chat. KERNEL-788.

**A chat started from New chat opens with its right panel closed, whatever the global setting says.** The box stays where it is after the send, and the panel appearing beside it would move the transcript. `ui.panelHeld` lists the workspaces that stay closed until the user presses the panel toggle in that chat, which removes the entry. The panel never opens by itself, not even when the first PR appears. That PR still shows in the header's capsule. A chat with no PR yet shows no "No open PRs" capsule while it is held. KERNEL-788.

**The issue check and the picks moved onto the page.** A send with an issue chip in the box runs the same check as before and starts it when the chip arrives, so the send finds it answered (KERNEL-543). Someone else being on the issue opens the warning. Cancel only closes it when the page is still under it, since the words, chip and picks never left. Model, effort, plan and permission mode stay with the room's draft until a send succeeds. Amends KERNEL-500 and KERNEL-544. KERNEL-788.
