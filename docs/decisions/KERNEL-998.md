**A terminal seat always runs `claude` wired into Kernel, from a folder of its own.** When a terminal tab's pty starts and Settings, Terminal, Connected has `terminal.connect` on (the default), the pty gets `KERNEL_CHAT_ID`, `KERNEL_SEAT_TOKEN` and `KERNEL_MCP_URL`, and a folder in Kernel's data folder (`seats/<chatId>`) first on its `PATH`. The folder holds a `claude` script that finds the real `claude` on the `PATH` without that folder and runs it with `--mcp-config`, `--append-system-prompt` and, when the chat has a session, `--resume`. So typing `claude` again after `/exit` still has Kernel's tools. The token lives in a 0600 `mcp.json` the script points at, never in argv, where `ps` would show it. The prompt is the one the chat gets (`agentPrompt` with `rulesFor`), in a file the script reads. The `PATH` alone is not enough, since a login shell's rc files can put Claude's own folder before the seat's. So the tab first types a `claude` shell function (fish syntax for fish) that runs the script by its path, and a function beats any `PATH` folder for every later `claude`. The `seats` feature belongs to `Chats` and closes with the hook server, so `kernel.ts` is unchanged. The endpoint binds when the first terminal pty starts, not at launch, so a Kernel with no terminal tab opens no port. Off, the tab runs plain `claude` as before, and the plain shell is never a seat.

**Resume reads the chat's session id.** The script reads a `session` file in the seat's folder, written each time the pty starts from `Chat.sessionId` and again by `Seats.sessionChanged` (KERNEL-999 calls it as hooks report a new session). A restart, or a folder move once the tab is idle (KERNEL-424), starts the pty again and so resumes. A command line that names `--resume`, `--continue` or `--session-id` keeps its own. Claude Code looks a session up by working folder, so a move may leave `--resume` without a session to find; that is not handled here.

**The Lead preset is a seat of its Lead chat.** Amends KERNEL-337: a Lead workspace lists a built-in "Lead" terminal preset, and its tab joins the Lead chat's thread like any Lead tab, so "yours", `read_plans` and hand-offs work for it. `terminal.presets` takes the workspace to list for, and the preset is in no other. Other presets, in a Lead workspace too, belong to no chat. KERNEL-998
