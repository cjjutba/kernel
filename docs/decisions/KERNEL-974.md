**Settings, Models has a Frontend row and a Backend row, and Backend keeps the `engineers` key.** An agent whose role says frontend reads Frontend. Every other engineer, a custom one included, reads Backend, and so does a chat with no agent. Renaming the key would have meant a migration for every saved file and every place that falls back to it, for no change a user sees.

A settings file from before the split gets its engineers' model, effort and compact window copied to Frontend when it loads, so both rows start where the old one was. The file's version went to 3 to mark which files had the old row. A version 3 file that names Backend and not Frontend means the user left Frontend alone, so it isn't copied. Without the version, a user who set only Backend after the update would see Frontend change on the next launch. KERNEL-974
