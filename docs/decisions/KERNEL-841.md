**A chat stays on the account that holds its cache, and a switch changes only where new chats start.** Amends KERNEL-406, where one account per provider ran every chat, and KERNEL-568, where every chat followed a switch. The prompt cache lives on the provider's servers and belongs to one account, so a chat that follows a switch reads its whole history again at full price. With Settings, Account "Keep chats on their account" on (the default), `Placement.accountFor(provider, chat)` keeps a chat on the account it last ran on (`ranOn`) while that account is still in Kernel, reads as signed in, has no rejected 5-hour or weekly window and no limit on the chat's model, and is below the move threshold. The threshold is `nearLimit`'s: 90% of the 5-hour window, 95% of the weekly one. A chat that fails any of these moves to the provider's account in use, and so does a chat that never ran. With the setting off, every chat runs on the account in use, as before. KERNEL-843.

**The checks read what Kernel already knows and start no read.** Sign-ins are as Kernel last read them, and windows are the stored `limits`. A login that signed out behind Kernel's back keeps its chats until a session or a read finds out, then they move. KERNEL-843.

**A switch says which chats go: Keep or Move all.** `switchTo` takes `move`. `keep`, the default with the setting on, sends only new chats to the new account. `all` places every open chat of the provider on it until that chat's next turn starts. Kernel keeps those placements in store meta (`placedChats`), since a chat's `ranOn` must still name the account it left for the move note. Either way, only the idle processes of chats whose account changed end, and a running turn finishes where it started. A switch at a limit needs no `all`: the chats on the limited account fail the checks and move by themselves. KERNEL-843.

**A process runs on its chat's account, not the account in use.** A Claude process gets `claudeEnv(account)`: the login's folder, its token or its API key. A Codex process gets that account's CODEX_HOME and key. Every account's home links `sessions` to `~/.codex/sessions`, so a thread started in one home resumes in another. Removing an account ends the idle processes on it before its folder goes. A new key or a new sign-in for an account ends the idle processes on it, whether or not it is in use. KERNEL-843.

**The account list counts the open chats on each account.** `AccountProfile.chats` counts the provider's open chats whose next turn runs on that account. Chats that never ran are left out, since they start wherever the provider is then. The CLI's own login's chats count on its twin's row (KERNEL-701). KERNEL-843.
