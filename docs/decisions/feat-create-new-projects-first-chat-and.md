**Adding a project makes its first chat and worktree right away, so the first Send stays in the same chat.** Amends KERNEL-948 and KERNEL-951. The New chat page made the chat and its worktree on the first Send and then switched to it, which looked like landing in another chat, and the tab turned into "New tab". Now the last project setup step (Seat agents) is followed by `Projects.makeFirstChat`, which calls `Lead.newLeadChat` with no prompt: nothing is held or sent, the worktree is cut and the files are copied at once, and the chat waits for its first message. Its branch and folder still take their names from the first title. The chat is the project's `firstChatId`, so the renderer can open it, and it keeps `firstInProject`, so the setup rows show as KERNEL-948 and KERNEL-951 describe.

**The setup script stays optional.** With a script, it runs in the background as in KERNEL-1012 and the chat takes a message meanwhile. Without one the chat has no `setupRun` and is `ready`, never failed or warned, and the Lead hears nothing about setup.

**An unused first chat blocks nothing.** Archiving the project or auto-archive removes it like any other chat. It is made once: a retry of setup, a project that already has a chat, or an archived project makes none. If it can't be made, setup does not fail, and New chat makes the chat on first Send as before.
