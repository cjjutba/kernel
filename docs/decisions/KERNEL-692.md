**Kernel is the only Lead, and a repo's Lead file customizes it instead of replacing it.** Under KERNEL-397 a file marked `lead: true` or named by `[team] lead` became the Lead, and Kernel's own Rowan filled in only when the repo had none. That meant two personas for the same job, a Lead name that changed from room to room (Rowan, Lead or Kernel Lead), and a Lead picker in Settings that moved workspaces between agents. Now `resolveTeam` always leads with the built-in, under `kernel-lead`, named Kernel, with `builtIn: 'lead'`. At most one file shapes it, picked in this order: `.claude/agents/kernel.md`, then the file `[team] lead` names, then the first file marked Lead by name that isn't a plugin's. Its prompt, tools, disallowedTools, model and effort replace the built-in's, its path goes in `file` so the UI can show Default or Customized, and it leaves the team list. Other files marked Lead keep the `second-lead` warning, and any other agent named Kernel shows as "Kernel (agent)" with a `kernel-name` warning. `leadFrom` is `file` or `builtin`, and the telemetry enum keeps its old values. `Lead.adoptLeadWorkspace` already hands a room's Lead workspaces to whoever leads, so a chat that ran on `rowan` moves to `kernel-lead` with no migration. Reverses the Lead choice in KERNEL-397. KERNEL-692.

**Settings no longer picks a Lead, and Customize and Reset only touch kernel.md.** `agents.setTeam` ignores `lead`, and leaves a `[team] lead` already in the file as it is, since that still names the file that customizes Kernel. Customize writes `.claude/agents/kernel.md` from the bundled starter, without its model line, and refuses when the file exists. Workspaces stay on `kernel-lead`, so nothing moves. `agents.resetLead` deletes `kernel.md` and nothing else. When another file customizes Kernel, such as a committed `rowan.md` with `lead: true`, Reset refuses and names it, so a click never deletes a file the team shares. KERNEL-692.

**The Lead rule speaks to Kernel as "you".** `LEAD_RULE` opens "You are Kernel" and drops lines like "Kernel names the branch", which read oddly once the Lead is Kernel. The update header is "Team update, not from the user." The rule tells the Lead that any message starting "Team update" is a report on its teammates, which covers the older "Team update from Kernel" header too. The rule is shorter than the KERNEL-678 cap.
