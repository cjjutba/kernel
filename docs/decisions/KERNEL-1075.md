**Automatic review is on by default.** Amends feat-automatic-review-off-by-default, which turned it off on every plan to save usage. KERNEL-1058 promises that one model reviews the other's PRs. With the default off, a tester who never opens Settings never sees that, so the headline feature stayed hidden. KERNEL-1074 lets reviewers run read-only commands without asking, so turning reviews on no longer fills the Inbox with approvals.

The base default `pr.autoReview` is now `true`, and `planDefaults` still sets nothing for it. A user who never set it gets reviews on, on every plan. A user who turned it off keeps it off: Kernel saves only what the user chose, and a patch with `false` is saved as chosen, so `false` is told apart from unset. A file from before KERNEL-225 that saved `false` keeps it, since it now differs from the default. Its `true` was never a choice and follows the default, which is also `true`. The special case that kept an old `false` against an off default, and the `true` entry in the list of values saved before KERNEL-225, are gone because they have no work left.

Everything else in the earlier decision stands: the setting is in Settings, Pull requests, and `Reviews.requestReview` still runs a round with it off.
