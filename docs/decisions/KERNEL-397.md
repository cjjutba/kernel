**Kernel adapts to a repo's own agents instead of asking the repo to adapt to Kernel.** Kernel used to assume Kernel's conventions: one agent marked `lead: true`, a role it could match words against, and agent files written for its own workflow. A repo that brought its own `.claude/agents` couldn't be briefed when no file said `lead: true`, and nothing in the app could pick a Lead. Now the agent files stay the repo's, and Kernel never rewrites them unless the user asks. Kernel's choices about the team live in a `[team]` table in the shared `.kernel/settings.toml`: `lead`, `reviewer` (`none` for no reviewer), `members` and `helpers`. The table holds only exceptions to what Kernel works out from the files, so a room that agrees with Kernel writes nothing, and an agent hired later joins without an edit. `agents.setTeam` is the only writer. It splices the table into the file's text (`upsertTomlTable`), keeping comments and other tables, and refuses any change it can't confirm by parsing the result back. `saveRepoSettings` re-stringifies the whole file and would drop a committed file's comments. `resolveTeam` (`services/teamResolve.ts`) is the one place a room's team is decided, from the files, `[team]` and Kernel's built-in agents, and every caller reads the resolved `lead`, `reviewer` and `member` flags (`@shared/team`). Setup decides roles from the files without a model call, the way New agent drafts (D-039). Team watches `.kernel/settings*.toml` as well as `.claude/agents`, so a pulled `[team]` change takes effect. KERNEL-397.

**Only `lead: true`, or a `role:` that says Lead, makes an agent the Lead.** `agentFromFile` used to make any agent whose role said "lead" the Lead, and when a file had no `role:` it took the role from the first words of the description. "Tech lead. Reviews architecture." became a second Lead that could never take a task or be retired. A description that says lead now gets a `looks-like-lead` warning on Team. When several files are marked Lead, `[team] lead` decides, else the first by name, and the others get `second-lead`. A room whose Lead was only named in the description gets Kernel's Rowan after the upgrade. `Lead.adoptLeadWorkspace` hands the Lead's workspace, with its chats, to whoever leads now, so nothing is lost. KERNEL-397.

**Kernel's own Rowan and Theo fill in when a repo has no Lead or reviewer, and they never become files on their own.** They run from the bundled `docs/starter-agents/rowan.md` and `theo.md` under reserved ids, `kernel-lead` and `kernel-reviewer`. A saved workspace therefore never points at the wrong agent when the repo later adds its own `rowan.md`. They show as Rowan and Theo, or as Lead and Reviewer when the repo has an agent with that name, or Kernel Lead and Kernel Reviewer when that is taken too. They have no model or effort of their own, so Settings, Models decides them. Save and Retire refuse them. Customize copies the bundled file into `.claude/agents` under the first free name (`rowan.md`, `lead.md`, `rowan-lead.md`, and the same for Theo), without its model line. It updates `[team]` when that named the reserved id, and moves their open workspaces to the copy. `Team.agentOf` still finds a built-in agent for a workspace that ran on it after the room gets its own. New rooms and the starter templates now seat only Kai, Noor and Ivy as files. Rowan and Theo are built in from the start, and Team can add one starter teammate to a team that already has agents. Amends D-028's seating and KERNEL-20. KERNEL-397.

**An agent whose tools can't open a pull request is a helper, and the Lead hands it no task.** Repos often carry small agents written to be called by another agent, such as a test runner or a read-only reviewer. A tools line without Bash, or without Edit or Write, can't take a task to a pull request. Such an agent doesn't take tasks unless `[team] members` lists it, and `[team] helpers` keeps any agent out. `create_workspace` refuses a helper with the list of agents that take tasks. A task with `review_of` still goes to the room's reviewer. `list_agents` marks the Lead, the reviewer and the helpers. Settings, Agents has a switch per agent, and Room setup reviews the team when the repo brought one. Autostart waits for Open the room only when that team has warnings. KERNEL-397.

**The reviewer is the one `resolveTeam` picks, and the auto-review rule needs one.** The reviewer is `[team] reviewer`, else the first non-Lead agent whose role says review, else Kernel's Theo. Lead updates, `reviewedByBase` and `modelFor` read the resolved reviewer instead of matching words in the role. `LEAD_REVIEW_RULE` used to ask for "the team's reviewer" whether or not there was one. It now goes to the Lead only when the room has a reviewer, so `[team] reviewer = "none"` turns automatic review off for the room. A retired reviewer's open reviews go to whoever reviews next, and its other workspaces to the Lead, since the next reviewer may be Kernel's read-only Theo. Settings, Agents won't make an agent the Lead while it has open workspaces of its own, which would then run with the Lead's tools and send no updates. Amends KERNEL-115. KERNEL-397.

**An agent file's tools line holds in Kernel.** Kernel never passed `tools:` to the SDK, so an agent documented as read-only could edit. `toolPolicy` (`services/agentTools.ts`) reads the line the way Claude Code reads a subagent's. `Bash(git:*)` counts as Bash, older tool names map to the tools that replaced them, and `mcp__linear` or `mcp__linear__*` allows a whole server. Built-in tools the line leaves out go in the session's `disallowedTools`, except Write and Edit. Plan mode writes its plan to `~/.claude/plans` before it asks for approval, and the plan comes up empty without that file (D-023). So those two stay, and an agent whose line leaves them out can use them only for a `.md` file right in that folder. A PreToolUse hook with no matcher refuses any other tool the line doesn't list, with the reason, and that covers the session's subagents too. Every agent keeps Kernel's `mcp__kernel__` tools and the tools a session needs: ExitPlanMode, EnterPlanMode, AskUserQuestion, ToolSearch, Skill and the task list. An agent with no tools line is unrestricted. The SDK's `agent` and `agents` options were not used. They apply the agent's own model over the chat's, they need the file in the worktree (uncommitted files aren't there), and they would register every teammate as a subagent of every session. A changed agent's process ends once its turn does (`Sessions.restartIdle`), since a process reads its agent only when it starts. This repo's own Kai, Noor and Ivy gained `mcp__linear`, and Lumi gained Write, so they keep what they used. `test/live.tools.test.ts` checks it against real Claude Code. KERNEL-397.

**Kernel's workflow lives in rules it adds to every agent, and agent files describe only the job.** The share_file guidance was only in the starter files, so a repo's own agents never knew it. `SHARE_RULE` now goes to every teammate and reviewer while sharing is on, after their own rule, and the starter files drop what the rules say. `BLOCKER_RULE` named Kernel's own repo rules (code added to `kernel.ts`, hex values in screen code), and Kernel's Theo now reviews every repo. It names the repo's own CLAUDE.md or AGENTS.md instead. This repo's `theo.md` adds Kernel's examples on a line of its own. Amends KERNEL-377. KERNEL-397.

**A role comes from the description only when its first words are one word.** "Frontend engineer." is Frontend, as before. Most agent files outside Kernel open with a sentence, such as "Reviews pull requests for...", which used to read as roles like "Reviews Pull". Those now take the file's name, so code-reviewer is Code Reviewer. KERNEL-397.

**Usage data is opt-in, and nothing leaves the Mac until the user says yes.** Without it, a problem on someone else's Mac shows up only when they file a bug. Every event and property is listed in `@shared/telemetry`. A property is a fixed value, yes or no, or a short code checked by a pattern, and `checkEvent` drops anything else, so no path, name, prompt or line of code can reach an event. The Telemetry feature always keeps the last 200 events for Settings, Privacy and Help, Copy diagnostics. It sends only when the build has a key and `privacy.telemetry` is `on`. Kernel asks once, after the first room and outside Settings and onboarding, and closing the question counts as no. The events wait in a capped file in the data folder, then go to PostHog's batch endpoint once a minute under a random install id, with no person profile and no location lookup. Turning sharing off deletes the file and the id. The key comes from `KERNEL_TELEMETRY_KEY` at build time (`docs/RELEASING.md`), and only a packaged build that isn't a smoke test, fixture or headless run gets it. `DO_NOT_TRACK=1` and `KERNEL_TELEMETRY=0` turn it off whatever the setting says. An error is sent as its class and the first line of the stack in Kernel's bundle, never its message. The site and the README now say usage data is opt-in. Amends KERNEL-288, which kept crash reporting local. KERNEL-397.
