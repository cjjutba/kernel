**Kernel's features move out of `kernel.ts` into one file each under `src/main/features/`, and `kernel.ts` keeps only the wiring.** Almost every Engine PR conflicted on `kernel.ts`. It had 3,211 lines and 87 commits, and of its last 80 commits, 53 touched the import block, 43 the `handlers()` map, 37 the constructor and 35 the class fields. Those are lists every feature adds to at the bottom, so two unrelated PRs met there. KERNEL-324 to KERNEL-331 move the code in eight PRs during an Engine freeze, and KERNEL-332 splits `src/shared/types.ts` by domain. Once they land, a feature's state, logic, imports and IPC channels live in its own file. `handlers()` joins each feature's map with `channels`, which throws when two features answer the same channel, where a spread would quietly keep the last. A reaction to a finished turn goes in `features/sessionDeps.ts`. A reaction to a push event goes in `listen` in `features/wiring.ts`, which keeps one push listener, so the reactions still run in a fixed order and one that throws still stops the rest. KERNEL-324.

**A feature holds the Kernel it was built with, not a deps object.** The services in `src/main/services/` take a deps object of closures and keep doing so. A feature calls other features all the time, and with a deps object every new call would edit the deps type and the construction site in `kernel.ts`, the conflict this series removes. A call through `this.k` is looked up when it runs, so tests that swap `github`, `refreshPr`, `archiveWorkspace` or the whole `settings` on the instance still reach the code they stub. Five rules keep that true. A feature's constructor stores `k` and nothing else, because tests build Kernels that never start and `settings` is undefined until `start()`. The test seams stay on Kernel in one block, and code reads them through `k` each time it calls them. Every call to `refreshPr` or `archiveWorkspace` goes through `k`, even from inside the feature that owns it. A Kernel method that forwards to a feature returns the feature's promise and is not `async`, since an extra await moves timing-sensitive tests. A feature imports `kernel.ts` and other features only as types, which `test/featureBoundaries.test.ts` checks. Until a member's feature moves out, code outside `kernel.ts` reaches it with typed bracket access (`k['nameChat']`) instead of making it public, so each move changes few lines in `kernel.ts` and a renamed member still fails typecheck. KERNEL-331 removes the last of those. KERNEL-324.

**The moves move code and change nothing else.** Meta keys stay as they are saved (`setups`, `reviewsToArchive`, `trash`, `limits`, `cutOff`, `held`, `leadChatBackfill`), with no version envelope, so nothing saved is lost on upgrade. `createWorkspace` moves whole. Behavior that looks like a slip, such as `update.get` reporting 0.0.0 where `app.info` reports 0.1.0, stays until a PR of its own changes it. KERNEL-324.
