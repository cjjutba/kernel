**Variables live encrypted in `<dataDir>/env.json`, and Kernel saves none when it can't encrypt them.** The file keeps names in the clear and each value encrypted on its own, app-wide under `app` and per room under `rooms.<roomId>`. The cipher is injected in the Kernel options, the way `refreshPath` is. `index.ts` passes `safeStorage`, which keeps the key in the Keychain. Tests pass a fake, because `safeStorage` doesn't work under ELECTRON_RUN_AS_NODE. With no cipher, `env.set` throws and nothing is written, so a Mac where the Keychain is unavailable gets an error rather than a secret in plain text. Values are decrypted once into memory, because a session starts synchronously and can't wait on a read. A value the cipher can no longer read keeps its name and is left out of every environment until it is set again. Removing a room deletes its variables. Only `env.reveal` sends a value to the renderer, and fixtures hold names only. KERNEL-247.

**One builder makes the environment for sessions, scripts and terminals, and a later layer wins.** The order is the Mac's environment, app variables, the room's env files in list order, the room's variables, then Kernel's own. A room's variable beats its env files because it is the one the user typed into Kernel. Env files come from `[env] files` in the room's settings and are resolved against the workspace folder, so each worktree reads its own copy. A file that can't be read is skipped and `env.get` reports it as missing. The environment is built when the process starts, so a running session or dev server keeps the values it started with. `exec.ts` git and gh calls still use Kernel's own environment, so a room variable can't change how Kernel talks to git or GitHub. KERNEL-247.

**Sessions, scripts and terminals get the same Kernel variables.** These are `KERNEL_PORT`, `KERNEL_WORKSPACE_ID`, `KERNEL_WORKSPACE` (the folder) and `KERNEL_ROOT_PATH` (the main checkout), listed in `src/shared/kernelVars.ts`. Before, scripts had no `KERNEL_WORKSPACE_ID`, and sessions and terminals had neither path. Users can't name a variable after one of these four. Scripts also get `PORT` and `FORCE_COLOR=0`, which win over a user's variable in scripts only and can still be set for sessions and terminals. `sessionEnv` drops `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN` after the merge, so a user variable can't move a session or a big terminal onto API billing. Scripts keep them, since a project's dev server may need its own key. KERNEL-247.
