**Variables live encrypted in `<dataDir>/env.json`, and Kernel saves none when it can't encrypt them.** The file keeps names in the clear and each value encrypted on its own, app-wide under `app` and per room under `rooms.<roomId>`. The cipher is injected in the Kernel options, the way `refreshPath` is. `index.ts` passes `safeStorage`, which keeps the key in the Keychain. Tests pass a fake, because `safeStorage` doesn't work under ELECTRON_RUN_AS_NODE. With no cipher, `env.set` throws and nothing is written, so a Mac where the Keychain is unavailable gets an error rather than a secret in plain text. Values are decrypted once into memory, because a session starts synchronously and can't wait on a read. A value the cipher can no longer read keeps its name and is left out of every environment until it is set again. Removing a room deletes its variables. Only `env.reveal` sends a value to the renderer, and fixtures hold names only. KERNEL-247.

**A missing `env.json` is empty, and one Kernel can't read is moved aside, never written over.** A parse error or a wrong shape moves the file to `env.json.corrupt-<time>` and starts empty, and the activity log gets one note naming the moved file. The moved file holds only names and ciphertext, so keeping it is safe, and the user can still recover from a half-written file. If the move fails, Kernel refuses to save until the file is gone. KERNEL-247.

**One builder makes the environment for sessions, scripts and terminals, and a later layer wins.** The order is the Mac's environment, app variables, the room's env files in list order, the room's variables, then Kernel's own. A room's variable beats its env files because it is the one the user typed into Kernel. Env files come from `[env] files` in the room's settings and are resolved against the workspace folder, so each worktree reads its own copy. A file that can't be read is skipped and `env.get` reports it as missing, without reading it. The environment is built when the process starts, so a running session or dev server keeps the values it started with. `exec.ts` git and gh calls still use Kernel's own environment, so a room variable can't change how Kernel talks to git or GitHub. KERNEL-247.

**An env file is read only when it sits inside the workspace folder, is a regular file, and is 1 MB or less.** `[env] files` can come from a repo's shared `settings.toml`, and KERNEL-209 only asks before the room's scripts run and its files are copied. So an absolute path, a path that climbs out with `..`, and a link whose real path is outside the folder all count as missing, the way KERNEL-209 confines `files.copy`. A link that stays inside is followed, because people link one shared `.env` into several places. The file is opened without blocking and checked after opening, so a FIFO or a device can't stall the main process, which reads env files synchronously when a session starts. Reading a file inside the repo needs no trust, because the agent can already read it. KERNEL-247.

**Sessions, scripts and terminals get the same Kernel variables. Amends D-041.** These are `KERNEL_PORT`, `KERNEL_WORKSPACE_ID`, `KERNEL_WORKSPACE` (the folder) and `KERNEL_ROOT_PATH` (the main checkout), listed in `src/shared/kernelVars.ts`. Before, scripts had no `KERNEL_WORKSPACE_ID`, and sessions and terminals had neither path. D-041 gave a big terminal `KERNEL_PORT` on top of the Mac's environment. A terminal now gets the whole environment a session gets. The terminal's shell binary still comes from the Mac's `SHELL`, so a `SHELL` in a room's variables or env files can't pick it. Users can't name a variable after one of the four. Scripts also get `PORT` and `FORCE_COLOR=0`, which win over a user's variable in scripts only and can still be set for sessions and terminals. KERNEL-247.

**Sessions and terminals take Claude Code's endpoint, account and billing settings from the Mac only. Builds on D-018.** D-018 drops `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN` so sessions bill the Claude plan. Once a room's `.env` reaches sessions, those two aren't enough: an AI project's `ANTHROPIC_BASE_URL` would send the session's traffic, the plan's login token included, to the project's proxy, and `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX` or `CLAUDE_CODE_OAUTH_TOKEN` would move billing or the account. So every `ANTHROPIC_*` and `CLAUDE_CODE_*` name from app variables, env files or room variables is dropped for sessions and terminals. The same names from the Mac's own environment stay, because setting them there is the user's choice, and `sessionEnv` then applies D-018, Kernel's own agent teams switch (D-027) and the 200k compact window (KERNEL-226) as before. So a compact window only the Mac sets can override KERNEL-226's. Scripts get every layer whole, these names included, since a project's dev server may need its own key or proxy and scripts don't run Claude Code on the plan. KERNEL-247.

**Kernel keeps values out of its own logs, but not out of what an agent prints.** An agent that runs `env` or `echo $NAME` puts the value in its own transcript, the same as reading a `.env` file. Kernel can't stop that, and KERNEL-192 lists transcripts as a place values can end up. KERNEL-247.
