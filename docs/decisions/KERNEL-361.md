**A brief held for a merge waits for `merge`, not `setup`.** A hand-off with `wait_for` holds its brief in the chat's queue the same way a brief whose setup hasn't passed is held, and both reported `setup`. The queued row then said "Queued. Sends when setup passes." and hid Send now, while the note above it said Send now starts it sooner. Once setup has passed and the brief still waits for its PRs, the queue now reports `merge`: the row says "Queued. Sends when the work it waits for merges." and keeps Send now, which starts the brief (KERNEL-259). A held brief whose setup runs again or failed still reports `setup`. The reason follows the workspace's state, so Kernel checks every queue's reason again when a workspace changes. Amends KERNEL-273. KERNEL-361.
