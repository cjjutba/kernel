**A room icon is a file in the data folder, served as a data URL, stored as downloaded and shown in grayscale by the renderer.** A room shows its letter unless `Room.icon` names a file. The file is the GitHub owner's avatar or a PNG or JPEG the user picked. Files live in `<dataDir>/room-icons/<roomId>-<at>.<ext>` and never in the room's repo, so an icon is Kernel's choice and stays out of git. `gh api users/<owner> --jq .avatar_url` finds the avatar for a user or an org, and Kernel downloads it with `s=128`. Kernel checks every file's first bytes for PNG or JPEG and refuses anything over 2 MB. It doesn't use `nativeImage`, which tests can't load. Setting an icon writes the new file before the room points at it, then deletes the old one, so a failed fetch or a rejected file leaves the room as it was. Removing the room deletes its file. When `gh` is missing, the network is down or the room isn't on GitHub, `rooms.setIcon` throws "Couldn't get the GitHub avatar. The room keeps its letter." and nothing changes. `rooms.icon` returns the image as a data URL, which the renderer's CSP already allows (`img-src data:`). The data URL stays off `Room`, because rooms are pushed whole on every change and an image would make each push kilobytes larger. CJ chose grayscale for display, so the renderer applies the filter and the stored file keeps its colors, in case that choice changes. KERNEL-241.
