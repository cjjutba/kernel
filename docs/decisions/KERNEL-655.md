**Setup, run and archive scripts run in a terminal of their own.** `runScript` starts each one in a node-pty (`xterm-256color`, the login shell with `-lc`) at 120 by 30, so pnpm, Vite and the rest print colors and redraw their progress in place. The terminal makes the shell a session leader, so it leads its own process group, and Stop, the setup timeout and quit still signal the whole group. SIGKILL now goes to the group `STOP_GRACE_MS` after SIGTERM even when the shell already exited, since with a terminal the exit no longer waits for every process holding the output. A script's exit code is null when a signal ended it, as before. `scripts.resize` sizes a running script's terminal, and the next run of that script starts at the size its view last asked for. KERNEL-655.

**Scripts no longer get FORCE_COLOR=0.** A terminal tells tools they can print colors, and the view built on `script.data` shows them. Scripts still get `PORT`. A `FORCE_COLOR` from the Mac, the app or the room reaches scripts unchanged. Amends KERNEL-247. KERNEL-655.

**A script's stdin is /dev/null, not the terminal.** The shell runs `exec </dev/null` before the script, so every read ends at once, as with the closed stdin from KERNEL-216. Typing an EOF into the terminal was tried first. It echoed `^D` into the output and ended only the first read, so a script that read twice hung, and run scripts have no timeout to end it. With stdin not a terminal, a prompt library also skips its prompt instead of waiting in raw mode. Amends KERNEL-216. KERNEL-655.

**Script output goes out twice.** `script.data` carries it as printed, batched every 50 ms like `terminal.data`, and main keeps each script's last `TERMINAL_KEEP` characters for `script.state`, dropped on archive like the lines (KERNEL-340). `script.output` still carries plain lines, with escape sequences removed and only what the last `\r` left on each line, so the URL check, the setup log and the bottom-bar word read the same text as before. A redraw that moves the cursor up, as pnpm's progress does, shows in the lines as one line per redraw. Kernel's own lines in the setup log, such as "Setup failed with exit code 1", go out on both, after the script's output. KERNEL-655.
