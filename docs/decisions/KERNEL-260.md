**A repo's own install scripts wait for the user to trust them, like its setup script does.** Amends D-078 and KERNEL-209. `pnpm install`, `npm install` and the others run the root `package.json`'s `preinstall`, `install`, `postinstall`, `preprepare`, `prepare` and `postprepare` scripts. New room's Install step ran that install in a fresh clone, and every workspace's setup script ran it again, so cloning a hostile repo ran its code before anything asked. KERNEL-209 gated the settings text and left this alone.

The choice was between skipping the install until trust and running it with `--ignore-scripts`. Kernel asks first. Running with scripts off would leave a repo that needs its `postinstall` half installed, and the setup script is the repo's own text either way.

`installScripts(repoPath)` reads those six scripts from the root `package.json` when a lockfile install applies. The trust subject carries them as `installScripts` when the room's setup script installs packages, or its Install step still has to run. A setup script installs packages when it contains the lockfile's own command or calls npm, pnpm, yarn or bun with an install verb, through wrappers, so `npm ci` and a bare `yarn` count. That reads more than the lockfile's command on purpose: missing `npm ci` would leave the hole open. `trustHash` adds the scripts tagged and only when there are some, as it does env files (KERNEL-247), so a room whose package.json has none keeps the hash it trusted. The dialog lists them under "Install scripts in package.json" and shows the setup script too.

New room. The settings.toml Kernel writes is still trusted without asking (D-078), but only when the repo has no install scripts. Otherwise the first workspace waits in `trust` as KERNEL-209 has it, and the Install step ends `ok` with "Skipped until you trust this repo's install scripts". Trusting the room runs the install that was held, in the background, and logs a note. `installCommand` decides, so nothing runs when `node_modules` exists. The Install step counts as one of the room's installs only until it has run, so trusting also trusts the same text without the install scripts. Without that, a room whose setup script isn't an install would ask a second time once `node_modules` appeared. A Settings save never vouches for install scripts, since no page writes `package.json`: new or changed ones wait for the dialog.

Not covered. The scripts of the packages an install fetches. pnpm 10 skips those by default, and npm and yarn run them. Only the root `package.json` is read, so a workspace package's own scripts in a monorepo aren't listed. Trust covers the text, as in KERNEL-209: trusting `"postinstall": "node setup.js"` doesn't cover a later change to `setup.js`.

Existing rooms get no free pass. A room whose package.json has install scripts, and that installs packages, asks once on its next workspace after the update. `prepare` scripts such as husky's are common, so expect that prompt for many rooms. KERNEL-260, KERNEL-404.
