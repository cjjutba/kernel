**Before a hand-off starts an issue, Kernel checks whether someone else is already on it, and create_workspace refuses until the Lead passes confirm.** Kernel runs three checks at once. It lists the branches on the room's remote with `git ls-remote --heads`, looks for an open PR through gh when the room's code host is GitHub, and reads the issue's assignees through the room's tracker. A branch counts when its name holds the key the way Kernel and the trackers name branches: `kernel-31` as a word in any case, never `kernel-310`, and a GitHub number only at the start of a part of the name (`feat/41-crash`, `41-crash`). A PR counts when its title or description names the key (`#41` for GitHub), or its branch does. An assignee counts when the tracker says it isn't the user. Linear says so with `isMe`. For GitHub, Kernel compares the login with gh's signed-in user, and asks gh only when someone is assigned. When anything turns up, create_workspace says what it found, and the Lead asks the user and calls again with `confirm: true`. Rowan answers in the chat, and no card is drawn, as KERNEL-438 left open. A review starts no work on the issue, so it skips the checks. New workspace reads the same findings through `issues.taken` for ConfirmIssueTaken.png. KERNEL-479.

**The room's own workspaces are never someone else.** A branch or PR number that any workspace in the room has, archived ones included, doesn't count. A room that started the issue before and archived it shouldn't warn the user about their own work. KERNEL-479.

**Every check fails open.** Each one gets 10 seconds (`TAKEN_TIMEOUT_MS`), and `git ls-remote` runs with `GIT_TERMINAL_PROMPT=0`, so a remote that wants a password fails at once. A check that fails or runs out adds one sentence to the notes, and the workspace starts anyway. create_workspace's result ends with those sentences. A room with no such remote, a code host that isn't GitHub and a room with no tracker skip their check without a note, since there is nothing to ask. A GitHub assignee Kernel can't compare, because gh is signed out, is a note and not a finding. Holding the user up over their own name would be worse than missing one. KERNEL-479.

**`freeBranch` treats a name `<remote>/<name>` has as taken.** It reads `refs/remotes/<remote>/` as of the last fetch, with no network call, so a new workspace never picks a branch someone already pushed and then fails to push or pushes over it. Every branch pick that knows the room's remote passes it: new workspaces, forks, Continue, a restore that needs a new branch, and a chat with Rowan named from its title. KERNEL-479.
