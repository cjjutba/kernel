**The right panel's toggle ends the chat header in both states, outside the PR band.** Amends KERNEL-413 and departs from `design/redesign/README.md`, which puts the toggle at the end of the panel head with the panel open (Header and panel toggle, and the `PrMergedOpen` row). Inside the head the toggle took the band's green, violet or red and read as part of the PR state. It is window chrome, not a PR action. The header spans the chat column only, so with the panel open the toggle sits just left of the panel's edge, in neutral grey. The panel head now holds only `PrHeader spread` or `LeadPrSummary spread`, and the band reaches the panel's right edge. The head's right padding is 12px, the same as its left. With the panel hidden nothing changes: the PR capsule, then the toggle, at the window's right end. Conductor lays it out the same way. No canvas PNG draws it.

The README's build note said the container rule that hides the PR button labels must count the toggle's width. It no longer does. The merged row needs about 337px of the head's content box, and the box is 375px with the panel at its widest, so the labels hide below 337px instead of 372px. KERNEL-425.

**⌘⇧B toggles the right panel, next to ⌘⌥B.** ⌘⌥B keeps working, ⌘B stays the sidebar only, and ⌘⌥⇧B does nothing. The toggle's tooltip shows ⌘⇧B because it is the shorter chord. The handler matches the physical `KeyB`, since Option turns B into ∫. `meta+shift+KeyB` also joins the keys a preview hands back to Kernel, so ⌘⇧B works while a preview has focus. That adds ⌘⇧B to the list in KERNEL-303's "App shortcuts typed in a preview go to Kernel". KERNEL-425.

KERNEL-769 replaces this: the toggle now stays in the top right corner, in a neutral cell beside the band, in both states.
