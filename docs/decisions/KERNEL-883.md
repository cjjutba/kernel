**A retried clone clears only a folder Kernel made for that setup.** New project records whether the checkout's folder was there when setup started. If it wasn't, anything in it before a clone succeeds came from a failed clone, so Try again deletes the folder and clones again. If it was there, it is the user's: Kernel never deletes it or anything in it, and when a failed clone left files there the retry stops with an error that says to empty it. A folder project never goes through this, since its checkout step never clones. Amends KERNEL-876.

**A setup that hasn't finished cleanly is saved, so Try again works after a restart.** The steps, the New project request and what Kernel did on earlier tries (seated the starter team, made the folder) go under the meta key `projectSetups` on every publish, and leave it once no step fails or waits. On the first use after a launch Kernel reads them back. Nothing from before the quit is still running, so a step that was running, or the next one due when none had failed, fails with "Setup stopped when Kernel quit." and Try again starts there. Amends the third entry of KERNEL-876.

**The saved steps reach the window on the `project.setup` events it already reads, sent when it asks for the projects.** Pushes sent before a window loads are lost, and a window asks for `projects.list` once as it loads, after it starts listening. So that call publishes every unfinished setup first. Project setup and the store need no change, and a reload gets them back too. KERNEL-883.
