**Sharing a file with the user is a file plus one tool call.** An agent saves the file in its workspace, usually under `.kernel/shared/`, which Kernel adds to `info/exclude`. Then it calls `mcp__kernel__share_file({ path, title?, note? })`. Nothing else is part of the contract: no Claude artifacts, no Design canvas, no SDK feature. Any harness that can write a file and call an MCP tool can share, so Codex or Gemini CLI fit later without a second path. The Lead, a reviewer and an ordinary teammate all get the tool, next to the tools they already had.

Kernel decides what the file is, not the agent. The extension names the type, and the first bytes must agree: PNG, JPEG, GIF, WebP and PDF by magic number, SVG by its first element, HTML and Markdown as UTF-8 with no NUL byte. Caps are HTML 10 MB, SVG 2 MB, other images 20 MB, PDF 50 MB and Markdown 2 MB, and a file keeps at most 100 versions. A path outside `realpath` of the workspace is refused, and a symlink that leads out counts as outside. For the Lead the workspace is the room's checkout.

Each version is a copy in `<dataDir>/shared/<id>/v<n>/<name>`. Kernel writes it through a temp file and a rename, and saves the row after the bytes. One row per workspace and source path holds every version in `shared_files` (migration 3). Sharing the same bytes as the newest version adds nothing. The copies belong to the room, not the workspace: archiving a workspace leaves them, and removing the room deletes the rows and the folders. Show in Finder reveals the source file while it still has that version's bytes, and Kernel's copy otherwise.

A share puts a `shared` item in the calling chat and adds a `shared` event to the Team update. That event never wakes the Lead by itself. It goes out with the next update that does, in `TeamUpdateRow.shared` rather than `events`, and only the newest version of each file is listed. The Lead's own shares stay in its own chat.

`services/kernelServer.ts` is the only place the MCP server gets the name `kernel`, because the auto-allow in `canUseTool` and the hook server's quiet list both match `mcp__kernel__`. A server under another name would ask the user before every share.

The tool ships behind `experimental.sharing` in settings.json, off by default, with no page in Settings. Off, every agent gets exactly the server and prompt it had before. The Lead's line about shared files in Team updates is `LEAD_SHARING_RULE`, which `rulesFor` adds after LEAD_RULE only while sharing is on.
