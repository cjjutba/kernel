**The Lead can merge a ready PR when the user asks, behind two gates Kernel enforces.** Amends D-008, which kept merging with Kernel and never with an agent. `merge_workspace` is always registered, because a Lead gets its tools when its session starts, and `mcp__kernel__*` tools are auto-allowed, so the handler is the only gate. It refuses the whole call while `pr.leadMerge` is off, which is the default and lives in Settings, Pull requests as "Let the Lead merge when you ask". It also refuses in a turn Kernel started (`sessions.kernelTurn`), such as a Team update, so Rowan never merges on its own initiative. Answering an approval card inside such a turn doesn't make it the user's. The setting and the turn are read on each call. Each id then goes through the same `mergePr` as the Merge button, so `mergeBlock` (KERNEL-349) still asks for green checks and the reviewer's approval, and the wait release, archive on merge, review archive and notifications follow from the `pr` event as they do for a click. The saved PR state is read again from GitHub first, since a merge moments before makes GitHub check every other PR again (KERNEL-283). A review's id merges the PR it reviewed. KERNEL-352.
