**Main picks the command a big terminal tab runs, and the tab keeps it.** `chats.create` with `kind: 'terminal'` takes a preset id, and with none it uses `terminal.preset` from the settings. Main looks the preset up, works out the command and stores it on the chat as `Chat.terminal: { preset, command }`. `ensurePty` types `chat.terminal.command` into the login shell, so a tab restarts with the command it was opened with even after the preset changes or goes away. A plain shell stores `command: null`. Terminal chats from before presets have no `terminal` and run `claude`, which is what they always ran. The renderer never sends a command. KERNEL-248.

**Presets come from Kernel's built-ins, the PATH and the app settings, never the repo, so they need no trust.** KERNEL-209 makes a room's scripts and KERNEL-247 makes its env files wait for trust because a commit can change them. A preset can't come from a commit. The built-ins and the five CLIs are in Kernel's code, and custom commands are the user's own, typed into `settings.json`. A custom command runs in the login shell the same way `claude` does today, with the environment `envFor` builds. So a repo's env files still reach it only once the room is trusted. KERNEL-248.

**Kernel lists a CLI when an executable file with its name is on the PATH, and never runs it.** `terminal.presets` checks `codex`, `opencode`, `amp`, `copilot` and `gemini` in each folder of `process.env.PATH` with `stat` and `fs.access` X_OK. It doesn't refresh the PATH itself. That PATH is the one `refreshPath` set at launch or at the last preflight, so a CLI installed since shows up after Check again or a restart. A file that isn't executable and a folder with the name don't count. Running `codex --version` would be slower and would run code to answer a list. A CLI that is found runs its plain command, and flags go in a custom command. KERNEL-248.

**When the settings' preset is gone, a new tab runs Claude. A preset asked for by id that is gone is an error.** A preset goes away when its CLI is uninstalled or its custom command is removed. The settings' choice falls back so ⌘⇧T keeps working. A preset the + menu named but that vanished since the menu opened fails with a message, rather than quietly running something else. KERNEL-248.

**Only in worktrees takes `--dangerously-skip-permissions` out of any preset's command on a current-branch workspace.** That covers Claude without permission prompts and any custom command with the flag as a whole word. The shell takes off quotes and backslashes before `claude` reads its arguments, so the flag counts in double or single quotes, after a backslash, with `=value`, and next to `;`, `|`, `&`, `<` or `>`. Kernel removes it in each of those forms and keeps the rest of the command, so `claude --dangerously-skip-permissions --verbose` runs as `claude --verbose`. The command stored on the chat is the one that ran, and the tab can tell the flag was dropped by comparing it with the preset. Other ways to skip prompts in a custom command, such as `--permission-mode bypassPermissions`, are left as typed. The user wrote that command, and KERNEL-193 scopes the switch to this flag. Only in worktrees guards against mistakes in the user's own commands and is not a security boundary. An alias, a shell variable or command substitution (`X=--dangerously-skip-permissions; claude $X`) can't be caught. KERNEL-248.

**A tab is titled after its preset: a built-in or found CLI by its id, a custom command by its name as typed.** So "Terminal (claude)", "Terminal (claude-skip)", "Terminal (shell)" and "Terminal (codex)". That is how `WorkspaceTerminalPresets.png` shows it, and what a terminal tab was already called. A full name such as "Claude without permission prompts" is too long for a tab. A custom command keeps the name the user gave it, "Terminal (Dev server logs)". On a current-branch workspace with Only in worktrees on, a claude-skip tab keeps its title while it runs plain `claude`, and KERNEL-251's one-line notice says so. KERNEL-248.

**`experimental.bigTerminal` and `experimental.bigTerminalWorktreeOnly` move to `terminal.enabled` and `terminal.onlyInWorktrees`.** Loading a settings file copies each old value across unless the `terminal` table already sets that key, then drops both old keys. The next save writes the file without them. Loading and saving also drop a custom command with no id, name or command, a repeated id, and an id a built-in or a known CLI uses. Otherwise a custom `codex` would be listed until Codex is installed, then vanish behind it. With `terminal.enabled` off, `chats.create` refuses a terminal tab. KERNEL-248.
