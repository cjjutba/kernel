**A failed setup can be skipped, and the user can stop setup.** A new chat waiting for setup used to show a skeleton, a "Queued. Sends when setup passes." note, the queue row and a shut composer. When setup failed, Run again was the only way on (D-044), and only archive or quitting could stop setup (D-122). The Setup tab now has Stop while setup runs. `scripts.stop` takes `kind: 'setup'` and ends it the way a quit does: failed, no exit code, the brief still held, and no word to the Lead. The failed card has Send anyway next to Run again (`scripts.skipSetup`, `Setup.skipSetup`). It only works on a failed workspace, is guarded like Run again so a double click sends once, and goes on the way Run again goes on after a pass: the brief goes out, or keeps waiting for the PRs it waits for. The Lead hears it as `setup.passed`. Saying it was skipped would need a new update kind, and a teammate that started without setup reports its own trouble. Each setup script run is kept on the workspace as `setupRun` (start, end, exit code, null when stopped). The chat counts the time from the start, and a pass or skip leaves a note above the brief: "Setup finished in M:SS" or "Setup failed, sent anyway". The note is only written right after a script passed in this run, so a stale `setupRun` never writes one. While a chat is held for setup the composer stays open and what you type queues behind the brief. A teammate's chat that isn't held yet (its brief still with Kernel, D-120) keeps the composer shut, so nothing goes out before setup does. Amends D-044 and D-122. KERNEL-430.
