**The website shows a release only once GitHub has published it.** The site deploys from `main`, so a release file went live when the release PR merged, minutes before the tag, the build and notarization published the release. For 0.2.1 the landing page said "Kernel 0.2.1 is here" for nine minutes while the download was still 0.2.0, and a failed notarization would have left it advertising a version that didn't exist. The changelog, the landing pill and the sitemap now read GitHub's latest release (`/repos/cjjutba/kernel/releases/latest`) and hide any newer file. The pages already regenerated hourly for the star count. The release check refreshes every 5 minutes, so a release appears within about 5 minutes of publishing, without a deploy hook or a secret in the release script. If GitHub can't be read, the build fails and a regeneration keeps the last good page, rather than guessing. Every file is still parsed at build, so a bad one fails the build even while it's hidden. Amends D-058. KERNEL-412.

**The changelog's closing line shows only while there is one release.** "This is where it all starts. Older releases will appear here as Kernel grows." is in the design reference, which draws one release, and stopped being true with the second. It stays for a single release, so the render comparison still matches. KERNEL-412.
