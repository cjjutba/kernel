**What's new reads titles and areas from the notes, carried in the existing release format.** A release's notes reached 132 lines, and the dialog showed them at one weight in one scroll, with Restart to update scrolled out of view. A `new` fragment can now carry a `title` and an `improved` or `fixed` fragment an `area` from a fixed list in `site/lib/schema.ts`. The title becomes the item's lead, which `renderApp` already sent as its own `###` note. An area becomes a `### <area>` heading inside its section in the release file and the GitHub body, and a `### Improved: Chat` note for the app. So `parseNotes`, the saved update and the shared types keep their `{ title, body }` shape, and the renderer rebuilds the sections from the note titles. A copy that installed an earlier version reads the new notes with its own parser as titled lists, which is why the area rides in the note title instead of a new field. Notes without an area come before the area headings in a section, since a heading in the release file runs to the end of the section. Both fields are optional, so a fragment from a branch opened before this still passes.

**The dialog keeps its header and buttons in place and folds long sections.** Only the notes scroll. New features show their title over their sentence. A section with more than seven lines shows one closed row per area, and a long list without areas, from a release before this, shows five lines and Show more. Every state uses the app's own state kinds: LoadingRow before the state arrives, EmptyList when there are no notes, the neutral banner for a failed check or a failed restart (no longer a toast), and the busy button for Restarting and Trying again. Amends D-058.
