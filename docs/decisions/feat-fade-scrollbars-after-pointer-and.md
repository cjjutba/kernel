**The scrollbar thumb fades a second after the last use, even under a pointer that rests on the area.** Amends KERNEL-602, which showed the thumb for as long as the area was hovered. A chat read with the pointer parked on it kept a thumb on its right edge all the time. The thumb now shows through `data-scrolling` alone, and `:hover` no longer has a rule in `tokens.css`. `ui/scrollIdle.ts` sets the attribute when the area is in use: it scrolls (wheel, keys, touch or a dragged thumb), the pointer moves over it, or its native scrollbar is pressed. It clears it a second after the last of those, with the same 150ms in and 300ms out. A pointer move marks the scrollers that hold the element under the pointer, nearest first, so a sibling scroller is never touched. A list is read at most once a frame and reused for a quarter of a second for the same element, and only a scroller that overflows and does not say `scrollbar-width: none` counts. Electron sends a native scrollbar's `pointerdown` and `pointerup` to the scroller itself, and `pointerup` also arrives when the button is released over content, but there is no `pointermove` while the thumb is dragged, only `scroll` events. So a press that lands on the scrollbar holds the mark, which keeps the thumb up through a hold with the pointer still, and its release, a pointer move with no button down, a cancelled pointer or the window losing focus starts the second again. No state is kept in React and no attribute change moves layout, since the gutter width is the same shown or hidden. The reduced motion rules are unchanged: the thumb snaps instead of fading.
