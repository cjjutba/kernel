**A review runs commands that only read without asking, in every mode, on Claude and Codex.** Amends KERNEL-406, where every command Codex asks about goes to the user because accepting it runs outside the sandbox, and KERNEL-447. A review session (`Workspace.reviewOf`) puts `review` on its `Rules`, and `guardVerdict` allows a command when `readsOnly` says every command in it only reads. Never allow, Always ask, network off and protected branches are checked first, so they still hold. Everything that isn't a read follows the mode as before. KERNEL-1074.

**`readsOnly` is a short list read word by word, not a sandbox.** It accepts file readers (`cat`, `head`, `tail`, `ls`, `wc`, `grep`, `rg`, `diff`, `jq` and similar), `find` without `-exec`, `-delete` or `-fprint*`, git reads (`log`, `diff`, `show`, `status`, `blame`, `rev-parse`, `ls-files`, `cat-file`, `merge-base` and similar), `gh pr view|diff|checks|list|status`, `gh issue view|list`, `gh run view|list`, and the repo's tests: a package script named `test` or `test:*`, `pnpm exec vitest`, `pytest`, `cargo test`, `go test`. A command with a redirection, heredoc, process substitution, expansion, a wrapper such as `sudo` or `bash -c`, or an option that writes or runs another program (`--output`, `--pre`, `--ext-diff`, `git -c`, `--web`) falls through to the mode, and so does a program named by a path, since the PR may have put it in the worktree. `sort` and `tree` with an output option, `uniq` with an output file and `file -C` write, so they ask too. A test run can write files the repo's tests write, which stays inside the review's own worktree. The review keeps no way to edit a file (KERNEL-549).
