**`readsOnly` is a short list read word by word, not a sandbox, and it has no test runners.** It accepts bare command names only: `cat`, `head`, `tail`, `wc`, `ls`, `grep`, `egrep`, `fgrep` and `rg` with no output or preprocessor option, `find` without `-exec`, `-delete` or `-fprint*`, `git log|diff|show|status|blame` with no `-c`, no pager and no external diff, and `gh pr view|diff|checks|list|status`, `gh issue view|list` and `gh run view|list` without `--web`. A path as the command (`./cat`), a wrapper (`sudo`, `bash -c`), a redirection, heredoc, process substitution or expansion falls through to the mode. Test runners are not on it: `pnpm test`, `pnpm exec`, `vitest`, `pytest`, `cargo test`, `go test`, `npx` and `dlx` run code the PR supplies, and package-manager forms take paths and options that pick the program, so each patch of the list left a gap (security review of PR #1146, rounds 1 to 3). `uniq` and `sort` are off too, since they can write a named output file. The maintainer's call: a reviewer reads CI with `gh pr checks`, and a test run asks as any command does. The review's brief says so. A review keeps no way to edit a file (KERNEL-549).
