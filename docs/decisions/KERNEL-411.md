**Only the Merge button that was pressed spins.** A merge shows its spinner and "Merging" on the one button the user pressed, whether in a Team update row, the PRs tab or the PR header. Every other place showing the same PR reads Merging as muted text with nothing to press, and so does every place for a merge Rowan or Merge all started. With the old rule several buttons spun for one merge, and two merges close together made every Merge button spin, so the user couldn't tell which one they had pressed. Amends KERNEL-347's "the same dimmed, spinning label" for a merge either a button or the engine started. KERNEL-411

**Merge all stops at the first pull request that can't merge.** It merges the ready PRs one at a time, in the order the PRs tab shows them, because each merge moves the base the next one merges into. When one can't merge, often a conflict the previous merge caused, it stops and says where and why, and nothing after it merges. Rowan's merge_workspace still skips and carries on, since the user named each PR it merges. KERNEL-411

**A merge waits out GitHub's conflict check.** Right after a merge GitHub reads every other PR into the same base as mergeable UNKNOWN for a few seconds. A merge started then re-reads the PR every 2 seconds for up to 30 seconds, instead of refusing it as not ready, so Merge all's next PR and a second click go through. Past the wait it says GitHub is still checking. KERNEL-411
