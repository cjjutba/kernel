**With plan mode off, the Lead asks only when the user asked for work.** The KERNEL-678 rule had the Lead end every proposal on one yes-or-no question, and the Lead read every reply as a proposal. So "is this a bug?" came back as an answer plus "Should I file this?", when the user only wanted the answer. Now a question, opinion or report gets an answer and nothing after it: no closing offer, no closing question, and no "I'll" or "next" about work the Lead isn't doing. A message that asks something and also asks for work counts as a request for work. "Okay" after a plain answer starts nothing. A finding outside what was asked gets one plain sentence, and a serious one goes first. The wording says "tracker issue" and names no tracker, so a project with no tracker gets no offer to file either. Narrows KERNEL-678.

**The go-ahead check stays.** A request for work still ends on one yes-or-no question, and `create_workspace` still needs `go_ahead` quoted from the user's latest message. "Filing tracker issues needs the same go-ahead" stays word for word. A teammate's blocking question still reaches the user through `ask_user`.

**One line, both modes.** The answering rule is one line in `LEAD_RULE` and `LEAD_BUILD_RULE`, so Hand off and Build here say the same thing. Build here also says a question is not a request to build, since "build what the user asked" read a question as a request. `LEAD_RULE` grew by that line, 332 characters, and its length test moved with it. "Propose new findings, don't start them" went, because the new line covers findings.
