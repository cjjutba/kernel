**A local merge reuses the PR header's band instead of getting its own panel.** A repo with no GitHub remote has no PR, but the user still decides when a branch lands and needs to know whether it can merge, what is in the way and whether it worked. So the workspace panel keeps the band, its tones and its buttons, and `design/redesign/PrLocal*.png` draw the six states (ready, behind, conflicts, merging, merged, refused). The `#N | ↗` link pill becomes a plain `→ main` pill, because there is no number and nothing to open. A merge line under the band says "N ahead of main · N behind" and the room's merge method. The diff stat stays in the Changes tab, which already counts the same files. KERNEL-441.

**Behind main is a grey state with its own button, not a red one.** Nothing failed when main moved on, and the fix is one step, so it takes the neutral band with a soft Update branch, the way Draft takes a soft Ready for review. Merge conflicts keep the PR's word, tone and button (Resolve conflicts), and add a note that lists the conflicting files. A branch that is behind is not offered Merge, so the user never merges onto a base the branch has not seen. Git can merge cleanly onto a moved base, so the engine may allow it. If it does, Merge replaces Update branch in this state and the note stays as information. KERNEL-441.

**A merge Kernel refuses because the base checkout has uncommitted changes reads "Can't merge" on the red band, and the panel carries the whole explanation.** The note says what is wrong ("Your main checkout has uncommitted changes"), that nothing was merged, and the fix ("Commit or stash these files there, then try again"), and lists the dirty files with their status letters. The band's button is a soft Try again, not Merge, so a second press after the user cleans the folder is an obvious retry. Kernel never stashes or commits for the user. KERNEL-441.

**Room setup shows the code host as a check row after the first step.** "Code host" sits after Clone or Use your folder and before the worktree folder, because Kernel reads the remote from the checkout. GitHub reads "GitHub, owner/repo". Local reads "Local, no GitHub remote. Kernel merges branches on this Mac.", the one sentence that tells the user why there will be no pull requests. `RoomSetupGitHub` and `RoomSetupLocal` draw it, and `RoomSetup` and `RoomSetupTeam` are not redrawn. KERNEL-441.
