**Kernel keeps a plain-text setup log for each project, in its database, and shows it in a dialog.** Project setup had Details and a toast for each failure, but nowhere to read what a step printed. The log is one text value under the meta key `setupLog:<projectId>`: a stamped line when a step starts, what `gh` printed for the clone and the GitHub repo, a line when it finishes (or fails or is skipped, with its error), and a line when Try again or a push recheck runs it again. It is kept in the database, as `projectSetups` is, so no new folder or file format is needed, and it goes when the project is removed.

**It is bounded.** At most 100,000 characters, with the oldest lines dropped first from the start of a line. One tool's output keeps its last 4,000 characters, since that is where a failure is. Output that never reaches a step (the setup script of a chat's worktree) is not in it: that has its own log in the workspace's Setup tab.

**It opens in the one modal shell.** Open the setup log in the Details popover opens a "Setup log for <project>" dialog with the text in a code box, opened on its end, and a copy button. The Pen file has the link and no frame for what it opens, and a dialog needs no new surface or window. A project set up before Kernel kept a log shows an empty state that says so. KERNEL-1117.
