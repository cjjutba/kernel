**Every PR body Kernel's agents write has three headings: What changed, How it was checked, What could go wrong.** Many Kernel users don't read code, so quality has to be shown in plain words, not assumed. "What changed" is 2 to 5 sentences about behavior. "How it was checked" lists the exact commands and their results, with a screenshot or the preview (shared with `share_file`) for anything visible. "What could go wrong" lists risks and anything not checked. The text is `PR_BODY_SHAPE` in `@shared/prTexts`, used by Kernel's Create PR text (with or without a repo template, where the repo's own template still comes first), and the teammate and Lead rules say the same in a shorter line.

**A skipped check is written "not checked", and a check that was not run is never claimed to have passed.** A teammate's final message to the Lead, and the Lead's report to the user, end with one plain line: what was done and how it was verified. These are one instruction line each in `TEAMMATE_RULE` and `LEAD_RULE`, about 70 words together. The Lead rule stays under its 700 word cap, so two older lines were shortened (a "use a comma, or split the sentence" clause and a "failed checks" phrase) and nothing else was cut.

**No new evidence screen.** `evidence.pr` already weighs a PR's acceptance criteria against checks, review verdicts, files and shared images, shows them in the PR panel and posts them as one comment on the PR. That is evidence for the plan's criteria, not for the PR body, so it was left as it is. A later change could show the body's "How it was checked" section in the panel.

**Kernel does not generate PR bodies with a model.** The agent writes the body, following Create PR's text, so the rule is a prompt instruction and a test that the text carries it, not a check on the body itself. A body that ignores it is not rejected.
