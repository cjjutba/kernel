**A turn's changed files leave out what only arrived from the workspace's base.** Each checkpoint records its base as a `Kernel-Base: <sha>` trailer next to `Kernel-Stat:`: the merge-base of HEAD with the workspace's remote base. When the base moved forward between the previous checkpoint and this one, a path that held the old base's content at the previous checkpoint and holds the new base's content now came from the remote, and drops out. That covers Kernel's Lead sync, the fast-forward when a wait is released, and an agent that pulls, rebases or merges. Every other path stays: the agent's edits and its unpushed commits differ from the new base. A path the base changed too is counted against the new base, so its lines are the agent's. One that now matches the new base keeps its count against the previous checkpoint. `Kernel-Stat` counts the same list, so the Checkpoints list matches the files under the reply. No database change, and turns saved before keep their lists. Amends KERNEL-584. KERNEL-603.

**The base is a remote-tracking ref, never a local branch.** The workspace's `baseRef` counts when it resolves under `refs/remotes/`. Otherwise Kernel takes the upstream of the local branch it names. A current-branch chat whose base is the local `main` it commits to would otherwise move its base with each of its own commits and lose them from the list. A repo with no remote, a local base with no upstream, or a base ref that's gone records no base, and turns list every change, as before. KERNEL-603.

**Only a base that moved forward filters.** If the old base isn't an ancestor of the new one, as after `git reset` back or a force-pushed main, nothing arrived from it, and the turn lists every change. KERNEL-603.

**A checkpoint saved before this has no base, and Kernel works one out from its history.** The checkpoint commits chain back to HEAD as it was at the first checkpoint, so their merge-base with the remote base is the base the chain started from. That can be older than the real one, so the first turn after the update may still list a file main changed twice. It never drops one of the agent's. KERNEL-603.

**Known limit: a commit pushed to the base branch in the turn that made it doesn't show.** By the end of that turn the commit is on the remote, and its files match the new base. Teammates push to their own branches, so this only hits a chat that pushes straight to main. KERNEL-603.
