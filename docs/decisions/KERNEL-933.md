**Kernel reads an issue from the tracker its key or tag names, and the project's tracker stays the default for everything else.** Amends KERNEL-462, which read every issue from the project's tracker and gave a `#41` in a Linear project its title only. `trackerOf` in `features/integrations.ts` picks the tracker from the source's `tracker` tag, else from the key: `#41` is GitHub, a bare `41` is GitHub in a GitHub project, and any other key is Linear. When that is the project's own tracker, it reads as before. Otherwise Linear needs a token and GitHub a github.com remote, and without one Kernel keeps the task title, as it does when a tracker doesn't answer. `create_workspace`'s brief, the branch type from labels, the assignee check before a start and `get_issue` all read this way. A project set to `[tracker] kind = "none"` reads no issues at all. A Linear key reads with a token alone, without the project's `[linear] team`, since reading one issue by key needs no team. KERNEL-933.

**Up next, the From popover and the move to In Progress still use the project's tracker.** `issues.tracker` keeps KERNEL-462's `kind` and adds `available`: Linear when a token and the project's `[linear] team` are set, GitHub when the project has a github.com remote, and neither with `[tracker] kind = "none"`. The Issues screen's Linear and GitHub switch reads `available` and changes only the list. `startIssue` moves only an issue from the project's own tracker, so starting a GitHub issue in a Linear project moves nothing. KERNEL-933.

**The same work listed twice under two keys is out of scope.** Linear's GitHub sync can copy a GitHub issue into Linear, and then the Issues screen lists it once under each tracker, as `KERNEL-83` and `#41`. Kernel doesn't match the two. KERNEL-933.
