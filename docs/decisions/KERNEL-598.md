**A shared image's tab takes ⌘+, ⌘- and ⌘0 from the View menu, and the window zooms only when no image tab does.** The View menu binds those keys to zooming the whole window, and the menu gets a key before the page does, which is why ⌘W and ⌘R already go through `before-input-event` in `src/main/index.ts` (KERNEL-539). Main now does the same for the three zoom keys, ⌘= included, and offers each to the page as a cancelable `kernel:zoom` event. The image tab cancels it and zooms the picture. When nothing cancels it, or the page doesn't answer, main zooms the window half a level a step, which is what the menu's roles do, so ⌘+ keeps zooming the window on every other tab. The menu items stay, and clicking them still zooms the window. A modal being open leaves the keys to the window.

**Zoom on an image is local to its tab and goes back to Fit on a new version.** Nothing is saved, so an image opens at Fit as it did before. Switching versions resets it, since another version can be a different size and a zoom held from the last one would show part of it. Fit is a stop of its own that follows the frame when it resizes, so a window resize at Fit stays at Fit. The range is 25% to 400%, or down to Fit where Fit is under 25%, so a tall screenshot can always be seen whole.

**Double-click goes from Fit to 100%, and to 200% where Fit already is 100%.** An image smaller than its frame opens at Fit, which is 100%, so a toggle between the two would do nothing. From any other scale it goes back to Fit.

**The zoom buttons are `aria-disabled` at the ends of their range, not `disabled`.** A disabled button drops out of the tab order, and a keyboard user who zooms in to 400% with the button focused would lose their place. The click does nothing and the button is dimmed. The percent between them is the scale actually drawn, rounded, and goes back to Fit. No PNG draws the control, so it is built from DESIGN.md: a hairline box the height of Comment beside it, with the version chip's mono face for the percent. KERNEL-598.
