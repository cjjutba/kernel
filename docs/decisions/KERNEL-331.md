**The rest of Kernel's features moved out of `kernel.ts`, which now only builds, starts and stops them.** KERNEL-326 moved team and rooms (#261). KERNEL-327 to KERNEL-331 then shipped as one PR instead of five, at CJ's request, and `kernel.ts` went from 2,403 lines to 324. Fourteen features joined the nine already out: setup, trust, env, workspaces, archive, history, waits, chats, lead, tools, sharing, prs, autoArchive and reviews. Two weren't in the KERNEL-324 plan. `history` holds Delete in History (KERNEL-333), which landed after the plan. `autoArchive` holds what Kernel archives on its own: reviews of finished work (KERNEL-131) and work whose PR merged (KERNEL-114). `reviews` keeps where a review starts, the rule it gets and the verdict it sends. `handlers()` joins every feature's map with `channels`, typed `Handlers` with no cast. A channel no feature answers fails typecheck, and one that two features answer throws. KERNEL-331.

**A member another file needs is public where it lives, and nothing reaches a private member with `k['name']`.** Bracket access was the stopgap that let features move one part at a time (KERNEL-324). With every feature moved, a member another feature calls is public on the feature that owns it. Kernel's own `home`, `stopped` and `nudges` are public, since every feature reads them through `Feature`. That undoes #257, the follow-up to KERNEL-325 that made `home`, `stopped` and `roomRemotes` private again and read them with brackets. `test/featureBoundaries.test.ts` fails on `k['` anywhere in `src/main/features/`. Tests still reach a feature's private member with brackets, as `k.chats['sendNow']`. KERNEL-331.

**Kernel forwards only what tests and the app shell call, and gets no new forwarding methods.** Kernel keeps one-line methods such as `addRoom`, `createWorkspace` and `mergePr` that call the feature, because about forty test files and `src/main/index.ts` call them. Each is plain and not async, so no test's timing shifts. `refreshPr` and `archiveWorkspace` stay test seams. Every caller goes through `this.k.refreshPr` and `this.k.archiveWorkspace`, the feature that owns them included, so a test that replaces one on the instance reaches them all. New code and new tests call the feature itself. KERNEL-331.

**`kernel.ts` has a size limit.** A test fails when it passes 450 lines, and its message says where new code goes. KERNEL-331.
