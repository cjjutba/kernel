**A check the repo doesn't require holds a PR while it runs, though its failure still doesn't.** Amends KERNEL-388. #656 merged at 01:55 while Test, which branch protection didn't require, ran until 01:57. Kernel had dropped the optional checks before looking at them, so the PR read ready. Now any check running or queued makes the PR read `checks`, and Merge PR refuses with the check's name ("Test is still running."). Merge anyway goes past optional checks still running, never past a required one. A failing optional check leaves the PR ready, as KERNEL-388 decided. A check that runs blocks because nobody knows its result yet. A check that failed has a known result, and the repo said it doesn't decide the merge. Auto-merge refuses while any check runs, and the checks from the last read are part of what it weighs a PR on, so a run that finishes gets the PR weighed again. KERNEL-703
