**A roster picks a room's teammates, never its Lead or reviewer.** A repo can carry dozens of agent files, often a collection of Claude Code subagents copied from elsewhere, and with all of them on the team every plan and every `list_agents` gets crowded. `roster` in `[team]` lists the agents on the room's team. `resolveTeam` works out the Lead and the reviewer from every file first and then drops the files the roster leaves out, so a roster never changes who leads or reviews. Unset or empty, every file is on the team. An id that names nobody is left out without a warning. Retiring an agent leaves its id on the roster, and restoring it puts the agent back. A hire, an added starter agent and a restored agent join the roster when the room has one, or they would land off the team. `agents.setTeam` keeps only ids that have a file, and refuses a roster that drops an agent with open work, because that work would have no agent to run. Room setup asks for a roster when a room has more than 12 agents and `[team]` has none. Personal and plugin agents count, since they join every room (KERNEL-463), so a user with many of them is asked even in a repo that brought none. The agents step carries `roster` with the count, `needed`, and Kernel's suggestion, which is the agents that take tasks. 12 is the plan's "about a dozen". KERNEL-465.

**An agent written as a subagent, with no pull request workflow, starts as a helper.** Subagent files mostly have no tools line, and KERNEL-397 counted a file with no tools line as able to open a pull request, so every one of them took tasks. Now a file that names neither Edit nor Write, and whose description and prompt never mention a branch, a pull request (PR, merge request) or a worktree, starts as a helper with a `looks-like-subagent` warning. A file whose tools can't open a pull request keeps `cant-open-pr` instead. `[team] members` and `helpers` still decide, and `setTeam` writes `members` for such an agent only when the user makes it a teammate. The rule also catches a hand-written teammate with a one-line prompt ("You are Kai."), which took tasks before. Kernel's starter agents mention a PR and New agent drafts mention a worktree, so they stay teammates. A file `hire_agent` writes with no tools line stays a teammate only if its prompt mentions a PR, until KERNEL-476 gives hires Edit and Write. Amends KERNEL-397. KERNEL-465.
