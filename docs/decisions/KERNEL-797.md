**A revert keeps what arrived from the base since the checkpoint.** When the base moved forward between the checkpoint and now, because the agent rebased onto main, merged it or pulled it, revert writes the checkpoint's own changes on top of the current base instead of the checkpoint's whole tree. A file the base changed and the checkpoint didn't keeps the base's content. A file both changed keeps the checkpoint's content, as before, and the preview lists it in `conflicts`. A base that didn't move, moved back or sideways, or can't be read, and a checkpoint with no `Kernel-Base`, still get the whole tree. The tree comes from a per-path rule over `diff-tree` and `update-index`, not `git merge-tree --merge-base`, which needs git 2.40 while Apple's git on a Mac without Homebrew is 2.39. KERNEL-797

**The revert preview counts only the commits that aren't on the remote base.** Amends KERNEL-764. Commits that came in from main with a rebase or merge are teammates' merged work, and a revert no longer touches their files, so `commitsAhead` leaves them out and `pushed` reads the same set. A merge commit the agent made counts, since it is on the branch and not on main. KERNEL-797
