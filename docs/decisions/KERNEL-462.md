**Each room works out its own issue tracker: Linear, GitHub Issues or none.** Amends D-140, which read Linear for every room once a token was set. The room's `[tracker] kind` always wins. Without it, a Linear token (Settings, Integrations, else `LINEAR_API_KEY`) plus the room's `[linear] team` means Linear. Otherwise a github.com remote means GitHub Issues, read from the room's `owner/repo`, else from the room's remote as git has it now. Otherwise the room has no tracker. So a room on GitHub with a Linear token but no team now lists its GitHub issues. `trackerFor` in `features/integrations.ts` builds the tracker on every call, so a new token, team, remote or `[tracker] kind` applies at once. `issues.list` reads the room it is given. `[tracker] kind = "jira"` reads as no tracker until KERNEL-474 builds Jira. KERNEL-462.

**GitHub issues go through gh, and starting work on one changes nothing on GitHub.** The tracker runs `gh issue list --state open --limit 50 --json number,title,url` and `gh issue view <n> --json number,title,url,body,labels,comments` in the room's folder, so gh picks the repo the way it does for PRs (D-006). A GitHub issue's key is `#41`, and `41` reads as `#41`. GitHub has no started state, so `start` moves nothing. Kernel doesn't assign or label the issue instead. Those would be writes the user never asked for, and D-140 only ever changed a state. Kernel reads no blockers from GitHub, so KERNEL-263's waits stay Linear only. A gh call that fails rejects with the first line gh printed, and the From popover shows it. KERNEL-462.

**A room with no tracker lists no issues, and a workspace's issue records the tracker it came from.** The none tracker lists nothing, can't read an issue and moves nothing. `create_workspace` then falls back to the task title, as it does when Linear doesn't answer. Rowan's `issue` and an issue picked in New workspace save `WorkspaceSource.tracker`: `linear` or `github`, and nothing in a room with no tracker. A `#41` key is a GitHub issue in any room, and only a GitHub room's tracker reads it. In a GitHub room a key that isn't a number stays untagged. KERNEL-470 uses the tag to tell `#41` issues from PR numbers in waits and to stop the `#` checks in `features/workspaces.ts`. A source saved before has no tag, and its id still tells. KERNEL-462.
