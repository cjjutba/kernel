**A branch on the remote takes its base by a merge, never a rebase.** The guard hook denies every agent force push (D-023), and a rebased branch that is already on the remote can only be pushed with one. So every message Kernel sends about a base that moved picks its wording from whether the branch is pushed: a branch that has never been pushed rebases onto the base, and one on the remote merges `<remote>/<base>` in and pushes as usual. Kernel reads "pushed" from the branch's remote-tracking ref, which a push sets, with no network call. A ref git can't read counts as pushed, since a merge is never wrong and a rebase of a pushed branch is. Update branch always asks for a merge. The wait kept for a missing rebase (KERNEL-691) checks that the branch contains the base by ancestry, so a merge ends it the same way a rebase does. KERNEL-886.
