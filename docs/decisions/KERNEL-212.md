**The renderer ships minified, with Settings, Floor and Board as lazy chunks, and its stylesheets stay eager.** `electron.vite.config.ts` turns on `build.minify`, and `App.tsx` loads Settings, the hidden Floor and the hidden Board (D-104) through `React.lazy` behind one `Suspense` that falls back to the boot `Loading` shell. The main chunk went from 1,793,103 bytes on `main` (23190eb) to 888,475 bytes, 49.5%. The issue's criterion, at most half of the 1,765,593 bytes measured when it was filed, is measured against `main` at merge time instead, because `main` grew with new features since then. Settings is fetched once the app is idle after boot, and `lazyScreen` in `App.tsx` renders a warmed screen without suspending (a lazy component suspends on its first render even with its chunk in memory, and route changes here are synchronous), so ⌘, and Room settings open without the fallback. Before the idle fetch lands they open through the fallback. The CSS is not split. `floor.css` and `settings.css` hold rules other screens lean on (`.agent-dot` in the Workspace composer, the compact `.nav-item` in the sidebar), and `.log-all` has to sit before `tokens.css`'s `.btn` to lose the tie, so `App.tsx` imports each lazy screen's stylesheets in the slot its own imports used to fill, and the built CSS is byte-identical to the unsplit build. A new stylesheet under `screens/floor`, `screens/board` or `screens/settings` has to be imported there too. Moving those shared rules into eager files would let the CSS split as well. The two floor SVGs are inlined as `data:` URIs into the Floor chunk, so the build no longer emits them as files nothing fetches. Fonts stay files, as D-054 says, so `assetsInlineLimit` is now a function that says yes to those two SVGs and no to everything else, instead of `0`. The CSP also gains `object-src 'none'; base-uri 'none'; form-action 'none'`, which nothing in the renderer uses (its three forms call `preventDefault`). Amends D-054. KERNEL-212.
