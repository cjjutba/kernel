**A review waiting for usage to drop doesn't hold back another kind's blockers.** Amends KERNEL-552. A held kind can wait for hours, so blockers on the head now wait only for kinds whose review sets up or works, or for Kernel starting a round. The To do line that passes the blockers on names the held kinds and says their findings come later. `reviewState` still counts a held kind in `inProgress`, so auto-merge and the ready to merge line treat a held required review as not done. `stillBlocked` is likewise read once nothing runs, held kinds aside, since Kernel starts no round past the cap whatever they find. KERNEL-633.

**The `[review] rounds` that stops a round is saved on the round, so Rowan and Kernel use one value.** Amends KERNEL-552. `nextRound` checks the cap with the base branch's `rounds` at the push, while `stillBlocked` read the value saved when the round started. When the cap stops the next round, `onReady` now saves that `rounds` on the latest round, and the update says what Kernel did. Raising `rounds` still lets the next push start a round, since the cap is read again then. KERNEL-633.

**Archiving a review workspace before every kind reported, then re-running CI on the same head, re-runs the kinds that have no verdict.** Amends KERNEL-552's one round per head. With no open review workspace for the PR, a ready on the round's head starts a new review workspace for the round's kinds that have no verdict on the head, skipped kinds aside. It is the same round: `n` stays, so it doesn't count toward `rounds`. With a review workspace open, or every kind reported, a ready on the same head still starts nothing. KERNEL-633.
