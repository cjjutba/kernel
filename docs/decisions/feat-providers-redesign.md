**Meters take color as they fill: grey, amber from 75%, red from 90%.** Amends D-026, which turned a meter white from 85%. `Meter` now sets `data-level` from `meterLevel`, the same steps as the context ring (CONTEXT_NEAR, CONTEXT_WARN), so a bar in the Usage popover, on Account and usage and on Providers reads like the ring. White at 85% looked the same as a bar at 40%, and the limit is the one fact on these surfaces that someone acts on. The percent next to a bar stays grey, since it already says the number and amber text that is readable on white turns brown.

**Amber and red have fill tokens, apart from their text tokens.** `--needs-fill` and `--del-fill` color meter bars, the context ring and the warning icons below. In dark they equal `--needs` and `--del`. In light, `--needs` is `#7a4f00`, chosen to pass 4.5:1 as text, and it reads brown on a 6px bar, so the fill is `#d97706` (3.2:1 on white, 2.9:1 on the card surface) and red's is `#dc3e42` (4.4:1). The bar's length and the percent beside it carry the value, so the color is a second signal and doesn't need the 3:1 a lone graphic would.

**Settings warning lines have an amber icon.** Amends no-amber-icons for Settings only: the MCP sign-in line, Waiting for Keychain access and the MCP servers page's warnings (`.set-warn`) take `--needs-fill`, and the limit banner and a CLI problem on Providers take a red triangle. A warning there asks for an action on that page, and the color says which line it is. Sidebar rows, chat tabs and the other triangles in the app stay ink, as no-amber-icons decided.

**Providers lists subscriptions and API keys as two sections.** A key has no usage windows, Kernel never switches to one on its own, and adding one is its own form, so it reads as a different kind of account. Each section has its own Add button: Add key opens Add account on API key. The toggle is now "At a limit, switch to another subscription", and it turns off with "Add another subscription to use this." while fewer than two signed-in subscriptions can take agents.

**An account row shows one action and a menu, and the account in use wears a green Active pill.** The old rows carried up to four borderless buttons each. Switch to (or Sign in, Sign in again, Replace key) stays visible; Rename, Sign in again, Sign out and Remove go in the `more` menu, and Remove asks first. The pill uses the sidebar status pills' tint (D-084). There is no Status section: login method, plan and email repeated the row in use, and Run login is Sign in again in that row's menu. Version, the copy agents run on and the config file sit under CLI, where Executable is one select (Bundled with Kernel, System, from your PATH, Custom folder…) in place of two buttons.

**Settings pages are 800px wide, and the search field is quiet.** `.set-page` grows from 748px to 848px with its padding, so rows have room for meters and actions without wrapping. The Settings search drops `--input-line` for the panel's hairline, brightening on hover and focus with no ring, since its icon and placeholder say what it is and the bright border made it the loudest thing in the nav. Other inputs keep `--input-line` (KERNEL-575).

**Providers' tabs are underlined.** Pill tabs looked like the Personality control below them, so the biggest switch on the page read like a setting. `Tabs` takes `variant="underline"`: text tabs on a hairline across the content, the selected one in ink with a 2px bar under it. Other tab rows keep pills.
