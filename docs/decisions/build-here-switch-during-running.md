**A mode switch during a running reply shows its divider after that reply ends.** A reply finishes in the mode it started in (KERNEL-770), so a divider placed at once would sit above work that still ran in the old mode. A tab with a reply running keeps the mode that reply started in, and when the reply ends it gets one divider for the chat's mode then, or none if that is the mode it started in. Tabs with nothing running get theirs at once, and a divider that is already a tab's last item updates in place (KERNEL-809). The toggle under the input still flips as soon as it is clicked.

**Hand off's refusal reads the chat's mode at the call.** The tool policy is fixed when the session starts, so a Hand off reply keeps refusing edits after the user switches to Build here. The refusal used to suggest switching to Build here, which the user had just done, and Kernel made up another cause. Now it says the switch applies from the user's next message and asks Kernel to tell the user to send the request again. Codex declines the file change the same way and shows the same text as a note in the chat, since Codex's decline carries no reason to the model.
