**A project keeps one spare worktree, made when New chat opens, and the first Send claims it.** Amends KERNEL-542 and KERNEL-653. `git worktree add` took about half a second of every new chat's first message. Opening New chat now makes a hidden worktree in the background (`kernel-spare/<id>` in `.spare-<id>` under the project's worktree folder), and Send renames its branch to the name the chat gets and moves the folder to match, inside the project's branch lock, so the names and the free-branch check stay as they were. A spare has no workspace record, so nothing that lists workspaces shows it. A missing spare, one still being made, one cut from another base than the one picked, or a claim that fails falls back to making the worktree as before, without telling the user. The KERNEL-653 check that main didn't move now runs alongside the claim, and if main moved the spare is fetched and fast-forwarded before the message is released. After a claim the next spare is made in the background. Spares are removed when the project is removed, when Kernel quits, and at launch (a crash leaves them behind). KERNEL-1014.
