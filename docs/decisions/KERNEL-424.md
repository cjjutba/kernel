**A chat with Rowan names its branch and its worktree folder once, from the chat's first title.** KERNEL-405 renamed the branch on every title the chat got, cut to 35 characters, and never moved the folder. The folder and the terminal prompt kept the first words of the first message, the branch changed name under the chat, and the breadcrumb kept the first words too. Now a new chat's workspace starts with `naming: 'branch'`. The first name its first tab gets, from Claude Code or from Kernel, names the branch from the Lead branch pattern with every word of the title as the slug, cut to 60 characters at a word (`leadBranch`), with the free-name suffix when that name is taken. The user naming the chat before that doesn't stop it. The workspace's `name` follows, and `naming` becomes `folder`. A branch that was pushed or has a PR keeps its name and its folder, as before, and `naming` goes.

The folder then moves with `git worktree move` to the branch's folder name under the room's worktree root (`worktreeFolder`, with `freeWorktreePath`'s suffix when it is taken), under the room's branch lock. It moves only when the workspace is ready and nothing runs in its folder: no turn, background task, queued or held message, setup, run script, or terminal running a command (node-pty's foreground process isn't the shell). It also waits for the checkpoint the last turn started. Kernel tries right after the branch is named and after each of the chat's turns, through `syncLead`'s queue, so the move and the fast-forward never run git at once. The chat's tabs are held for the move, so a message sent meanwhile goes out from the new folder. Idle processes end (`restartIdle`), and the next message resumes each session by its id there.

Claude Code finds a session by its id from any folder, and keeps appending to the transcript in the old folder's project. The SDK's `forkSession` and `getSessionInfo` with `dir` look only in that folder's own project, so Fork into new chat and the title read retry without `dir`, as History already did. Codex resumes its thread by id and takes the new `cwd` on `thread/resume`. Open terminals start again in the new folder, at their size. A move git refuses, as for a locked worktree or one with submodules, leaves the folder where it is, and Kernel doesn't try again. A move a quit left pending happens after the chat's next turn, not at launch, since holding tabs before `Sessions.restore` would overwrite the queues saved at the quit.

Every later name, Kernel's or the user's, names the chat and `Workspace.title`, which the breadcrumb reads, and nothing else. Chats from before have no `naming` and keep their branch and folder.

Amends KERNEL-405 (the branch follows the chat's name until it is pushed). KERNEL-424.
