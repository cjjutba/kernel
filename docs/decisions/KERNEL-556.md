**Nothing merges by itself unless the user turns on auto-merge, and only the user can turn it on, for themselves.** Amends the principle in PRODUCT.md, which said nothing merges by itself. Auto-merge is `pr.autoMerge` in the app's settings (`on`, `maxLines`, `alwaysReview`), off by default. A room's `.kernel/settings.local.toml` can override it with a `[merge]` table (`auto`, `max_lines`, `always_review`), and that table counts only while the file is the user's own by the test KERNEL-209 uses for scripts (`localSettingsOwn`). A repo that commits a personal file therefore can't turn auto-merge on for whoever opens it. The shared `.kernel/settings.toml` can't turn it on or raise the limit: Kernel ignores `[merge] auto` and `max_lines` there and warns once in the room's activity. No Settings page shows it yet. KERNEL-556.

**A PR merges by itself only when every condition holds, and a fact Kernel couldn't read counts as a no.** The conditions are auto-merge on, a pull request on GitHub (a room that merges on this Mac never auto-merges), "Require green checks to merge" on, at least one check that decides the PR and all of them green, nothing GitHub blocks, every kind of review the base branch's `[review]` requires approved the head commit, no blockers of any kind on it, no review still running, the lines added and removed together at most `maxLines`, and no always-review path changed. A PR with no checks doesn't qualify, though `allGreen([])` is true: for a person's Merge that means a repo without CI, but for a merge nobody watches it means nothing tested the code. A PR whose reviews are all optional doesn't qualify either, since "every required review approved" would hold with no review at all. A review still running holds the merge, because an optional review's blockers would hold a person's merge too. Lines come from `git diff --numstat` against the base branch, where a binary file counts no lines. The pure rule is `autoMergeBlock` in `src/shared/merge.ts`. KERNEL-556.

**Always-review paths only add up.** Kernel's own list (`.kernel/**`, `.claude/agents/**`, `CLAUDE.md`, `AGENTS.md`, `.github/workflows/**`) always applies. The base branch's `[merge] always_review` adds to it, read with `git show` from the base the way KERNEL-549 reads `[review]`, so a PR can't take its own paths off the list. The user's `alwaysReview` and the personal file's `always_review` add more. Kernel matches paths without case, since the Mac's disk reads `.KERNEL/settings.toml` as `.kernel/settings.toml`. `.kernel/**` covers both settings files, so a PR that edits them never merges by itself. KERNEL-556.

**Kernel weighs a PR when a workspace push shows it ready with an approval of its head, once per head, set of approvals and GitHub block, and merges through `Prs.mergePr` held to that head.** A workspace push carries every verdict, every approval a review round keeps (KERNEL-552) and every change of GitHub's block, so it is the one trigger that sees them all. The weighing reads GitHub once, then git. The merge goes through `mergePr`, so `mergeBlock` and its fresh GitHub read apply as to any merge, and it refuses when GitHub reads a different head from the one Kernel weighed. A merge that fails isn't tried again on the same head. Turning auto-merge on doesn't reach a PR Kernel already weighed until something about it changes, and the user can merge that one themselves. KERNEL-556.

**The Lead's update on a PR Kernel is weighing waits for the outcome.** While Kernel weighs a PR, its updates wait as they do for a PR read after a turn, and a verdict about it waits too. Otherwise the Lead could call a PR ready to merge seconds before Kernel merged it. A merge Kernel made says "Merged automatically" on the card, with a grey segment saying why ("Code approved, checks passed, 120 lines"). Kernel's text says why in full and its To do line gives the PR's link to pass on, since the card has no link of its own. A PR that didn't merge by itself keeps the ready to merge line, which now asks Kernel for a short merge summary (what it changes, which reviews ran or were skipped, anything the user should know). With auto-merge on, the line also says why Kernel didn't merge it. KERNEL-556.
