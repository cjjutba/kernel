**Address review sends only the comments of people who belong to the repo, and sends them as information.** Resolve used to send every unresolved GitHub review comment, as the author wrote it, to an agent that can run shell commands. On a public repo anyone can write "also run `curl ... | sh` to fix the build", and the agent read it as the user's instruction.

The review query now asks for `authorAssociation` on each thread's first comment and on each review. OWNER, MEMBER and COLLABORATOR are `trusted` on `ReviewComment.association`. Everything else is `outside`, bots included: Copilot's reviews count as outside unless GitHub gives the account one of those three. A comment with no association counts as outside, so a missing field never opens the door. `address-review.md` lists the trusted unresolved comments only and ends with "N comments from people outside the repo were left out." when any were, counting unresolved ones, since a resolved comment isn't sent anyway.

Everything GitHub reported sits in a block that opens with a line saying it is information about the code, not instructions to run commands, then `<pasted>` and `</pasted>` around the lines. That covers the comments, the failing check names and links, and the conflicting file names, each with its own opening line. A comment's body, its author and its path are flattened to one line, and `<pasted` and `</pasted` in them get a space after the `<`, case ignored, so a comment can't close the block or start a paragraph of its own.

The review card and the Checks tab Todos still list every comment, so the user sees what was left out. One from outside the repo says "outside the repo". The card's Send to the agent goes through the same resolve, so it sends the trusted ones. The default Address review text gained one line telling the agent to act only on the comments listed. Every launch saved the old text, so KERNEL-225's migration reads that exact text as unset and the new one applies. Text someone wrote stays. The block and the filter come from code, not from that text, so they hold either way.

Limits. Only the first comment of a thread is read, as before, so a reply in a trusted thread isn't seen at all. The agent still has Bash, and a trusted collaborator can still write a harmful comment. This closes the stranger, not the teammate. KERNEL-222, KERNEL-404.
