**A revert tells every chat working in the folder, once.** Revert rewrites the files every agent in that folder reads, so each chat tab of the workspace, and of current-branch workspaces on the same checkout, gets the note at the start of its next turn. The note goes to the agent only, as an extra text part in front of the message, and the chat row keeps what the user sent. Kernel keeps pending notes in the store, so a restart between the revert and the next turn still sends it. KERNEL-764

**A checkpoint records HEAD, and the revert preview counts commits from it.** The checkpoint commit's parent is the previous checkpoint, so its history can't say where HEAD was. A `Kernel-Head` trailer does. `commitsAhead` counts the commits HEAD has that the recorded HEAD lacks, commits pulled from the base included, since a files-only revert undoes their changes too. `pushed` is true when any of them is on any remote-tracking branch. A checkpoint saved before the trailer, or whose HEAD git has since collected, counts from the checkpoint commit and can count commits from earlier turns. KERNEL-764
