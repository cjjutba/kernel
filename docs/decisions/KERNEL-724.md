**`src/shared/settingsTiming.ts` records when each setting change takes effect, with six timings, not four.** The issue named `now`, `nextTurn`, `newChats` and `newWorkspaces`. Two settings fit none of them. `team.defaultTemplate` only seeds a room when it is added, so it is `newRooms`. `hookPort` and `general.openTo` are read once when Kernel starts, so they are `restart`. A setting read when a chat's process starts counts as `newChats`, even though a running chat also picks it up after a 10 minute idle stop, a restart or an account switch, because the user can't see or time those. App settings are keyed by dotted path, and an entry covers every key under it (`models.roles`). test/settingsTiming.test.ts derives the app keys from `DEFAULT_SETTINGS`. Room settings have no defaults object, so their map is typed with a path union built from `RoomSettings`, and `pnpm typecheck` fails when a room key has no entry (KERNEL-724).
