**New chat's title names the room and picks it, and the where row has no room picker.** The title reads "What's next for <room>?", with the room's name underlined, dotted until hovered or opened. Clicking it opens the room menu that used to sit in the where row, hanging below the title. Two controls for one choice read as two different things, so the where row keeps only Worktree or Local and the branch. The status line under the old "New chat" title (agents working, waiting on you, PRs ready to merge) is gone: the sidebar and the Inbox already say it. A page whose room is missing or archived reads "What should we build today?", with Pick a room, or Add a room when there are none, and sends nothing until a room is picked. Amends KERNEL-786 and KERNEL-788.

**Hand off or Build here and Worktree or Local stay with the room, through sends. The branch stays until a chat starts.** All three live in the room's New chat draft (`DraftPicks`), so leaving the page keeps them, where before they were the page's own state and reset whenever it unmounted. A send clears model, effort, plan, permission mode and the branch, as KERNEL-544 has it for the first four, so no chat starts from an old branch by accident. Hand off or Build here and Worktree or Local are how the user works in the room, so a send keeps them. Picking the value the default already gives clears the pick, so the room follows Settings again. A picked branch the repo no longer lists goes back to the default. A room that is archived or removed loses its New chat draft. Amends KERNEL-544 and KERNEL-770.

**A choice the user makes stays until they change it, and screens keep one through `remember.ts`.** Each screen used to read and write localStorage itself, some without guarding a blocked store and some without respecting fixture mode, and others kept a choice in component state that reset on the next visit. `remember.ts` holds `readSaved`, `writeSaved`, their JSON forms and `useRemembered`, with one set of guards. The Inbox and History tabs, a room's GitHub issue filter, a room's picked run script and a shared page's preview width now go through it, along with the choices already kept (bypass confirm, closed limit banners, panel widths, expanded rooms, the Linear filter, the link picker's tab). `test/remember.test.ts` fails when any other renderer file calls localStorage, except `store.ts` and the draft store, which keep their own. The GitHub filter is kept per room, since labels and milestones are a repo's own.

**Up next lists the room's Linear team only.** `nextIssues` filters by the room's `[linear] team` key and lists nothing for a room with none, which keeps one room from showing another project's issues. Search and issue reads still reach every team the token sees, since linking an issue from another team is deliberate.

**New chat reads the room's branches when it opens.** The branch menu used to read them on every open and show "Loading branches" until they came, so the list flashed in. The page now reads them once as it opens and keeps the list per room, and the menu opens on it and reads again behind it.
