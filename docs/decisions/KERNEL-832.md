**A head Kernel made by updating a PR from its base keeps the reviews of the head it updated.** Reviews belong to a head commit, and an update from the base makes a new one, so without this every update would drop the approvals and start the reviews again. Kernel records the update only after a fetch, when git shows the new head's first parent is the old head, its second is a commit of the base, and its tree is the one git's own merge of the two makes. A merge that conflicted or carries anything else isn't recorded. A verdict on the old head then counts on the new one, approvals and blockers alike, and so do the review round, a review being worked out, and the user's overrule of blockers. A recorded head starts no new automatic review. A teammate's push is never recorded, even one that makes the same commit, so it is reviewed like any new commit. KERNEL-832
