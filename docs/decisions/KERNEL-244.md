**Each workspace gets a block of 10 ports.** `$KERNEL_PORT` is the first port of a block, and the workspace owns `$KERNEL_PORT` to `$KERNEL_PORT + 9` (`PORT_BLOCK`), so a frontend and a backend can each take one. Blocks start at 4300 and step by 10 up to 4800. A candidate is skipped when it overlaps `[p, p + 9]` for any open workspace's port `p`, so a workspace from before blocks keeps its port: one on 4312 holds 4310 and 4320. All 10 ports must be free to bind. Create, restore and the Lead workspace use the same allocator. Restore keeps the old port unless another workspace took a port in its block. The allocator puts a block in a set held in memory before it awaits the bind checks, and the block leaves the set once the workspace is saved. Two hand-offs in one Lead turn used to read the taken ports, await, and save later, so both could get the same port. KERNEL-244.

**Named run scripts go in a top-level `[run_scripts]` table.** `[scripts] run` stays the default script and is named `run`. Other scripts are `name = "command"` lines in `[run_scripts]`. An older Kernel ignores that table, so a shared file still works for teammates who haven't updated. Names match `/^[a-z0-9][\w-]{0,31}$/i` and are written as typed, without the snake case the other keys get. `run` is reserved: a `run` line in `[run_scripts]` is ignored, and a `runScripts.run` patch writes `[scripts] run`. `RoomSettings.runScripts` lists `run` first, then the table in file order, with names only the personal file has after the shared file's. Each name's source is under `runScripts.<name>`, and `runScripts.run` repeats `scripts.run`. A bad name in a patch is an error. One in a file is skipped. KERNEL-244.

**Run mode decides whether a room's workspaces run at the same time.** `concurrent`, the default, lets every workspace run its scripts at once. With `single` (One at a time), starting a run script stops every run script in the room's other open workspaces. Scripts in the same workspace still run side by side, since a frontend and a backend are one app. Setup and archive scripts are left alone. Starting from the Run tab and the run after setup both go through `startRun`, so both follow the mode. Archive and quit stop every run script. KERNEL-244.

**The branch list narrows to a remote only when one is configured.** Amends KERNEL-190. With no remote set in the room or the app, the From popover and the target branch menu list every remote's branches, as they did before KERNEL-190. A room remote, or an app remote other than `origin`, narrows the list to that remote. The app's `origin` is its default and can't be told apart from a value nobody set, so it doesn't count. Fetch, push and the base ref still use `remoteOf`, which falls back to `origin`. KERNEL-244.
