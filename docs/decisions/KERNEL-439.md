# Draft, to confirm with a live run

Agents can't run KERNEL_LIVE (D-023), so these answers come from reading `sdk.d.ts` in the pinned SDK (0.3.292) and the Claude Code 2.1.292 build it bundles. Nothing here has run against a real session yet. `KERNEL_LIVE=1 pnpm test test/live.agentOption.test.ts` checks each claim. When it passes, drop this heading. When a test fails, the entry it covers is wrong, and D1, D5 and D12 follow what the run shows.

**Kernel keeps enforcing an agent file's tools line on Claude, and doesn't pass the SDK's `agent` and `agents` options.** Claude Code does enforce a main-thread agent's `tools` and `disallowedTools`, but taking that would replace Claude Code's system prompt for every agent, make every definition list Kernel's own tools, and leave D5 nothing to ask about. Two of KERNEL-397's reasons for not using the options no longer hold: `agents` reaches the CLI in the initialize request, so the file doesn't have to be in the worktree, and Kernel builds the definition, so it can leave the model out. The reasons above are new. Codex has no agent option, so Kernel enforces files there whatever this says. KERNEL-439.

**With `Options.agent`, Claude Code makes the tools line the main thread's whole tool pool, and `mcpServers` only adds servers.** `agent` becomes the `--agent` flag. The CLI finds the agent among the `agents` the SDK sent and the agents its settings load, then filters the session's tools through it, the same way it filters a subagent's. A tools line keeps exactly the built-in and MCP tools it names, and `mcp__linear` keeps a whole server. A tool the line leaves out is gone from the model's context, not refused when called. The main thread gets nothing back by default, so ExitPlanMode, AskUserQuestion, ToolSearch, Write for the plan file and Kernel's `mcp__kernel__` tools go too unless the line lists them. `disallowedTools` then removes what it names, including `mcp__server` and `mcp__*`. In `mcpServers`, a server's name adds nothing for the main thread, since the CLI skips name entries there. An inline definition starts that server for the session, unless the folder isn't trusted or policy blocks it. No entry hides a server, so the only way to keep an agent away from Linear is its tools line or `disallowedTools`, as it is without the option. A definition with no `model` leaves `Options.model` in charge. KERNEL-439.

**Kernel's appended rules and its `kernel` server survive the option, but Claude Code's own system prompt doesn't.** With an agent on the main thread, the agent's prompt replaces the `claude_code` preset, and `systemPrompt.append` still follows it, so Kernel's rules reach the model. Every agent would lose the preset, which today carries how to use Claude Code's tools, its git and PR rules and its tone, because Kernel appends the file's body to the preset rather than replacing it. `AgentDefinition` has no field that keeps the preset. The CLI has one, but only its built-in agents set it. That is what `claude --agent` does, so it would match Claude Code, but it changes how every Kernel agent behaves and shouldn't come in as a side effect of enforcement. The `kernel` server stays connected, its tools run, and Kernel's PreToolUse hook and `canUseTool` still see every call, since they belong to the session. Its tools drop out of any tools line that doesn't list `mcp__kernel`, though, so Kernel would add `mcp__kernel` and the session tools to every definition it builds. That is the list `toolPolicy` keeps today. KERNEL-439.

**D1, D5 and D12 assume Kernel enforces agent files on both providers.** If the live run disagrees with the entries above, this still holds: Kernel's gate works whether or not Claude Code enforces as well, and it is the only gate on Codex. KERNEL-439.

- D1 keeps `toolPolicy` as the one reader of `tools` and `disallowedTools`, for Claude and Codex. To match what Claude Code does for a main-thread agent, a tools line keeps only the MCP servers it names, `disallowedTools` takes `mcp__server` and `mcp__*`, and `mcpServers` neither grants a server nor hides one.
- D5 builds the ask on Kernel's gate (`kernelHooks` in `claude.ts` and the Codex runner's approvals), as planned. Under the agent option an unlisted tool never reaches the model, so the gate would have nothing to ask about. The `hide` setting is what Claude Code does, and Kernel already does it through `deniedMcpServers` and `disallowedTools`.
- D12 checks Kernel's enforcement against Claude Code. `test/live.agentOption.test.ts` shows what Claude Code does with an agent on the main thread, and D12 can run the same file both ways and compare the tool pools, next to the subagent runs it already plans.
