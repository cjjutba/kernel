**Claude defers the Lead's rare tools per tool, and the pinned SDK supports it.** `McpSdkServerConfig.alwaysLoad` is OR'd with a per-tool `_meta['anthropic/alwaysLoad']`, and with the server flag left off a tool that has no flag is deferred behind tool search (`sdk.d.ts`, `McpSdkServerConfig` and `tool()`'s `alwaysLoad` extra). `kernelServer(tools, instructions, { loaded })` sets that meta on every tool: true for the names in `LEAD_ALWAYS_LOADED` (`list_agents`, `list_workspaces`, `create_workspace`, `message_agent`, `request_plan_approval`, `ask_user`, `say`), false for the rest (`create_agent`, `set_project_scripts`, `overrule_blockers`, `file_issue`, `link_issue`, `archive_workspace`, `merge_workspace`, `read_plans`, `wait_for_merge`, `get_issue`, `share_file`). A deferred tool is called like any other once ToolSearch has loaded it, and every agent keeps ToolSearch (`ALWAYS` in `agentTools.ts`, KERNEL-397, KERNEL-439). The old code set the server flag to true. Teammates and reviewers have three to five tools, which they use in most sessions, so their server still sets `alwaysLoad: true`. A resumed session once deferred tools even with the flag on (KERNEL-67), so nothing in the hand-off relies on which tools are loaded. Codex has no tool search, so it still gets every tool as a dynamic tool with the same names, and only the shorter descriptions apply. `toolReceipts` keeps each tool's `_meta`, since it copies the definition.
