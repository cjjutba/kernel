**Kernel opens where you left off by default, and unsent drafts survive a restart.** After a restart Kernel opened Home, or the Lead's first chat with Default home view set to Last room, and every unsent message was gone. CJ chose where you left off as the default for everyone. `general.homeView` is renamed `general.openTo` with `lastPlace` (the default), `home` and `inbox`, and Settings, General, Default home view lists Where I left off, Home and Inbox. The rename carries a one-time migration in `loadAppSettings`: a saved file with `homeView` and no `openTo` gets `inbox` if it was inbox and `lastPlace` otherwise, and loses `homeView`. It reads the file and not the merged settings, since the merge always fills `openTo`. Every launch saved `homeView: 'home'`, so nobody really chose it, the same reasoning as D-094; an `openTo` already in the file, even next to a leftover `homeView`, is kept. What is saved: `kernel.lastPlace` in localStorage holds `{ v: 1, route, tabs }`, the route you are on and every workspace's tabs (open chat, files, diffs). It is written by `moved()` ahead of its history block, so Back and Forward, which record no history, save as well, and by a watcher on `ui.tabs`, because closing a file or diff tab, and pruning the tabs of an archived workspace or a removed room, change what a relaunch shows without being a move. Both write the state as it is after the change, never the place left. Nothing is written before `system.booted`, so a restore never overwrites what it read, and none in fixture mode. What is not saved: Back and Forward history (a restart still starts empty, as KERNEL-200 says), onboarding and the dev pages, and Settings. Open Settings saves the place it was opened from, so Kernel never relaunches into Settings. An image or text tab lives in the screen and is gone after a restart, so a workspace on one is saved on the chat it was last on. Restoring: no rooms still opens Welcome and a failing check still opens the checks screen, both first. Then `openTo` inbox or home goes there. With `lastPlace`, the pure `restorePlace(saved, state)` in `nav.ts` brings back the tabs of workspaces that are still live and goes to `nearest(route)` with history `replace`, so an archived workspace opens its room's Lead chat and a removed room opens Home, with no toast. `agent`, `task`, `floor` and `board` routes open their room's Team page, since agents are not loaded yet and the floor and the Board are hidden (D-104). Nothing saved, JSON that doesn't parse, or a `v` this build doesn't know falls back to the last-room logic, then Home. `kernel.lastRoom` stays because `useProjectRoom` reads it. Drafts amend D-100, which said drafts are never written to disk. `draftStore` now keeps `{ workspaceId, parts }` per chat and writes `kernel.drafts` 500 ms after the last change and on `pagehide` and `beforeunload`; it loads once on first use. Image chips are never written, since one holds a whole screenshot, so a draft comes back with its text and its other chips but without its images. A draft over 100 KB once serialized stays in memory, and so does everything when a write hits the quota; that failure also removes the older saved copy, or a message sent since would come back after a restart. Sending saves an empty box, which removes the draft from disk too. The prune in `draft.tsx` used to check the chats of loaded workspaces only, which at launch would have wiped every saved draft. It now waits for `system.booted` and drops a draft only when its workspace is gone or archived, or when that workspace's chat list has loaded and the chat isn't in it. Whether a list has loaded comes from `chatsLoaded()` in `store.ts`, set by `actions.chats.set`, because `chats[id]` alone can't say: a pushed chat creates the entry with just itself, and judging by that would drop the drafts of the workspace's other chats. KERNEL-201.
