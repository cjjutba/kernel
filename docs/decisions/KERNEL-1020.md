**Restart to update never stops Kernel for an install that can't start.** An update is ready only once Squirrel.Mac accepts it. electron-updater reports a download on macOS before Squirrel has fetched and checked it, so that event only stages the version (status stays downloading at 100%), and Electron's own `update-downloaded` makes it ready. An error while a version is staged means Squirrel rejected it: the offer leaves, and `AppUpdate.installFailed` records the version and a reason, saved in update.json. A code signature failure skips that version (its download is cancelled on later checks until a newer version appears). Any other failure retries on the usual backoff. A newer version failing behind an accepted ready one leaves the ready one offered.

This updates the KERNEL-711 rule. Restart now waits for a newer download before Kernel stops, not after, so agents keep working meanwhile. If the newer one fails or stalls, the ready one installs. One Restart is in flight at a time, and a second press gets the same result. No timer, retry or failure ever calls `quitAndInstall`. After Kernel has stopped, if the app hasn't quit within 30 seconds, or Squirrel reports an error, Kernel saves `installFailed` and relaunches once on the running version. Agents carry on at launch (KERNEL-215). The engine isn't restarted in place.
