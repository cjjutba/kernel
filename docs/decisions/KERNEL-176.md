**The Lead asks for plan approval only while its chat is in plan mode, and with plan mode off it asks in the chat before handing off.** In a Lead chat with plan mode off, CJ asked Rowan a question and got back a plan with Copy and Approve on a hatched composer, so it looked as if plan mode had turned itself on. Rowan never entered plan mode. It called `request_plan_approval`, which the prompts allowed at any time: the kernel MCP instructions said "in plan mode or with request_plan_approval", and so did `LEAD_RULE`. Now the chat's plan toggle decides. With plan mode on, Rowan plans and asks with ExitPlanMode or `request_plan_approval`, the same as before, and an approval still means "hand it off now" with no second question. With plan mode off there is no plan and no Copy and Approve. Rowan answers in the chat, suggests what it would hand off and to whom, and asks before calling `create_workspace`. It hands off once the user says yes, or right away when the message already says to go ahead ("hand it to Noor"), so the user isn't asked twice. Archiving workspaces another chat handed off, or anything else that needs the user's OK, goes the same way. Follow-ups on work the user already agreed to need no new yes: passing on review blockers or failed checks, sending a PR that passed checks to the reviewer, answering a teammate from the plan. With plan mode off, `request_plan_approval` creates no approval and returns an error that says so. It reads the chat's saved plan flag on every call rather than the one the session started with, because the Plan mode chip and ⇧Tab change it mid-session. `create_workspace` has no gate. Kernel doesn't try to detect a yes, so asking first is up to the prompts: the instructions, the tool's description, `LEAD_RULE` and the starter `rowan.md` all say it. `LEAD_RULE`'s "don't ask whether to hand it off" now applies only after an approved plan, so it can't be read against asking first. Plan with Rowan from an issue still opens its chat in plan mode, so it still gets a plan. A pending plan keeps its hatched box and its Copy and Approve bar. Amends D-059, where an approval could come "in plan mode or through request_plan_approval", and D-092, whose task list from `request_plan_approval` now shows only in a chat that is in plan mode.
