**Room settings pages read and write their own room, and Reset covers personal values too.** Every room page takes its room from the route (`page: 'room'`, `roomId`, `section`), so `useProjectRoom` is gone and nothing reads "the last opened room". Room pages never pass `shared`, so they write `settings.local.toml`. A field shows "From settings.toml" when only the shared file sets it and "Overriding settings.toml" when both do. A value only the personal file sets shows no source line, because it matches nothing the other people on the repo see. Reset appears for both of those personal cases and sends `null` for the key. The settings files button offers `settings.local.toml` and `settings.toml` only when `sources` says a key lives there, so a file that exists but holds no key Kernel reads is not offered. KERNEL-191.

**The nav opens the room you are in, and the app defaults have no room.** The room row is a button with `aria-expanded`. The current room is expanded and the others fold. On an app page the room you were in last stays expanded, or the first room before any. Settings, Git and worktrees has no room to list branches from, so its branch and remote selects offer the branches of every visible room. The Environment and Big terminal rows are left out until KERNEL-254 and KERNEL-251 build their pages. KERNEL-191.

**The renderer strips the room's remote, not `origin/`.** `remoteOf` and `stripRemote` in `screens/settings/remote.ts` pick the room's remote, then the app's, then `origin`, as main does. A base ref written as `origin/main` still means the room remote (D-190), so `stripRemote` removes either prefix. KERNEL-191.
