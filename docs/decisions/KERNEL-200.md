**⌘[ and ⌘] (and a mouse's back and forward buttons) step through the screens and chats you visited, and a Settings page is not a step.** Kernel had no way back to the chat or screen you were just on. `store.ts` now keeps `past` and `future`, 50 places each with the oldest dropped, outside the store like `returnTo`, so a restart starts empty. A place is a route and, on a workspace, its tab (`Place` from KERNEL-199). `moved()` decides what gets recorded. Moving to the place you are already on records nothing. Moving between screens pushes the place you left, and so does changing the chat tab of the workspace on screen, so chat 1 then chat 3 then ⌘[ opens chat 1. File, diff, image and text tabs do not push, because they are a detour from a chat and not somewhere you navigated to, and neither does `openTab` on a workspace that is not on screen. A new push clears `future`. Onboarding and the dev pages replace instead of pushing, and so does any move away from onboarding, and `boot()` calls `go` with `history: 'replace'`, so Back right after launch has nowhere to go. Moving from one Settings page to another replaces too. The pages are a sidebar, like tabs inside one screen, so someone who opened four of them wants one Back to leave Settings, not four. That also guarantees that the newest `past` entry is outside Settings, which is what lets `leaveSettings()` (Back to app and Esc) be `back()`: it returns to the place Settings was opened from, and ⌘] reopens the last Settings page. When `past` is empty or its newest entry is dead, `leaveSettings()` keeps the `nearest(returnTo)` path from KERNEL-199. `back()` and `forward()` take the newest entry whose route is still there (`stillThere`) and drop the dead ones on the way, so a workspace archived in between is skipped. They also skip an entry that opens where you already are, which includes an entry whose tab has been closed since and now falls back to the tab on screen, since otherwise ⌘[ would appear to do nothing. They apply the entry with a tab select that records nothing, then `go(route, { history: 'none' })`, and put where you were on the other list. A closed tab falls back through `tabOf`, and a closed file or diff tab is not reopened. ⌘[ and ⌘] match `e.code` (`BracketLeft`, `BracketRight`) with Meta alone, and mouse buttons 3 and 4 on `mouseup` do the same. All of them are skipped while a modal is open or onboarding is on screen, the same guard as ⌘1 to ⌘9. Shortcuts lists Back and Forward in the App group, two rows `SettingsShortcuts.png` does not have. Amends KERNEL-199, whose Back to app followed `returnTo`: it now follows `past` first, so Settings opened from A, then a jump to W with ⌘K, then ⌘[ into Settings, then Back to app lands on A where it used to land on W. Image and text tabs live in the screen and are gone once you leave, so a step remembers the chat you were last on instead. Switching chats from a file or diff tab does the same, so the file never becomes a step and Back goes to the chat before it. Leaving the workspace from a file or diff tab keeps the tab, so Back to app from Settings still shows it. Closing the open chat is not a step either, since the tab you moved off is a fallback you never chose. KERNEL-200.
