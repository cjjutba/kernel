**An archive that asks to delete the branch while another archive of the same workspace runs waits for it, then deletes the branch itself.** The running archive's choice is fixed by the time a second call arrives, and leaving it a request it might read too late is a race. So the second call waits, and if the workspace is still archived, worktree mode, and its archive didn't keep the worktree, it counts the branch's commits and deletes the branch only when none are unpushed (KERNEL-70). A branch it keeps gets a warning note, for commits that were never pushed as well as for commits that can't be counted, because the person asked for the delete and should hear why it didn't happen. A second call that asks to keep the branch, or doesn't say, changes nothing: the running archive's choice stands. KERNEL-139.
