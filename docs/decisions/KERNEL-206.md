**Only the hook Kernel installed can post to the hook server.** Before this, `POST /hooks` took anything. A web page could send a `no-cors` fetch with `text/plain` and, with a guessed room path, open approval cards with any tool input, flood the Inbox (each held approval is a 300s timer and a row) and fake activity. Any local process could do the same. Now each install has a token: 32 random bytes as hex, in `hook-token` in the app data folder, mode 0600, made once and reused (`services/hookToken.ts`). `hookCommand` sends it as `-H 'X-Kernel-Token: <token>'`. The absolute curl path and `|| true` from D-050 stay. `-f` makes a 401 as quiet as a server that is down. The server checks every `POST /hooks` before it reads the body. A Host other than `127.0.0.1:<port>` or `localhost:<port>` gets a 401, which stops DNS rebinding. A missing or wrong token gets a 401, compared with `timingSafeEqual`. A content type other than `application/json` gets a 415. Rejections close the connection. `GET /health` stays open because the Test button and preflight use it. A foreign Host gets a 401 rather than a 403 so a forged post sees one answer whichever check it failed.

The token sits in the command, as the issue asked, so the Settings > Hooks snippet and Install write the same entry and the snippet still works when pasted. A Kernel entry without the current token counts as not installed, the same way D-050 treats old `http` entries, so CheckHooks and Settings > Hooks offer Install. A port or timeout change still rewrites any Kernel entry, so those move to the token too. A deleted or damaged `hook-token` gets a new token, and the hooks show as not installed until Install runs again.

The token is in `~/.claude/settings.json`, so install and uninstall now drop group and other read access on that file. They write a temp file next to it and rename it over, so Claude Code, which writes the same file, never reads half of ours. A symlinked settings file keeps its link, and the write goes to the file it points at. `.kernel-backup` is copied with `COPYFILE_EXCL` on the first install or uninstall and never overwritten. Before, every install replaced it, so the user's original settings were gone after the second one.

Risks that remain. While Kernel is closed, any process can listen on the port. It then receives every hook payload (prompts, tool input and output) and the token, and can answer a PermissionRequest with `allow`. curl's argument list, token included, is visible to `ps` while a hook runs. Any process running as the user can read the token from the settings file. A Unix socket in the 0700 app data folder (`curl --unix-socket`) would close the squatting gap, since another user can't create a file there. It's deferred because the hook port is part of the screens and flows other lanes own: the port field and Use next port in Settings > Hooks, the taken-port preflight and its fix, WorkspaceHooksDown and `/health`. Moving to a socket changes all of them and every installed entry. A process running as the user can read the token and the settings file whichever transport is used, so a socket doesn't change that case. Builds on D-050. KERNEL-206.
