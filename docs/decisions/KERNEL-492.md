**No limit means no cap on open workspaces, and a room can set its own cap.** Amends KERNEL-220 and D-094. KERNEL-220 capped the teammate workspaces the Lead can have open in a room at Settings, Models' Agents working at once, or at three when that was 0. CJ set No limit and Rowan was still refused at three, and the refusal told him to raise a limit that was already off.

There is no hidden default now. `agentCap` in `features/lead.ts` reads the room's `[agents] open_workspaces` when either settings file sets it, else `models.agentLimit`, and 0 from either is no cap. The room's value is a whole number from 0 to 12. Anything else is ignored, so a typo falls back to the app's number and never refuses on its own. The personal file wins over the shared one, as for every room key, and a patch with `null` clears the key so the room follows the app again. By default one number still covers both jobs, the running agents and the open workspaces. A room that wants them apart sets its own.

Dropping the default of three is safe for three reasons. The user approves every hand-off, so the Lead can't open workspaces nobody asked for. An open workspace uses no usage by itself, only a turn running in it does. Running agents stay capped by Agents working at once (`Sessions.atCapacity` and the queue) and by the pause near the usage limit from KERNEL-220.

The refusal names the setting that gave the cap. When the room set it, the user can change it in Settings, then the room, then Agents. When the room follows the app, the user can raise Agents working at once in Settings, Models, or give the room its own limit. Reviews (`review_of`) and `user_asked` still skip the cap. A workspace the user opens from New workspace is never refused and still counts toward the cap. KERNEL-492.
