**A chat's name comes from Claude on the active Claude account, or from Codex's small model when Claude gives no answer.** Before, Haiku ran on the CLI's own login (`sessionEnv(process.env, {})`), whatever account the user picked. CJ's CLI login sat at its usage limit, so every request came back as an error result ("You've hit your session limit") and Codex chats, which have no Claude Code transcript title to fall back on, stayed "New tab". Haiku now runs on `Providers.claudeEnv()`, the same account chats run on. When it throws (a limit, no login, no Claude Code), `Chats.titleFor` asks Codex on the active Codex account instead, so someone who only uses Codex still gets names. The order doesn't depend on the chat's provider: Claude first, then Codex, because Haiku is the cheaper and quicker of the two and most rooms have Claude. Codex runs one turn on an ephemeral thread with `gpt-5.6-luna` (Codex's "fast and efficient" model, about 2 to 6 seconds per name), low effort, a read-only sandbox and `approvalPolicy: never`. An account whose `model/list` lacks that id uses its own default model. A chat neither provider could name gets one line in the main log with each provider's reason, once per chat per run, so a failing fallback is never silent again. An answer that is no usable name ("New chat") doesn't try Codex, since Codex would read the same conversation. Amends KERNEL-202.
