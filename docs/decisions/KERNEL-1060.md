**A plan's attention count is what the user had to do for its PRs.** The count starts when tasks are handed off, so the approval of the plan itself is the start and is not counted. It covers approvals the user decided (allowed, denied or answered: tool approvals, questions and plan approvals) in the plan's step workspaces and in the review workspaces of their PRs (`reviewOf`), read from stored approvals so a restart keeps them. Expired and still pending approvals count for nothing, since the user never acted on them. A merge counts once per workspace, and only when the user started it, from the Merge button or by asking the Lead; an auto-merge does not, and Kernel keeps the mark in `meta` when the user's merge lands. A failed check, a change request or a ready PR the teammate settled never needed the user, so `blocker` stays in the counts at 0. A plan is finished when every step has a workspace and each is merged, closed or gone. KERNEL-1060, KERNEL-1067
