**A Reviewer started on another workspace's branch is a review of that workspace, even without review_of.** The Lead often created reviews with `base_ref` set to the reviewed branch and no `review_of`. On 2026-10-11, 34 of 37 open Theo and Lumi review workspaces in CJ's database had no `reviewOf`, so KERNEL-131 never archived them. create_workspace now links `reviewOf` when the agent's role contains "review", `review_of` is missing, and `base_ref` names an open workspace's branch in the room, with or without `origin/`. The usual review_of checks then run, so a second open review by the same reviewer is refused. Only the reviewer role links. A Frontend or Designer task branched off another task is follow-up work, and archiving it when that branch merges would throw away work. Lumi's design reviews stay unlinked for the same reason. A workspace on the main checkout never matches, so a reviewer on `main` stays a plain task. At start, Kernel links open reviewer workspaces the same way. It also takes an archived workspace as the target when its PR merged or closed, because a review of finished work is the stale case this fixes. It then runs archiveReviews for each one it linked. That run happens once per review: after linking, the next start skips it, so a review kept for unsaved work gets its log note once. KERNEL-299.
