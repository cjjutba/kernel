**A turn's changed files come from its checkpoint diff, not from its tool calls.** When a turn ends, Kernel saves its checkpoint and diffs the previous checkpoint's tree (or HEAD, for a workspace's first one) against the new one with `git diff-tree -r -z --no-renames --raw --numstat`. Each changed path becomes a `ChangedFile` with status A, M or D and its line counts, and that list goes on the turn's `result` row as `files`, which D-029's Changed row draws. Edit and Write calls would miss what Bash, a script, a formatter or a Codex command wrote, and they don't read the same in Claude and Codex. The checkpoint already holds every file the agent could have touched, so one diff covers both providers and every tool. A type change, such as a file turned into a symlink, reads as M. A binary file counts 0 added and 0 removed, since numstat prints `-` for it. Renames show as a delete and an add, as the checkpoint stat counts them. KERNEL-584.

**The files go on the result row the turn already wrote, and only when there are some.** Sessions writes the result row before the checkpoint starts, and the save can take seconds in a big worktree, so the next turn may have ended by then. The checkpoint feature picks out the turn's result row when the turn ends: the newest result row, unless the chat's last message or an Interrupted row comes after it. A stopped turn writes no result row, so its changes go on nothing rather than on the turn before it. Once the checkpoint is saved, Kernel saves the row again with `files`, which keeps its place in the transcript, and pushes `chat.item` so the renderer replaces it in place. A row the chat lost meanwhile, as after `/clear`, isn't brought back. A turn that changed nothing gets no `files`. Neither does the start checkpoint, nor the "Before discarding changes" one, which isn't a turn and calls `snapshot` directly. KERNEL-584.

**Known limit: the diff is the workspace's, not the chat's.** Checkpoints count per workspace, so two chats running in one workspace at once can show each other's files. Whichever ends first lists both chats' edits so far. Workspaces on the current branch share one checkout, so a turn there also lists what another workspace in that folder changed since this workspace's last checkpoint. Files the user edits between turns show under the next turn. Telling these apart would take per-tool attribution, which is what this decision avoids. KERNEL-584.
