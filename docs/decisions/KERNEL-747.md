**A teammate's proposed hand-off never becomes a workspace by itself.** propose_handoff only records the proposal for the Lead chat that handed the work off. The Lead proposes it to the user and calls create_workspace only on a go-ahead, the same as for its own hand-offs. A teammate can't start work the user never approved, and the proposal is refused for an agent the team doesn't have, for the Lead, for a helper that doesn't take tasks and for the teammate itself. KERNEL-747

**ask_lead waits for the teammate's turn to end, and propose_handoff doesn't.** A teammate that asks ends its turn right after, so the question waits for that turn and both wake the Lead once, the way a wait the teammate set does (KERNEL-262). A teammate that proposes carries on with its own work, sometimes for a long time, so the proposal goes to the Lead as soon as the batch is quiet. The user can approve the new work while the old one is still being built. KERNEL-747
