**The app carries its own version's notes for What's new.** What's new from the sidebar, the account menu or the command palette read the live updater state, and with no update ready it showed "Kernel 0.1 is ready" with no notes and a Restart to update that could only fail. It now shows the running version's notes with Done, and offers Later and Restart to update only when an update has downloaded. No PNG draws that state. It reuses the layout What's new has after an update installs, and the `WhatsNewCurrent` fixture shows it. Kernel kept a version's notes only when it updated itself (`update.json`), so a copy installed from the DMG had none. `scripts/release.sh` now writes the same notes it gives `latest-mac.yml` into the build as `out/release-notes/<version>.md`, and the updater reads them at launch into `AppUpdate.currentNotes`. The file is named after the version, so a later local build never shows an older release's notes. A build without the file falls back to `update.json` when that holds the running version. Dev runs and local `pnpm dist:mac` builds have no notes, and What's new shows only its title and Done there. Reading the notes from GitHub at open time would also cover those, but it would fail offline and make an app screen wait on the network. KERNEL-154.
