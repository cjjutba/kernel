**Kernel ends what an agent started on Stop, Close chat, archive and the launch after a crash, and never at the end of a turn.** Each agent process leads its own process group (KERNEL-340), so a dev server or test run it starts sits in that group. Ending only the agent left those running: 8 vitest workers from archived workspaces once held about 35 GB on a 24 GB Mac. Now `sessions.stop` with `tree`, which Close chat, archive and a failed room removal pass, sends SIGTERM to the group once the process is closed, then SIGKILL 2 seconds later. `endLeftovers` does the same for the groups of processes a crash or force quit left. Archive also ends every process whose working folder is inside the worktree, found with one `lsof` call, which catches what was started with `nohup` or in a group of its own. A keepWorktree archive does this too.

Kernel never does this at a normal end of turn, at the idle stop, on `restartIdle`, or for the Stop button, which interrupts a turn and keeps the process. An agent may start a dev server on purpose and expect it to stay up between turns. Archive's sweep runs only for a worktree workspace whose folder is inside the room's worktree folder and does not hold the room's repo, so a current-branch workspace signals nothing and the main checkout, where the user runs `pnpm dev`, is never touched. Kernel's own pid and the processes above it are left out. KERNEL-810.

**Recursive deletes in the main process go through `removeTree`.** Electron's `fs` reads a `.asar` file as a folder, so deleting a worktree that has Electron in its `node_modules` failed with ENOTEMPTY, and every archived worktree stayed in `.trash`. `removeTree` uses `original-fs` under Electron and `node:fs` elsewhere. A trash folder that still fails stays in the saved list and goes in the log once per launch with its error code. KERNEL-810.
