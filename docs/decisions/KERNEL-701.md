**One login shows as one row, and only Add account and Sign in again refuse a login Kernel already has.** Two rows are the same login when their emails match, ignoring case, and on Claude their organizations match too unless either is unknown. Every check uses this one test (`sameLogin` in `features/providers.ts`). An unread organization counts as a match, so a twin can't pass as a spare at a limit just because one side wasn't read yet. A login with no email matches nothing, which is a known limit.

Claude Code's or Codex's own login can match an added account through Run login or a sign-in in Terminal. Kernel allows that and folds the two: `accounts.list` leaves the CLI row out and marks the added row `alsoCli`. That row reads as in use while the CLI login is, and another row's `sameOrg` names it in place of `cli`. Sessions still run on whichever login is active. The fold is only how the list shows it. Sign in again on an added row checks the other added rows, not the CLI login, since a match there folds too. A match with another added row signs the row's folder or home out, keeps its old email and refuses with "That account is already in Kernel."

A switch at a limit skips every account that matches the login in use, whatever its own windows say, on Claude and Codex. When the CLI login matches an added row and signs out, it saves no notice of its own, so one login gets one sign-out notice. The added row's read gives the notice. KERNEL-701.
