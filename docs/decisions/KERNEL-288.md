**Kernel keeps its own log in `~/Library/Logs/Kernel/main.log`, and nothing leaves the Mac.** A crash used to leave a blank window or Electron's raw dialog, and a user reporting a bug had nothing to send. Main now writes a log that rotates at 5 MB and keeps 3 files (`main.log`, `.1`, `.2`). It takes main's `console.error` and `console.warn`, which every service already uses with a `[tag]` prefix, so no call site changed. It also takes uncaught exceptions, unhandled rejections, a crashed window page, a helper process that died, and the page's own `console.error` lines, because a React error can blank the window without any crash. Writes are synchronous, so a line is on disk before a crash ends the process. A write that fails, as on a full disk, is dropped and said once on the console, so the log can never be what breaks. Lines are redacted as they are written, so a token never reaches the disk either. Crash reporting stays local for v1: no Sentry, no upload. Fixture runs (the shots harness, the click-throughs) and the smoke test leave the log off. A dev run can point it at another folder with `KERNEL_LOG_DIR`, which `test/crash.e2e.test.ts` uses. KERNEL-288.

**An uncaught error in main is logged and Kernel keeps running.** Node's advice is to exit after `uncaughtException`, and Electron shows its raw dialog when nothing listens. Kernel listens, logs, and carries on. SQLite writes in transactions, so a half-done handler leaves no half-written row, and a stuck feature is better than an app that quits under the user's working agents. Boot failures still go through `bootFailed`, which shows Kernel's own "Kernel could not start" box and quits. KERNEL-288.

**A crashed window page reloads, with a toast, up to 3 times a minute.** On `render-process-gone` (any reason but `clean-exit`) Kernel logs the reason and loads the app page again, the same way the window first loaded it, and after the load pushes a `toast` event: "Kernel reloaded". The `toast` push event is new in `src/shared/ipc.ts`, for news no other event carries, and Copy diagnostics uses it too. A page that crashes as it loads would reload forever, so the 4th crash inside a minute stops the reloads and shows a native box, Reload or Quit, that points at Help, Copy diagnostics. A headless run only logs it. KERNEL-288.

**Kernel builds the app menu from Electron's default roles, with Help holding Copy diagnostics.** Before this, Kernel set no menu and Electron's default was in use. The new menu is the same list of roles (`appMenu`, `fileMenu`, `editMenu`, `viewMenu`, `windowMenu`, `help`), so every standard shortcut stays. Quit is the `quit` role, which calls `app.quit()`, so it still goes through the quit prompt (KERNEL-214). Help drops Electron's links to its own site. Copy diagnostics puts the app, macOS and Electron versions, the version of the Claude Code copy agents run, the `gh` version, the hook port and the last 200 log lines on the clipboard, then shows "Diagnostics copied". KERNEL-288.

**Diagnostics and the log hide the home folder and anything shaped like a token.** The home folder becomes `~`, matched only as a whole folder. The hook token is replaced by value, read from its file (KERNEL-206), and also by shape: the `X-Kernel-Token` header value and any hex run of 48 or more characters. Commit hashes are 40 characters and stay. GitHub tokens (`ghp_`, `gho_`, `ghs_`, `ghu_`, `ghr_`, `github_pat_`), `sk-` keys, Linear and Slack tokens, AWS key ids, JWTs, `Bearer` values, `user:password@` in URLs and `token=`, `password:` or `apiKey` style pairs with values of 8 characters or more are redacted. Shorter values, like `input_tokens: 500`, are counts and stay. The user name can still appear outside a path (in a git author, say), which the issue doesn't ask to hide. KERNEL-288.
