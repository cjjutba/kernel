**The user's answer to a plan, question or agent card is a user row in the chat, written by the engine and never sent to the agent.** The renderer used to draw the answer bubble from the approval's status, so the chat never saw a send and didn't anchor it like a typed message. Now the `approvals.decide` handler, which every decision in Kernel goes through (the card, the composer, Inbox, Home, the command palette), adds `{ kind: 'user', id: 'answer-<approvalId>', approvalId, parts }` with no `from` once the card settles. The parts are the answer text from `approvalAnswer.ts` and, on Request changes, the images. Agent proposals say Approve or Not now, the button words, even when the user typed a note. A tool permission's Allow or Deny, an expired card, a timeout and a replaced plan add nothing, since only the handler adds the row. The id comes from the approval, so a second settle replaces the row instead of adding another. On the restart and Codex path the row goes in before Kernel's own hidden `from: 'kernel'` message, which still carries the decision to the agent. The row is only for people: Retry, a fresh session's brief, the turn a nudge picks up, the Lead's go_ahead quote and a checkpoint's title all skip it (`isSentItem`), so the agent never reads it as a prompt (KERNEL-836).
