**A GitHub failure carries its kind in the error's name, not in a second transport.** Electron hands the window only `String(error)`, which is "name: message", so main names a failed GitHub call `GitHubError[signed-out]` (or `not-found`, `rate-limited`, `offline`, `other`) and the window reads it back with `githubErrorKind` from `@shared/githubError`. `cleanError` drops the name, so the text a person reads is unchanged. A result type like `{ ok: false, kind }` on each channel was rejected: every caller of `github.repos`, `github.issueList` and `github.issue` already handles a rejection, and a second shape would have to be checked everywhere. The kind comes from what gh prints (`ghErrorKind` in `services/github.ts`): "gh auth login" or HTTP 401 is signed out, "Could not resolve to a Repository", HTTP 404 and "Resource not accessible" are not found, "rate limit" is rate limited, "error connecting to" and Go's network errors are offline, and a run Kernel killed for taking too long is offline too. **PR status freshness is kept per room and goes out with the GitHub pause.** `GitHubStatus.reads` maps each GitHub room to the time GitHub last answered a PR read and, when the last read failed, its kind. A failed read keeps the last good time. It rides the `github` push the footer already listens to. A failure starting or ending pushes right away; a new time alone waits for the end of the poll, so the read after every agent turn doesn't push on its own. A PR read that finds the repo gone still reads as "no PR" (KERNEL-388), so it doesn't mark the room failed. KERNEL-861
