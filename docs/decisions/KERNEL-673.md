**A finished turn reads its account's usage a minute later, once for every turn on that account that finishes in the meantime.** The footer shows usage all the time, so Kernel can't wait for the Usage popover or the 10 minute timer to refresh it. The read covers the provider and account the turn ran on, not every account. The first turn on an account starts a 60 second timer, and turns that finish before it fires share its read. Ten agents finishing together cost one call to the experimental usage API (KERNEL-6), not ten. The window is 60 seconds because Claude Code answers the usage call from a snapshot up to a minute old. A read sooner could return numbers from before the turn. It also matches `USAGE_FRESH_MS`, so when `readUsage` skips the account as freshly read, that read already ran after the turn ended. The 10 minute timer and the read when the popover opens stay.

Accounts that aren't in use are not read after a turn. Each read would start a short Claude session, or a Codex account read, per account. Their numbers come from the 10 minute timer while any agent works, from opening the account menu or Settings, Providers, from launch, and from the account in use nearing a limit. KERNEL-673
