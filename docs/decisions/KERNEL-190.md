**Room pages write the personal file and say where each value came from.** Amends D-046. `settings.setRoom` without `shared` writes `.kernel/settings.local.toml`, as before, and the room's settings pages use it by default. `loadRepoSettings` reads each file on its own through the same whitelist, then merges them key by key: the personal file, then `settings.toml`, then the app default. `settings.room` returns `sources`, keyed by the app-side dotted path (`scripts.setup`, `workspace.remote`, `pr.createInstructions`). `shared` means only `settings.toml` sets the key, `local` only the personal file, and `override` both. A path missing from `sources` falls back to the app default. An array is one value, so a `files.copy` set in both files is an `override`. A `null` or an empty string in a patch removes the key, and a personal file left with no keys is deleted (KERNEL-69). KERNEL-190.

**Every PR action has an instruction a room can replace.** Fix checks and Address review were fixed text in the GitHub service. They are now `pr.fixChecksInstructions` and `pr.addressReviewInstructions` in the app settings, with the old text as the default, so existing settings files pick them up on the next launch. A room's `[pr]` table can set any of the four (`create_instructions`, `resolve_instructions`, `fix_checks_instructions`, `address_review_instructions`). `prInstructions` takes the room's text per action, then the app's, then the default. A blank text counts as unset. The conflicting files, failing checks and review comments still follow the text. KERNEL-190.

**The remote setting now takes effect.** `workspace.remote` was saved but never read, and every git call said `origin`. `remoteOf` picks the room's remote, then the app's, then `origin`. Kernel uses it to fetch and resolve a workspace's base, fetch and merge for conflicting files, push from Archive, count unpushed commits before deleting a branch, restore a branch from the remote, list branches, find the default branch, start and reset a review, continue after a merge and name the base in PR notes. With no remote set, every call uses `origin` as before. Two parts of this are judgment calls. First, a base ref from Settings, from the Lead or from a picked PR is written as `origin/main` because `origin` was the only remote, so with another remote set `origin/` in those refs means that remote (`onRemote`). A branch picked from the list is a real ref and stays as it is. Second, the branch list shows local branches and the room remote's, not every remote's. `gh` picks its repo on its own, so a fork remote is out of scope. The review rule can't wait on a file read, so Kernel keeps each room's own remote in memory, filled at start and whenever the room's settings are read or saved. KERNEL-190.
