**Claude chats keep Claude's guess at the user's next message.** Every Claude session starts with `promptSuggestions: true`. The one `prompt_suggestion` the SDK sends after a turn's `result` is saved on `Chat.suggestion` and pushed to the renderer. Kernel adds no switch for it. The SDK already skips the guess on a chat's first turn, in plan mode, after an API error and near a usage limit, and sessions load the user's Claude Code settings, so `promptSuggestionEnabled: false` there turns it off. Codex has nothing like it, so a Codex chat never gets one. KERNEL-530

**A guess only ever describes the turn that just ended.** One from a process that no longer owns the chat is dropped. So is one that arrives after the next turn started, as when a queued message goes out the moment a turn ends and the guess comes right behind it. Anything that starts a turn clears the saved guess before the turn goes out: the user's message, a queued message, a Team update, a message from the Lead and Kernel's own nudges. /clear clears it too. A message that waits in the queue leaves the guess saved, and the composer hides it until the queue is empty or the message goes. KERNEL-530

**The composer offers the guess in the empty box, and only a key takes it.** → or Tab fills an empty box with it. Enter on an empty box sends nothing, so nobody sends a guess they didn't read. The guess stays hidden in plan mode, while a turn runs, while the chat is blocked, while messages are queued and while autocomplete is open. It uses the placeholder's existing style.
