# KERNEL-895: every chat action draws its result in one frame

**A user action draws its end state in the render after the click, and main confirms it in place.** This is part 2 of one-frame sends (KERNEL-858) and builds on KERNEL-894, where the engine keeps the id the window gives a message.

- One send path (`composer/sendMessage.ts`) serves the composer, the starter suggestions, Ask to fix, Retry and a command from the / menu. It makes the id, then draws the bubble and the running state together, or the tray row when a turn runs, setup holds the chat or the Mac is offline. The saved row replaces the drawn one by id. When main queues what the window drew as a bubble, or sends what it drew as queued, the row moves in one step. A failed call removes everything it drew and puts the text and images back in the box.
- `State.assumed` marks a running state the window drew from the user's action. Main's `chat.running` ends it, the failed call undoes it, and there is no timer. Main holds a message when `chats.send` answers `queued: true`, and also when it answers `queued: false` with no `item` (an account move waits for a choice and queues the message under the window's id without starting a turn). The drawn bubble then moves to the tray and the starting state ends. Send now hides the row it drew as a bubble in the composer while main still lists it.
- Send now, Stop, Approve, a plan's change request (with its images in the answer row) and New chat's first message follow the same rule. New chat opens the chat with its message already in the tray or the thread. A queued message that posts, and a turn that ends into the next message, arrive as one render: a `chat.queue` or a turn ending opens a burst that draws the events that follow it together.
- The queue tray no longer fades rows in or out, and the plan strip no longer animates closed. Its opening is unchanged. Approve also marks the plan settled and takes the chat out of plan mode in the same render.
- Replaces the crossfade of KERNEL-839 (the placeholder and the mode chip fading to the box's own mode once a plan's strip closed). Its `swap`, `swapFrom`, `lastShown` and `wasHolding` state, `data-swap` and `data-from`, the chip's ghost and their CSS and keyframes are gone. The placeholder comes from the current state only: the plan text while a plan waits, "Add a follow up" while a turn runs, else the normal one. The crossfade replayed whenever the box emptied and drew the old text on a second line. The strip's close of KERNEL-833 and its held placeholder and chip are replaced too. The rest of KERNEL-839 (approval folds) stays.
