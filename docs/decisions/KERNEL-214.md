**Quitting while agents work asks in a native macOS dialog, and Cancel is the default.** CJ pressed Cmd+Q by accident with several agents working, and every one of them stopped. Now `before-quit` holds the quit while any agent has a turn running and shows `dialog.showMessageBox`: "3 agents are working", "Quitting stops them partway through their work.", Quit and Cancel. It is a native dialog, not a Kernel modal, because Electron is holding the quit at that point and the window may already be closed or hidden. A native dialog shows either way, with no route change in the renderer. Cancel is both the default and the cancel button, so Return or Escape keeps the agents working. The dialog exists to catch a quit nobody meant, and a reflexive Return should not turn it into one. Kernel counts agents, meaning workspaces with a running chat, not chats. A turn waiting on an approval or a question is still running, so its agent counts. A second Cmd+Q while the dialog is up does nothing. On Quit, Kernel waits for `Kernel.stop()` for at most 5 seconds and then quits, so a stop that hangs can't keep the app open. KERNEL-215 changes the detail line once agents carry on after a relaunch. KERNEL-214.

**A Mac shutdown, restart or logout never shows the quit dialog.** macOS gives apps a short window to quit during a shutdown, and a dialog nobody answers would stall it until macOS gives up on the app or the user. powerMonitor's `shutdown` marks the quit, and it goes ahead after the capped stop. A failed boot, a headless run and a quit with nothing working skip the dialog too. Each still waits for the capped stop. This assumes macOS sends `shutdown` before it asks the app to quit, which is the order `NSWorkspaceWillPowerOffNotification` arrives in. KERNEL-214.

**Restart to update asks before `quitAndInstall`, not in `before-quit`.** On the `quitAndInstall` path Electron closes every window before `before-quit` fires, so a dialog there would show over an app that already looks gone. The `update.install` handler asks through a callback from the app shell, with Restart in place of Quit. On Restart it waits for the capped stop, marks the quit done so `before-quit` lets it through, and then calls `quitAndInstall`. On Cancel it returns `{ ok: true, canceled: true }` and Kernel keeps running. Amends KERNEL-164. KERNEL-214.
