**Try again on room setup runs the first failed step and every step after it, and keeps the steps before it.** The steps before the failure already finished, and running the checkout again could clone or copy over the room's folder. The steps after it run again because they ran on a room with a step missing, or never ran at all after a failed checkout. A step that warned is not a failure, so a retry never starts at one. Starter agents that an earlier try seated still count as Kernel's, not as agents the repo brought. KERNEL-876.

**A second Try again while setup runs is refused, and so is a Try again once nothing failed.** Refusing is simpler than joining the running try, and the page already shows that try's progress. `rooms.retrySetup` returns once the try has started, as `rooms.create` does, and progress comes on the same `room.setup` events. Setup stops counting as running when it publishes its last result, so Kernel never refuses a Try again pressed on that result. KERNEL-876.

**Setup can be tried again only while Kernel runs.** The steps and the New room request live in memory, as they already did for Check again (KERNEL-460). After a restart the call says the room has no setup to try again. KERNEL-876.
