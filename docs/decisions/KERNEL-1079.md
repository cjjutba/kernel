**Replaced by KERNEL-1113:** Kernel no longer checks a go-ahead or hides tracker writes from the Lead. Kept for history.

**A go-ahead can be quoted from the user's latest message and from the question cards they answered after it.** The user approved in a long paste, which the composer turns into a `pasted_text_1.txt` chip, and then on the Lead's own question card. Neither counted: the check read only the text parts of the latest message, and it skipped card answers, which are rows the agent never receives as a prompt. The Lead made 9 `file_issue` calls that were all refused and then asked a third time. Now `userWordsIn` gives the tools the latest message's words and the words of each question card answered in the tab since. A card answer since that message is from the same turn, and the next message replaces them all. Amends KERNEL-678. KERNEL-1079.

**A picked option counts only whole. What the user wrote counts as typed words do.** The Lead writes the labels, so a piece of one is not the user's choice: "file it" out of "Don't file it" is refused, and the refusal names the whole label to quote. The text under Something else follows KERNEL-678's rule, a quote anywhere in it, ignoring case and whitespace. Each question is its own answer, so a quote can't join two. Plan, tool and agent cards say nothing: an approved plan already needs no quote, and a plan's answer row ("Approved") must not stand in for one. KERNEL-1079.

**A paste is the user's words only when the message has nothing typed.** A paste can carry instructions the user didn't write, such as an email or a log. Next to typed words it is material to act on, so only the typed words count. A message of nothing but pastes is what the user is asking, as in this bug. The composer marks a paste with `pasted` on the file part. The engine doesn't trust the `pasted_text_N.txt` name, since a text file from disk carries `text` too (KERNEL-907) and can have any name. Files from disk and images never count. The actions a go-ahead unlocks (a hand-off, an issue, a Build here change) can be undone, and merging still needs a turn the user started. KERNEL-1079.

**A second refusal for the same words says to stop.** The refusal didn't say why, so the Lead retried what couldn't pass. The tools keep the words they last refused. A second refusal for the same message and answers reads "this go-ahead was already refused for the user's latest message, and trying again won't pass. Don't call it again: ask the user once in plain words and end your turn." The check still runs first, so a right quote after a wrong one passes, and a new message or card answer starts over. A refusal also says when the message holds only files or images, or when the quote was a piece of an option. Telemetry counts repeats as `go-ahead-repeat`. KERNEL-1079.

**overrule_blockers takes a card answer too, still only in a turn the user started.** In that turn every card answered since the user's latest message is from the same turn. In a turn Kernel started, an answer could be left over from an earlier turn, and Kernel keeps no clock of when a turn began, so a Team update turn still can't overrule. Amends KERNEL-732. KERNEL-1079.

**`userSaidIn` keeps the message's time for everything timed.** `buildOpen`, `recordGoAhead` and "a plan approved since the user last wrote" still read the latest message, so answering a mid-build question in Build here doesn't close the go-ahead, and plan approvals work as before. KERNEL-1079.

**The Lead's rule didn't grow.** `LEAD_RULE` sits at its length limit, so the go_ahead descriptions and the refusals say a card answer counts and an option is quoted whole, where the Lead reads them while writing the quote. KERNEL-1079.
