**Type, layer and motion values are tokens, and a baseline ratchets the old ones away.** `tokens.css` names every font size, line height, weight, z-index above 9, duration and `cubic-bezier` curve at the value the app already uses, so nothing moved on screen. A one-off value got its own role name and was not rounded to a neighbor. A screen that needs a value that has no token adds one, and `test/theme.test.ts` fails on a literal outside `tokens.css`, a literal type, color or spacing in an inline style, a raw `type="checkbox"`, a `var()` that names no token and a token nothing uses. The first attempt (closed PR #663) moved every screen in one change and could not be reviewed. This one lands the tokens, three shared controls (`Checkbox`, `Button size="sm"`, `IconButton box`) and the checks, with `test/themeBaseline.json` holding today's violations as one line per file. A file can't go above its line, and it can't go below without the line being lowered, so the baseline only shrinks. KERNEL-927, KERNEL-928 and KERNEL-929 lower it folder by folder and the last one deletes it. There are no `!important` utility classes: a shared class goes in `tokens.css` only when three or more screens need it. Z-index 1 to 9 stays literal because those values order siblings inside one component. Keyword curves such as `ease-out` are not flagged. KERNEL-681, KERNEL-926.
