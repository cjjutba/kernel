**An added Claude account is a full `claude auth login` in `<dataDir>/claude-homes/<id>/`, used as `CLAUDE_CONFIG_DIR`, with `~/.claude` linked in.** This is the recommendation for KERNEL-567, which replaces KERNEL-406's `setup-token` accounts.

- **One path string per account.** The Keychain item is named after the exact folder path, so Kernel builds it once as `join(dataDir, 'claude-homes', id)`, with no trailing slash and no `realpath`, and passes that same string to the login, every session and probe, and the logout. A data folder that moves, or a home folder that is renamed, means signing in again, since the old item no longer matches. KERNEL-567 has to handle that: keep the string the account signed in with, show the account signed out with Run login when it no longer matches, and on Remove run `claude auth logout` with the old string so the orphaned item goes too. Whether logout clears the item when the folder is gone is untested.
- **What to link.** Like `linkCodexHome`, before each use, every entry of `~/.claude` gets a link in the folder unless the folder already has one. These stay the folder's own: `.claude.json`, `.credentials.json`, `backups`, `mcp-needs-auth-cache.json`, `policy-limits.json`, `policy-limits.json.stamp.json`, `remote-settings.json`, `daemon`, `daemon.log`, `daemon-auth-cooldown` and `daemon-auth-status.json`. `skills` and `plugins` are real folders whose entries link to `~/.claude`'s, all but `synced`. Link right after the login, before any session or probe, or the CLI makes real `projects`, `plugins` and `skills` folders that block the links.
- **Which `.claude.json` keys to copy.** Before each Claude process on an added account (session, usage probe, MCP probe, models, commands), Kernel writes `mcpServers` and `projects` from `~/.claude.json` into the folder's `.claude.json`, replacing the folder's own, as a temp file and rename at mode 600. Every other key stays: `oauthAccount`, `userID` and the CLI's caches describe the login, and the CLI login's would be wrong there. How this copy interacts with a CLI already running on the same account wasn't tested.
- **MCP servers added on an added account.** They land in its folder, and the next copy drops them. Kernel's terminals don't set `CLAUDE_CONFIG_DIR`, so `claude mcp add` typed there writes `~/.claude.json`, which every account gets. OAuth MCP servers and claude.ai connectors belong to the account: each needs its own sign-in, and Kernel doesn't copy MCP OAuth tokens between Keychain items.
- **Sign-in.** Run `claude auth login` in `node-pty` at `TOKEN_COLS` wide, with `sessionEnv(process.env, {})`, `CLAUDE_CODE_OAUTH_TOKEN` removed and `CLAUDE_CONFIG_DIR` added. Pass on the link with `signInLink`. Show the code field from the start, since the CLI always shows its prompt, and write the code and `\r` as `sendCode` does. Finish on "Login successful." with exit 0, then run `claude auth status` with the folder to get the email and plan, so the Add account sheet no longer asks for a plan. Keep `SIGN_IN_MS` at 15 minutes: this sign-in took 11.
- **Usage.** An added account gets the usage call like the CLI login, so `probeClaudeUsage` and the other short sessions need the account's env, and `usageFromTurns` goes for these accounts.
- **Sign out and Remove.** Sign out runs `claude auth logout` with the folder. Remove runs it, then deletes the folder without following its links.
KERNEL-560.
