**An archived workspace keeps its checkpoints for 30 days, then Kernel drops their refs.** Every turn writes `refs/kernel/checkpoints/<workspace>/<turn>` and `refs/kernel/checkpoint-head/<workspace>` into the user's repo, and archiving left them there, so `.git` only grew. At start and once a day, the archive feature deletes the refs of each workspace archived more than 30 days ago, in its room's repo, one workspace at a time. Kernel doesn't run `git gc`. Git collects the unreachable commits in its own time. A workspace restored within 30 days keeps its Revert entries. One restored later opens with none and saves new ones from its next turn. A room whose folder is gone is skipped and tried again the next day. The meta key `checkpointsDropped` maps each workspace done to the `archivedAt` it was done for, so a daily run makes no git calls for it, and a workspace restored and archived again counts from the new archive. `kernel/backup/*` branches that Revert made belong to the user and stay, as with Delete in History (KERNEL-333).
