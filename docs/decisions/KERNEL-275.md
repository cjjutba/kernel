**Kernel names every new branch itself, from the issue key and a few words of the title, instead of using Linear's `branchName`.** Linear builds its name as `username/key-full-title`, so branches came out like `cjjutbaofficial/kernel-267-a-review-cant-start-when-the-reviewed-branch-name-is-long`, 84 characters. The username says nothing in a repo with one author, and long names set off the review folder bug (KERNEL-178). The default pattern is now `{type}/{task}-{slug}`. `{type}` is `fix` when the issue has a label named Bug, in any case, and `feat` otherwise. `{task}` is the key, lowercased, with anything but letters, digits and dashes removed, so `#41` gives `41`. The slug drops apostrophes, then filler words (a, an, the, is, are, was, were, be, when, that, its) unless nothing else is left, and keeps whole words up to 35 characters. A single longer word is cut at 35. Every name, including one the Lead passes, is cut to 60 characters at its last `-` or `/`, and `validBranchName` checks the cut name. The KERNEL-267 issue now gets `fix/kernel-267-review-cant-start-reviewed-branch`.

The Lead's hand-off reads the labels along with the issue. The New workspace modal's "Start from an issue" reads them with `getIssue` and gives Linear 5 seconds. No answer means `feat`, so Linear never holds a workspace up. `LEAD_RULE`, the `branch` description of `create_workspace` and Plan with Rowan's first message no longer tell Rowan to pass Linear's branch name. Rowan passes `branch` only when the user asks for one.

Linear still links the PR. It matches the issue key in the branch name or the PR title, and both still carry it.

A saved app setting equal to the old default `feat/{slug}` loads as the new default. Every launch saved the defaults, so nobody chose that value, the same reasoning D-094 used for `maxConcurrent`. A pattern someone typed stays. Branches that already exist keep their names, since renaming them would break their open PRs.

A review branch is `review/<key>` for an issue's work, else `review/<a few words of the reviewed title>`, in place of `<reviewed branch>-review`. A second review of the same work gets `-2` from `freeBranch`. Amends D-140 and KERNEL-130. KERNEL-275.
