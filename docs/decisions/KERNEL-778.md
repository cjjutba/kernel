**A Build here chat's PR takes a teammate's path, and the mode decides it, not who owns the workspace.** `buildsHere` in `@shared/leadMode` is true for a chat with Kernel in Build here. For such a chat, Kernel starts reviews when the PR passes checks, reads the PR after each turn, runs base watch, and sends the PR's news and its reviews' verdicts to the chat as a Team update. Switching the chat back to Hand off returns its PR to the old path, where nobody hears about it. Auto-merge, mergeBlock and the overlap check never left Lead workspaces out, so they need no change. A merge still never archives the chat (KERNEL-405). KERNEL-778.

**The chat fixes its own PR, so its Team update says "in this chat's worktree" where a teammate's says "Tell Noor".** `LeadUpdates` takes an `ownChat` dep (`Lead.buildTab`, the chat's first open tab) and routes the workspace's events there. `decide` gets `self` and words failed checks, requested changes, conflicts, blockers and a GitHub block as work for the chat itself. A review of a teammate's PR still names the teammate, and its blockers still go to them. An update that arrives while the chat runs waits for the turn to end, like every Team update. KERNEL-778.

**After a merge, the chat's next turn starts on a new branch in the same worktree, and only from a clean worktree.** `Lead.freshNow` runs in the sync queue before `syncNow`. It runs once the PR reads merged and the chat is idle. It cuts a branch from `<remote>/<default>` named the way `nameChatBranch` names one, and clears the PR fields, the reviews and a linked issue. It pushes a `pr` event with state none, so the next PR reads as opened. With uncommitted changes it keeps the merged branch and leaves one note per PR saying why. Kernel never stashes or discards the user's edits. Amends KERNEL-181, which only ever fast-forwarded a Lead chat. KERNEL-778.

**link_issue renames the branch only before the first push.** The tool, `lead.linkIssue` and `Lead.linkIssue` set `Workspace.source` to the issue. While the branch has no PR and was never pushed (the same check `nameChatBranch` uses), the branch takes a teammate's name for the issue, `feat/kernel-760-retry-button`, and the folder follows once the chat is idle. After a push, renaming would orphan the remote branch and its PR, so only the link changes. The tool tells Kernel to write "Closes KERNEL-760" in the PR body, which is what moves the issue to Done on merge. Hand off refuses it, since a teammate's workspace takes its issue in create_workspace. KERNEL-778.
