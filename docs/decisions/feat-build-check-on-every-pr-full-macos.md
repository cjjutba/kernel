**macOS is the release gate while Kernel ships only for Mac.** Every PR runs `pnpm build` on Ubuntu (the `Build` job), so a PR can't break bundling and still show a green `Test`. The full suite runs on macOS every night on `main`, on every PR from a `release/**` branch and by hand ("Test on macOS", `test-mac.yml`), and `/release` won't merge a release PR without that check green. Ordinary PRs don't run it, so the 5-job macOS limit stays free during the day. Ubuntu stays the per-PR runner because it is faster and has 20 slots. We already found three differences between Linux and macOS (terminal idle detection, the SIGHUP exit, zsh). Adding a platform means adding it to the nightly run and to the release check. A failing macOS run opens or updates its own `ci-mac-red` issue, through the same `scripts/ci-main-red.sh` as `ci-main-red` with a different label. Only a green "Test on macOS" run on `main` closes it. The Ubuntu `ci-main-red` issue keeps closing on the next green push to `main`, and sharing it would let a green Ubuntu push close a Mac-only failure within hours.
