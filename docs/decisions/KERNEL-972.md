**The page tells main when its zoom changes, and main moves the traffic lights from the zoom it reads.** The lights don't zoom with the page, so main places them for each zoom (KERNEL-901). `zoomWindow`, `settleZoom` and the `zoom-changed` handler still do that, but CJ's running Kernel once showed the page at 110% with the lights left at the 100% place, 3pt above the sidebar toggle, and no path we could drive reproduced it. Zooming with `webContents.setZoomLevel` alone reproduces the same picture. So the page listens for a resize that comes with a new `devicePixelRatio` and calls `system.zoomChanged`, and main runs `settleZoom` on the sender's window: it reads the zoom level from the webContents, never from the ratio, which mixes in the display's scale. A move between a 1x and a 2x display sends the signal too and leaves the lights where they are. Don't drop the signal because the main-process placements look complete: it is the net for the cause nobody found.
