**The page tells main when its zoom changes, and main moves the traffic lights from the zoom it reads.** The lights don't zoom with the page, so main places them for each zoom (KERNEL-901). `zoomWindow`, `settleZoom` and the `zoom-changed` handler still do that, but the maintainer's running Kernel once showed the page at 110% with the lights left at the 100% place, 3pt above the sidebar toggle, and no path we could drive reproduced it. Zooming with `webContents.setZoomLevel` alone reproduces the same picture. So the page listens for a resize that comes with a new `devicePixelRatio` and calls `system.zoomChanged`, and main runs `settleZoom` on the sender's window: it reads the zoom level from the webContents, never from the ratio, which mixes in the display's scale. A move between a 1x and a 2x display sends the signal too and leaves the lights where they are. Don't drop the signal because the main-process placements look complete: it is the net for the cause nobody found. Measured on macOS 27.0 from `screencapture -l` window captures, the constants stay as KERNEL-901 set them. KERNEL-972

**The lights also follow Settings, Appearance, Font size.** The signal above didn't fix the maintainer's window: the page zoom was right and the lights sat where the page zoom put them, 3.5pt above the row. Font size zooms `#root` in CSS (`zoom: 1.1` for Large, `0.92` for Small, settings.css), which Electron's page zoom never sees, so the row sat on 31 x 1.2 x 1.1 while the lights sat on 31 x 1.2. Main now places the lights for the page zoom times `FONT_ZOOM` (features/appearance.ts), and moves them when the Font size changes. test/appearance.test.ts checks `FONT_ZOOM` against settings.css, so changing one without the other fails. The floor (`FLOOR_LEVEL`) still counts the page zoom only. With Small at 100% the lights clear the sidebar toggle by 2pt, not 8. They overlapped it before this change.
