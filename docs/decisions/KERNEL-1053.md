# KERNEL-1053: chips show a colored icon for their kind

**Chip icons are colored by what the thing is, and nothing else.** KERNEL-1044 made every chip monochrome, and an image, a pasted text, a PDF, an issue and a PR then looked alike until you read the label. Each kind has its own icon color again: image green, pasted text blue, attached files by type (PDF red, document blue, spreadsheet green, slides orange, archive amber, audio and video pink), workspace teal. An issue shows its tracker's mark, with Linear in blue because its own purple would read as merged. A PR is green while open, grey when closed and purple only when merged, since a PR's state is what it is. An agent keeps its avatar and an @ file its file icon. The `--kind-*` tokens hold the colors, and each light value reaches 3:1 on `surface-3`. Only the icon is colored. The chip's background, border, name and meta stay as they were. Sent messages use the same colors, so a chip looks the same before and after it is sent.

**A gone or unreadable chip goes back to muted.** Color means a kind, so a status never takes it over. Gone and unreadable chips drop to `--muted` for the whole icon, which says the file can't be used. Don't remove the colors in a later cleanup of KERNEL-1044's monochrome rule: DESIGN.md now says "monochrome UI, colored content kinds". KERNEL-1053.
