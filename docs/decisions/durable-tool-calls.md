**A repeat of a Kernel tool call answers from a stored receipt, keyed by the provider's own call id.** Kernel's tools change things: they start teammates, file issues, merge and archive. A provider can send the same call twice, as a retry after a dropped connection or a replay on resume, and the second run would start a second teammate or file a second issue. Each side-effecting call now stores its result in the `tool_receipts` table (migration 10), unique on chat id and call id, and a repeat of that id in that chat returns the stored result without running the tool. The key is the id the provider already gives the call, so the model passes nothing and spends no tokens on it. Receipts older than 30 days are deleted at start and once a day, and a chat's receipts go with the chat.

**Where the id comes from.** Claude Code puts the tool_use id in the `tools/call` request's `_meta` under `claudecode/toolUseId`, and the SDK's in-process MCP server hands it to the handler as `extra._meta` (checked against the pinned SDK in `test/toolReceipts.test.ts`; the typings call `extra` unknown, so Kernel reads it defensively). Codex sends a `callId` with each dynamic tool call, which `callTool` passes to the handler as `extra.callId`. A path that has neither runs the call with no receipt. Kernel does not make up a key from the arguments, because two honest calls with equal arguments, such as two messages with the same words, would then collapse into one. The receipt wraps the tools in `Tools.toolsFor`, the one place both providers get them, so a tool call made directly in a test or another caller is unchanged.

**Every tool is wrapped except a short read-only list.** `list_agents`, `list_workspaces`, `read_plans` and `get_issue` change nothing and are listed in `READ_ONLY_TOOLS`. Everything else is wrapped, so a tool added later is covered until someone lists it there. That includes the ones that wait for the user (`ask_user`, `request_plan_approval`, `set_project_scripts`, `create_agent`): a replay gets the user's earlier answer instead of a second card.

**What is not stored.** A result with `isError` is not stored, since a refusal did no work and the same call should be able to succeed once the reason is gone, as with a plan-mode refusal. A call whose turn was stopped is not stored. A result over 1 MB is not stored. Two calls with one id at the same time share one run. A receipt is matched on the tool's name too, so a call id reused for another tool runs.

**Restart recovery found two gaps, and the rest of the start was already sound.** Closed by this change: a tool row still marked running in a chat the working journal didn't list, which happens when Stop comes just before a force quit and the row never ended, now fails at the next start with no note and no carry on; and a worktree under the project's worktree root that no workspace record names, which a crash between `git worktree add` and the saved record leaves, is reported in the project's feed and a toast, once per folder, and never removed, since it may hold the only copy of someone's work. A folder younger than a minute is skipped, because a workspace being made has its folder before its record. Already handled, with tests: a workspace whose folder is gone (`folderGone`, `test/missingFolder.test.ts`), an approval pending for a turn that is gone (`expireStale`, `test/approvals.test.ts`), a setup run marked running after a crash and a worktree that was never made (`recoverSetups`, `test/projects.test.ts`, `test/newChatAtOnce.test.ts`), a chat that was working (`relaunched`, `test/sessionRunner.test.ts`), a review round in flight (`reviewPending`, `test/reviewRounds.test.ts`), a half-finished archive (`trash` and `cleanups`, `test/archiveTrash.test.ts`) and spare worktrees (`sweepSpares`).
