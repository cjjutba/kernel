**Auto-merge updates a stale PR before it merges it, at most 3 times.** A PR is stale when GitHub reads it behind its base, or when the base's tip has moved past the base commit GitHub last compared the PR with (`baseRefOid`). Auto-merge then runs `gh pr update-branch`, which merges the base in and never rebases, so the teammate's commits keep their ids. Kernel records the update (KERNEL-832) so the reviews carry over, and the new head waits for its checks like any other push. The teammate's worktree fast-forwards to the merge when it is clean and nothing runs in its chat. Otherwise the teammate is told to pull before it pushes again. An update that conflicts moves the PR to conflict, and the Lead asks the teammate to resolve it. After 3 updates of one PR Kernel stops, and the Lead tells the user, so a busy main can't keep a PR updating forever. The count lives in memory and starts again after a restart. Merges a person starts don't update anything. KERNEL-835
