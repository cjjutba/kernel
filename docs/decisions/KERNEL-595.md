**The 80% and near-limit banners can be closed, and View usage opens Settings.** Amends KERNEL-224. "You've used 80% of this week's limit" showed in every workspace from 80% until the week reset, often for days, and could not be closed, though the Inbox row and the macOS notification had already said it. "Close to your 5-hour limit" is the same kind of banner: it informs and blocks nothing.

Those two banners (`weeklyWarn` and `nearLimit`) get a close button and close with a swipe right. Every other banner is unchanged: limit reached, signed out, setup, trust, offline, overloaded, context and hooks have no close control, because each one is a state the user has to act on or wait out.

The button is a small X on the banner's top right corner, hidden at rest and faded in on hover or keyboard focus, so the row looks the same as before and the action button stays where it was. A drag right, or a two-finger swipe right on a trackpad, closes it with the toast's thresholds (60px, or a flick) and slides out the way a toast does. The shared `Banner` gets both whenever it is given `onDismiss`, and no other banner passes one yet. The swipe logic is `useSwipeDismiss`, copied from the toast, which keeps its own copy.

A closed banner stays closed in every workspace until its usage window resets. The key is the banner id plus the window's `resetsAt` (`weeklyWarn:1760000000`), so the next window shows the banner again. The renderer keeps the keys in localStorage (`kernel.limitBannerDismissed`). Main and the database know nothing about it, and fixture mode keeps them in memory only. Keys of windows that have passed are dropped the next time the list is read or written. `bannerFor` takes `dismissed` and skips only those two branches, so the banner below shows in its place. `BannerView.dismissKey` says which banners can be closed and by what key.

Closing "Close to your weekly limit" also hides "You've used N% of this week's limit" for the same week. From 95% the hold is the banner for that window, and the 80% line right after it would say the same thing again. A hold on the 5-hour window does not hide the weekly warning, since that is another window.

The banner action `usage` opens Settings, Account and usage instead of running `claude /usage` in an external Terminal, since that page shows the same numbers inside Kernel. Its label is "View usage" on every banner that has it, including the weekly limit banner, whose PNG still says "Open /usage". The Open /usage button inside Settings, Account and usage stays. KERNEL-595.
