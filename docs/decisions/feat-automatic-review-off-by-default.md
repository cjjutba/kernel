**Automatic review is off by default on every plan.** Amends KERNEL-225, which turned it off for Pro only and left it on for Max, Team, Enterprise and a plan Kernel can't read. Each review is a full extra agent run on every PR that passes checks, and a room with security and UX reviews runs up to three. That is too much usage to spend without being asked, on any plan, so the user opts in with Settings, Pull requests, "Review every pull request automatically". The base default `pr.autoReview` is now `false`, and `planDefaults` no longer sets it.

A saved choice still wins. A file written since KERNEL-225 keeps the value it has, so a user who turned the toggle on or off keeps that. A user who never touched it gets off, on Max too, where reviews ran until now. A file from before KERNEL-225 saved `true` on every launch, so its `true` was never a choice and reads as unset, as KERNEL-225 decided. Its `false` was a choice, since the default was on then, so `loadAppSettings` keeps it as saved even though it now equals the default. `pr.autoReview` stays in `PLAN_KEYS` though no plan sets it, so `planDefaulted` still says whether the user chose it.

Rowan says why no review ran. When a PR passes checks and the setting alone kept a review from starting, the Team update's To do line has Rowan tell the user "No review started because automatic review is off. Turn it on in Settings, Pull requests, or ask me to review it." Without it, a Max user who had reviews last week would see PRs go straight to ready to merge with no explanation. `Reviews.onReady` reads the room's `[review]` for the PR as it would with the setting on, and remembers the head when a review would have started: the plan has a kind, the head had no review round and no review workspace is open. `reviewState` reports it as `notStarted` while the setting is still off and no review or verdict exists for the PR. So the line stays out when the setting is on, when someone already asked for a review, and when `[review]` asks for none, as with `[team] reviewer = "none"`.

The note lives in memory and is not saved. After a restart the next ready event reads it again. The update goes out two seconds or more after the ready event, and reading `[review]` takes a few git calls, so the note is there by then. If git is slower than that, the update goes without the line, which is what it said before this change. The PR card and the workspace panel say nothing new, since they follow `design/redesign/` and a line there needs a design first.
