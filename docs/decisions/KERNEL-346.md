**Fork into new workspace copies the files as they are now, not as they were at the message.** The new branch is `<source branch>-fork` (then `-fork-2` and so on). It starts at the source's HEAD and keeps the source's base, so its diff and PR compare against the same branch. The source's uncommitted and untracked files are written into the new worktree, uncommitted there too. Ignored files come from files.copy and setup as for any workspace. Fork into new chat already works this way: the conversation goes back to the message, and the files stay as they are. The workspace is named `<source name>-fork`, since the sidebar shows the name. It has no issue source and no Lead chat, so it doesn't move a Linear issue or count as a hand-off. KERNEL-346
