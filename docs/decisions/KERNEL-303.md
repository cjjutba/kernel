**A shared HTML page runs in its own sandboxed view, never in an iframe in Kernel's page.** Kernel's window runs with `sandbox: false` so its preload can use Node, and Electron applies the sandbox per WebContents. An iframe would share a renderer process with the Kernel bridge, and a page that loops forever would freeze Kernel with it. Each open tab gets a `WebContentsView` instead, made by `src/main/previewHost.ts` and drawn over the tab at the rect the renderer sends. The view has `sandbox: true`, context isolation, no preload, Node off in frames and workers, no webview tag, no plugins, no drag-and-drop navigation, safe dialogs, and DevTools only in dev builds. It lives in the in-memory partition `kernel-preview`, a different storage partition, so Chromium always gives it a process of its own. A view also gives `capturePage` for stills, which the tab shows while a menu or modal covers the view. Kernel never imports the host; `index.ts` wires it in. KERNEL-303.

**A preview reaches one version's bytes and nothing else.** The page loads from `kernel-shared://<token>/`, a scheme registered as standard, secure and streaming, with no fetch, CORS, CSP bypass or service workers. Each view gets a random token for one version, and a new version gets a new token, so the old one stops serving at once. Every response carries a CSP that allows inline code and `data:` and `blob:` URLs and nothing it can connect to, frame, submit or post to. The session cancels every request that isn't a live token's URL, one of its blobs or a `data:` URL. Its proxy is `http://127.0.0.1:9` with loopback included, so anything that slipped past the filter goes to a port nothing listens on. WebRTC is limited to proxied UDP. Every permission request and check, device permission and screen capture is refused, downloads are cancelled, and spellcheck is off. Navigation, redirects, new windows and webviews are all prevented; hash links still work because they don't navigate. `test/preview.e2e.test.ts` runs a page that tries fetch, XHR, an image, CSS `url()`, a WebSocket, `sendBeacon`, a form post, meta refresh, `location`, `window.open`, geolocation, the camera, notifications and a download. None of them works, and a local server sees no request. KERNEL-303.

**PDFs get no live view.** Chromium's PDF viewer does not render in an in-memory partition. In Electron 38.8.6 the viewer's extension frame loads, but its `<embed>` never appears and the page stays blank, from `kernel-shared:` and from `file://` alike. In the default session and in a `persist:` partition the same file renders. So `system.preview.open` returns no view for a PDF, `plugins` stays off in every view, and the PDF extension's URLs stay blocked. The tab shows "Open in Preview" instead. A `persist:` partition used only for PDFs would make the viewer work, at the cost of a profile folder on disk; that is a separate call. KERNEL-303.

**Thumbnails draw in an offscreen window, so Kernel addresses its own window by name.** An offscreen `WebContentsView` that isn't attached to a window never paints: no `paint` events and an empty capture. An offscreen `BrowserWindow` renders with Kernel's window closed, but it joins `BrowserWindow.getAllWindows()` and Playwright's `app.windows()`. So `index.ts` sends push events, focus, the quit dialog and `activate` to Kernel's own window, never to the first or every window, and a thumbnail window never gets Kernel's events or focus. Playwright's `firstWindow()` is still Kernel's, because Kernel's window opens before any thumbnail. Note that `app.windows()` also lists every preview view. A thumbnail renders the page at 1280 by 800, waits for the load plus 600 ms, or 6 s at most, and keeps a 640 px wide PNG. A page that loops before its first paint never lets `capturePage` resolve, so the whole job, capture included, has an 8 s deadline, and `unresponsive` or `render-process-gone` end it sooner. Then the file gets no thumbnail, main kills the stuck renderer, because closing the window alone doesn't stop it, and the next thumbnail in the queue starts. The issue asked for JPEG, but KERNEL-302's `capture` hook and `shared.thumb` already call it a PNG. An image draws inside a small page with `object-fit: contain`, so an SVG's scripts never run. PDF and Markdown get no thumbnail. KERNEL-303.

**A hidden view still gives a fresh still.** `capturePage(undefined, { stayHidden: true })` on a view hidden with `setVisible(false)` returns the page as it is after each change, in a shown window and a hidden one. Main pushes `settled` 300 ms after input, a finished load or a move, so the tab knows when a new still is worth taking. KERNEL-303.

**App shortcuts typed in a preview go to Kernel; editing and system keys stay put.** The view's `before-input-event` matches on the key's `code` and exact modifiers. ⌘K, ⌘N, ⌘⇧N, ⌘T, ⌘⇧T, ⌘W, ⌘B, ⌘⌥B, ⌘\, ⌘comma, ⌘[, ⌘], ⌘1 to 9, ⌘⇧L, ⌘⇧P, ⌘L, ^⌘1 to 4 and ⌘⇧/ are prevented, focus moves to Kernel's page, and main pushes `preview.key` for the app to run. ⌘R reloads the preview and F6 hands focus back. ⌘C, ⌘V, ⌘X, ⌘A, ⌘Z, ⌘Q, ⌘H and ⌘M go to the page and the menu as usual, so ⌘Q still quits. KERNEL-303.

**Four views stay open.** One view per tab, keyed by workspace and file. A hidden view is kept, so switching back is instant. Past four, the least recently opened or placed view closes, and the tab opens it again when it comes back. All of them close with Kernel's window. KERNEL-303.

**The preview e2e runs the real host in a fixture run.** A real boot rewrites the hooks in `~/.claude/settings.json`, so the e2e can't start Kernel for real. With `KERNEL_E2E_PREVIEWS=1`, a dev build in fixture mode makes the host and serves copies laid out like Kernel's under the fixture's data folder. A packaged app ignores the variable, and without it a fixture run has no live views: `open` returns the fixture's still. KERNEL-303.
