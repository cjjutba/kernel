**A skill or MCP server switched off in Settings reaches a new session as a deny entry in the session's flag settings, not as an allow-list.** Kernel passes `skillOverrides: { <name>: 'off' }` and `deniedMcpServers: [{ serverName }]` through the `settings` option of `query()`. The issue asked for `skills` with the enabled list, plus `strictMcpConfig: true` with the switched-on servers. Against the pinned CLI (0.3.292), on CJ's config, those two options drop far more than the switches cover. Settings, Skills and MCP lists the repo's and the user's own skills, 19 of the 109 a session loads. The other 90 are plugin skills, Claude Code's built-in skills and skills synced from claude.ai, and a `skills` list hides every one of them. `strictMcpConfig` drops every plugin server and every claude.ai connector (paper, context7 and eight connectors on CJ's Mac), and that page doesn't list those either. Both options would take away things the user set up, with no switch to bring them back. The deny entries remove exactly what was switched off and nothing else.

A denied server never starts. With `chrome-devtools` denied, its `npm exec` process and its child were missing from the session's process tree, and `mcpServerStatus()` no longer listed it. A skill set to `off` is gone from the model's listing and from `/name`. Kernel's own server (`kernel`, which Leads, reviewers and teammates all get through `mcpFor`) is never denied, even when the user has a server of that name switched off. Kernel reads the room's `[disabled]` table when the session starts, from both settings files, synchronously, because `start()` can't wait. A change made in Settings or by hand reaches the next session, and a running session keeps what it started with.

What switching things off saves on CJ's config is small, and the PR says so. Turning off 13 of the 19 user skills and 6 of the 7 user servers took a bare session in an empty folder from 19,484 to 18,771 tokens, the same on two runs. The CLI caps the skill listing at 1% of the context window and shortens descriptions to fit, so 109 skills cost about 10k tokens and 96 cost nearly as much. MCP tools are deferred behind tool search, so a server's tools cost little until used. Most of the MCP instructions come from the claude.ai connectors. The bigger saving is processes: the stdio servers a user switches off no longer start in each of dozens of sessions. Listing plugin skills, plugin servers and claude.ai connectors in Settings so they can be switched off too is a follow-up, not this change.

**Kernel's sessions compact against a 200k window.** `sessionEnv` sets `CLAUDE_CODE_AUTO_COMPACT_WINDOW=200000` unless the environment Kernel started with already sets it. The CLI compacts 33k below that window, so a chat on a 1M model compacts near 167k instead of near 967k. A model whose own window is smaller keeps its own. Tested against the pinned CLI: the variable moved the reported threshold, it is clamped to at least 100k, and a Haiku session with a 100k window compacted on its own (`compact_boundary`, `trigger: auto`, 78k tokens down to 7.5k) after its context passed 67k. `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` at 20 left the threshold at 967k, so Kernel doesn't set it. The context meter in a chat now reads against 200k on a 1M model, which is where compaction happens. KERNEL-226.
