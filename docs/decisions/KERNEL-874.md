**The sidebar's Issues and Pull requests are one page, Work, with two tabs.** Both answer one question, what is being worked on, so they share an entry, a header and a room picker. The routes `issues` and `prs` stay as they are and the route's name decides the tab, so every older link (Up next, the palette, a workspace) lands on the right tab with Work selected. The sidebar's Work opens the last tab used.

**It is called Work, not Tasks.** "Task" already means one step of an approved plan, handed to one agent as a workspace (docs/PRODUCT.md, Glossary). An issue is not a task: it may never become a plan, and one issue can hold several tasks. A page called Tasks would list things that are not tasks and send people looking for plan steps there. Work names the page without taking a word the product uses. KERNEL-874.
