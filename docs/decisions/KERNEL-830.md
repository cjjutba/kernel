**Workspace port blocks run from 4300 to 5999, minus any block holding a port browsers refuse.** Amends KERNEL-244. Blocks start at 4300 and step by 10 up to 5990, which leaves room for 169 open workspaces where 4300 to 4809 left room for 51. The range stops short of 6000, which browsers refuse to load, and stays well below the hook ports (7420, 7430, and a workspace run's `$KERNEL_PORT + 9`). A block that contains a port browsers refuse is left out, so no preview gets a `$KERNEL_PORT` it can't open. In this range that is 5060 and 5061 (SIP), so block 5060 is gone. `BROWSER_BLOCKED_PORTS` sits next to `BLOCK_STARTS` in `scripts.ts`. Ports another app holds, like AirPlay on 5000, are not listed there: the bind check already skips a block with a port in use, and the list would go stale as apps change. Every non-archived workspace still holds its block, Lead chats included. Taking ports only while a dev server runs would change `$KERNEL_PORT` for every setup script, so it waits.

**Running out of ports tells the user how to get them back.** `portBlock` throws `NoFreePortBlock`, and `withPort` turns it into a message that says how many workspaces are open and that archiving finished ones frees their ports. The Lead's create_workspace doesn't catch it, and the SDK's MCP server returns a tool error's message unchanged, so the Lead reads the same text. KERNEL-830.
