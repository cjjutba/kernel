**Kernel watches a room's settings files from the first time the window reads them, and sends a change only when the values differ from what the window last had.** `settings.room` and every save through `settings.setRoom`, `settings.setReview` and `settings.setAlwaysReview` record what the window holds and start the room's watcher. A file event re-reads both files 200 ms later and sends `settings.roomChanged` only when the result differs, so Kernel's own saves don't echo back, and nothing is sent while either file doesn't parse (the existing warning from KERNEL-231 goes out instead). Rooms nobody opened in Settings aren't watched. An archived room stops its watcher from the push reaction in `features/wiring.ts`, and quit stops them all from the teardown `listen` returns, so `kernel.ts` gets no new line. macOS sends no event when a whole repo folder is deleted, so a gone folder is noticed at the watcher's next event or when the window reads the room, and quit closes the watcher in any case.
