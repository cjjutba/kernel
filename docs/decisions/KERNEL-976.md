**The guard's repo is the chat's own folder, not the main checkout a chat with Kernel takes its config from.** Amends D-023. A chat with Kernel runs in its own worktree but passes `projectConfigRoot` (KERNEL-355), so Claude Code sets `CLAUDE_PROJECT_DIR` to the main checkout and runs the checkout's hooks there. The guard took its root from `CLAUDE_PROJECT_DIR`, so it denied every Write and Edit in the chat's worktree as "outside this repo". It showed up after KERNEL-424 moved a chat's folder, but the move wasn't the cause: the root was never the worktree. Now the guard uses `KERNEL_WORKSPACE`, which Kernel sets to the chat's folder and sets again when the session restarts after a move, when that folder is a worktree of the same repository as `CLAUDE_PROJECT_DIR` (same `git rev-parse --git-common-dir`). Any other value is ignored and the root stays `CLAUDE_PROJECT_DIR`. A teammate's two variables already match, so nothing changes for it. A chat with Kernel can no longer write into the main checkout, which is the maintainer's, and every other D-023 check is unchanged: symlinks are followed part by part, `..` after a link, symlink loops, the plans folder and the app's data folder.
