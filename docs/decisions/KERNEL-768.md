**Auto-merge weighs a PR again when GitHub or Kernel hadn't settled it, a few times at most (KERNEL-768).** Kernel weighed each PR once per key (number, head, approvals, GitHub's block, checks) and stored the key before its fresh read of GitHub. When that read came back with mergeability still unknown, failed, or saw a check or review still running, the refusal stood until the key changed. GitHub settling a few seconds later changes no part of the key, so approved, green PRs stayed at Ready to merge. Now `autoMergeRetry` sorts each refusal. A temporary one forgets the key and asks for the quick re-read, which weighs the PR again, up to 8 times per key. The Lead hears the reason only after the last one. The same goes for a merge that failed because GitHub was still checking for conflicts. Refusals from the user's own rules (auto-merge off, a local room, green checks off, a failed or missing check, GitHub's block, missing approvals, blockers, overrules, the line limit, the always-review paths) are never retried, since they only change with something that changes the key. Nothing is retried after the PR is forgotten or the poll stops.
