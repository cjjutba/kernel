**The Bash guard reads a command the way a shell does, with a reader written in Kernel.** Amends D-016. The guard matched commands as text, so quoting, aliases, variables, `--all`, `--mirror`, flag order and redirections got past Never allow, Always ask and room rules. These all passed with `main` protected: a quoted `main`, `--all`, `--mirror`, a `-c alias.p=push` alias, and a branch held in a variable. The default Always ask rules missed `rm -fr`, `rm -r -f`, `git push -f` and a push of a `+` refspec. A room rule `cat:*` covered `cat <(cmd)`, and `echo:*` covered `echo hi > ~/.zshrc`.

The reader is `services/bashGuard.ts`, with no dependency. A vetted package would have meant checking its license, size and upkeep for a guard that has to stay small, and the forms an agent writes are a small part of the grammar. `parse` gives simple commands with their words, which words hold an expansion, their redirections, process substitution and heredocs. It handles quotes and escapes, the operators, subshells and groups, `$( )` and backticks (their inside is read as commands of their own), `<( )`, heredocs (the body is data, unless the delimiter is unquoted, then its substitutions run), `$'...'` and comments. `unwrap` takes off assignments, `env`, `command`, `exec`, `sudo`, `nice`, `nohup`, `time` and `timeout`, reads `bash|sh|zsh -c`, and reads `eval` as unknown and as a script. Git's global options and `-c alias.x=...` are resolved, and a `!` alias is read as a script.

A command that runs another with the rest of its words is read too: a `git` among the words of `xargs`, `find -exec`, `watch`, `npx` or `ssh host` is read as a git call, unless the command only prints or reads its words (`echo`, `printf`, `grep`), so `echo git push origin main` stays text. A heredoc is data, unless a shell reads it (`bash <<EOF`, `cat <<EOF | sh`, `ssh host <<EOF`), and then its lines are commands. A `case` pattern's `)` doesn't end the `$( )` it sits in. The old text check found a `git` anywhere in a command, and these keep what it caught.

A push to a protected branch is denied in any spelling: quoted, with a `+`, `src:dst`, `:dst`, `refs/heads/`, `--all`, `--branches` and `--mirror`. A ref that is only known when it runs (`$b`, `$(...)`, a brace list, a pattern) asks, and so does a command git doesn't provide, or one only known at run time, that names a protected branch. So pushing the current branch by `$(git branch --show-current)` now asks. Rules match by words as well as by text: `rm -rf` covers `-fr`, `-r -f` and `--recursive --force`, and the force-push rule covers `-f`, `--force-with-lease` and a `+` refspec. The text match every rule always had stays, so nothing that asked before stops asking. That keeps one old false positive: a rule's text inside a longer word, as the protected-branch rule inside a push to a branch named `main-fix`.

Room rules. A prefix rule covers one plain command whose words start with the prefix. It never covers a chain, a redirection, process substitution, a heredoc, a substitution, a word only known when it runs, a wrapper or a leading assignment. So `npm test 2>&1` and `FOO=1 npm test` ask even with `npm test:*`. An exact rule matches the same command with its spacing normalized. D-016 stays as written: a room rule beats Always ask, and Never allow beats a room rule.

It is a guard for what an agent writes, not a sandbox. It doesn't read a script run as `bash file.sh` or `curl x | bash`, a push with no ref that follows git's config, an alias set in a git config file when the command names no protected branch, or a script a command runs by another name than a shell. KERNEL-230, KERNEL-404.
