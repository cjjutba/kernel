**Tests run on plain Node, and CI uses the Node major Electron ships.** Replaces D-013. Running vitest through `ELECTRON_RUN_AS_NODE=1 electron` made every forked worker an Electron process, each with its own Dock tile and about 13 MB more memory than Node. With several agents testing at once the Dock filled with "exec" tiles. On plain Node the only thing that broke was better-sqlite3: postinstall builds it for Electron's ABI (149 on Electron 44), and Node 24 needs 137. node-pty loads fine.

So the tests get their own copy. `scripts/sqlite-node.ts` downloads better-sqlite3's prebuilt binary for the running Node with the `prebuild-install` the package already depends on, and builds it with `node-gyp` when there is no prebuilt one. Both run on a copy of the package in a temp folder, so the Electron build in `node_modules/better-sqlite3/build` stays as it is. The result goes to `node_modules/.kernel/better_sqlite3-<abi>.node`, and the script does nothing when that file exists. `postinstall` runs it after `electron-builder install-app-deps`, and vitest's `globalSetup` runs it too, so a worktree installed before this change works without a reinstall. It runs no dependency install script, so `allowBuilds` (D-014) doesn't change.

App code keeps importing `better-sqlite3`. `vitest.config.ts` aliases exactly `^better-sqlite3$` to `test/support/sqlite.ts`, which loads the real package with `require` (the alias doesn't apply to it) and passes the Node binary as `nativeBinding`. `pnpm dev`, `pnpm shots`, `pnpm build` and the packaged app never see the alias and load the Electron build. `pnpm test` is `vitest run`, so `pnpm exec vitest run <file>` works too.

Electron 44 ships Node 24.21, so `engines.node` is `>=24` and the Test workflow runs Node 24. When an Electron bump moves to a new Node major, CI and `engines.node` move with it, so tests keep running on the Node the app ships. Tests that launch the real app through Playwright (`navMemory`, `envEdit`, `windowGuard`, `crash.e2e`, `preview.e2e`) still start Electron and stay opt-in with `KERNEL_E2E`. KERNEL-735.
