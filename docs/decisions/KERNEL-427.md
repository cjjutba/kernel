**The Open in menu shows each app's own colored icon.** This is the second exception to DESIGN.md's monochrome rule, after D-062's green image chip. A grey glyph for Cursor, Zed and Warp would leave the user reading names to find their app, and a person spots their editor by its icon first. CJ chose the real icons, which Conductor also shows. Main draws each as a 32 by 32 Quick Look thumbnail (`nativeImage.createThumbnailFromPath`), once per app path per launch, and hands them to the renderer as PNG data URLs on `OpenApp.icon`. Not `app.getFileIcon`: on macOS Chromium looks icons up by file extension, so it drew every .app with the same blank app icon. The renderer never reads a file to get them. Fixture mode lists apps without icons, so a screenshot looks the same on every Mac. KERNEL-427.

**Open in launches only apps from Kernel's own catalog, with `open -a`, and never hands a terminal or Finder a file.** The catalog in `services/openApps.ts` names each app, its bundle id and its .app file. Kernel looks for the .app in /Applications, ~/Applications, /System/Applications/Utilities and /System/Library/CoreServices. Then it runs one `mdfind` for the rest, which gives up after 3 seconds and skips the Trash. The renderer sends a catalog id, never a path to an app, and Kernel refuses an id it doesn't know or didn't find. It also refuses a path outside every room and workspace, the check that `system.openInEditor` had (KERNEL-208). Main runs `open -a <app> <target>` with an argument array, never through a shell and never `shell.openPath`. `open -a Terminal run.command` runs the script, and a checkout carries no quarantine flag to stop it. So terminals get the file's folder, and Finder opens a folder or shows a file in its folder through `reveal`. Ghostty doesn't start in a folder `open` hands it, so it gets `-n -a Ghostty --args --working-directory=<folder>`. `system.openInEditor` stays for the file view, plan rows, approval cards and Settings. It now opens in the default editor instead of running `code`, which sent anyone without VS Code's command to Finder. KERNEL-427.

**The last app picked in Open in becomes the default.** An explicit pick is saved as `general.openIn` once the app opens, and a launch that fails keeps the old pick. The menu's default is that app while it is still installed, else the first installed editor in catalog order, else Finder. Open in editor with no app named opens the last pick only when it is an editor, else the first editor, else shows the path in Finder. It never opens a terminal, since a terminal would ignore the file the user asked for. There is no setting to edit the pick and no migration: the key is unset until the first pick. KERNEL-427.
