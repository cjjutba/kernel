**A room with no GitHub merges a workspace's branch on the Mac with git plumbing, and never runs `git merge` or `git rebase` in a folder.** `git merge-tree --write-tree` builds the merged tree, `commit-tree` makes the commit, and `update-ref` with the old value moves the base branch only if it still points where the merge started. A merge that stops halfway can't leave any folder mid-merge, and the workspace's own worktree is never touched. Only committed work merges, the way only pushed work merges on GitHub. `features/codeHost.ts` gives a room with `host: 'local'` this host, and the git work is in `services/localMerge.ts`. KERNEL-467.

**A branch that is behind its base merges when nothing conflicts.** GitHub does the same unless the repo requires branches to be up to date, and a repo on the Mac has no such rule. `PrInfo.local.behind` says how far behind it is, and it never blocks. KERNEL-441 left this to the engine, so the Behind panel offers Merge in place of Update branch and keeps its note as information. KERNEL-467.

**Rebase replays each commit through merge-tree with a stand-in commit, so it works on git 2.38.** `--merge-base` arrived in 2.40, and Kernel's minimum is 2.38. For each commit, Kernel writes a throwaway commit with the tip's tree and the commit's parent. The two share that parent as their merge base, so merge-tree applies just that commit, the way a cherry-pick does. Merge commits on the branch are dropped, as `git rebase` drops them. A commit whose parent is already the tip is kept as it is, so a branch that isn't behind fast-forwards with its own commits. A step that conflicts stops the merge, even when the branch as a whole would merge cleanly. Authors and messages carry over, and Kernel's git identity only goes on the throwaway commits. KERNEL-467.

**The folder with the base checked out moves only when it is clean, and Kernel never stashes or commits there.** Clean means no tracked file with uncommitted changes and no untracked file where the merge writes. Other untracked files don't count, as for `fastForward` (KERNEL-259), because the merge leaves them alone. Kernel checks, swaps the branch, then moves the folder with `read-tree -u -m old new`, the way `git merge --ff-only` would. If git refuses because a file changed in between, the branch goes back. A folder with no base checked out leaves only the branch to move. KERNEL-467.

**A local merge is final once git says it landed.** The workspace moves to merged, with `mergedAt` and `mergeCommit`, from the merge's own result and not from a later read. Git can't tell a squashed branch from one that never merged, so every read after that keeps it merged. The `pr` push then archives it through `archiveMerged`, as for a merge on GitHub. A local PR has no number or url, and Create PR refuses in a local room. KERNEL-467.

**`[pr] merge_method` decides the merge on every host.** `CodeHosts.methodFor` reads the room's setting, else Settings, Pull requests. KERNEL-468 adds a default from the methods the repo allows. KERNEL-467.
