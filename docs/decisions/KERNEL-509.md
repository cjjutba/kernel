**One sidebar frame in the app and in Settings.** Amends KERNEL-419. Both columns read the same saved width, but they still looked different: Settings drew `.main` with 8px of padding on every side where the app uses `8px 8px 0 0`, so its panel started 8px further right and its footer sat 8px higher, and `SettingsNav` kept its own `<nav className="set-nav">` with its own copy of the width and padding CSS. That copy is how the two drifted. `Sidebar.tsx` is now the only frame. It owns the `<nav>`, `useSidebarWidth`, the `.sidebar` class and the `ResizeHandle`, and App renders it for every route except onboarding and the dev gallery. Only the list inside changes: `AppSidebar` in the app, `SettingsNav` in Settings, which App still lazy-loads and passes in as `settingsList`. Settings shows the frame even while the app sidebar is hidden with ⌘B, and it uses the default `.main` padding, so the panel's left border and the footer line up at any saved width. While the sidebar is showing, the frame is one element across both views, so a drag changes both without either reading the saved width again. With the sidebar hidden, Settings mounts the frame and it reads the saved width then. KERNEL-419 said the two are never on screen together and each reads the width on mount. There is one hook now. The 16px Settings gutter and its 16px wide, 8px outset handle are gone: the handle is the frame's 8px strip, and its glow lands on the panel's border the way the app's does. `.set-nav` is deleted. The frame passes `hideBelow` and `onHide` to the handle only in the app, so a drag in Settings still stops at the 200px minimum and never hides the column. The Hide sidebar button stays in the app's list. The frame is named Settings while Settings is open and Sidebar otherwise, so a screen reader can tell them apart as before. KERNEL-509.
