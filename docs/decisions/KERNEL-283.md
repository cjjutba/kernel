**A PR GitHub is still checking for conflicts is never ready.** Each time the base branch moves, GitHub reports `mergeable: UNKNOWN` until it has worked out again whether the PR conflicts. `prStateOf` reads that as `checks` where it would have said `ready`, and `PrInfo.conflictsUnknown` marks the read. Only the conflict question is open, so the rest of the read stands: failing checks still read `cifail` and requested changes still read `changes`. A PR that was in `conflict` stays there until GitHub settles, so it can't flip to another state and back in a few seconds. KERNEL-283.

**One quick read follows an unknown one.** After an unknown read, Kernel reads that PR again 15 seconds later, once per workspace. If GitHub still hasn't settled by then, the 45 second poll takes over until a settled read clears it, so a slow PR doesn't cost a `gh` call every 15 seconds. Archive and stop drop a pending quick read. KERNEL-283.

**Ready again on the same commit isn't news to the Lead.** A ready PR now reads as checks for a moment each time main moves, then ready again. Once an update has told the Lead a PR is ready, a return to ready from checks on the same head commit adds nothing. Any other state in between, or a new commit, makes the next ready news again. This also quiets a manual rerun of checks that pass again, which `collapse` already treats as old news while the update waits. KERNEL-283.
