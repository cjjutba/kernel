**Main reads Settings, Appearance before it makes the window, and native UI follows the app's theme.** Before KERNEL-708 the window opened on a hardcoded `#070707` and the dark tokens, and only switched once the page loaded settings over IPC, so a Light user saw a dark frame first. Main now reads `appearance` from settings.json synchronously (`features/appearance.ts`), with every key checked on its own and dark for a missing or unreadable file. It sets `nativeTheme.themeSource` to the setting, so menus, context menus and dialogs follow Dark or Light, and Match system follows macOS. The window's background is `--canvas` for the resolved theme, kept in `WINDOW_BG` and checked against tokens.css by test/appearance.test.ts. It follows a change in Settings through `onSettings`, and a change in macOS through nativeTheme's `updated` event. The page gets the appearance as a `--kernel-appearance=` flag in `additionalArguments`, which the preload exposes as `window.kernel.appearance`. `main.tsx` puts `data-theme`, `data-font`, `data-density`, `data-pointer` and `data-reduce-motion` on `<html>` before React mounts. A flag, not an inline script, because the CSP forbids inline scripts, and not a sync IPC call, because it blocks the page on main. A fixture run opens on the fixture's theme, or the one `pnpm shots --theme` forces (KERNEL-708).
