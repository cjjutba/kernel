**A session Kernel didn't start never asks in a workspace's chats, and its plans and questions stay in its own app.** The maintainer wrote a plan in the Claude desktop app inside the main checkout. The global hook posted its ExitPlanMode to the hook server, and `resolveCwd` matched the path to Kernel's workspace. An approval with no `chatId` shows in every chat of its workspace, so the plan appeared in Kernel's chat with an Approve button. Kernel's composer then sent whatever the maintainer typed as a plan rejection to the desktop session. Kernel can't tell which chat an outside session belongs to, and the main checkout is where the maintainer runs other Claude Code apps. So a `PermissionRequest` for ExitPlanMode or AskUserQuestion (`needsUser`) from a room's session now gets the empty response at once and opens no approval, and the app that started the session asks in its own window. Every other `PermissionRequest` from a room still opens an approval, but with `roomId` only. Chats, composers and the sidebar match on `workspaceId`, so the approval shows in Inbox and Home and nowhere else. Archiving a workspace no longer ends a hook approval, because it has no workspace. The session isn't the workspace's, and its approval still ends when that session stops waiting or the timeout passes. The `hook` bus event and the activity lines keep the full context, so agent status and logs don't change. Sessions outside every room still get the empty response at once. Amends D-138. KERNEL-285.
