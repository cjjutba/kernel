**A tool the quit cuts off says "Stopped when Kernel quit", whatever Claude Code answers for it.** When `shutdown` interrupts a turn, Claude Code answers the running tool with its own rejection text: "The user doesn't want to proceed with this tool use ... STOP what you are doing and wait for the user to tell you how to proceed." Kernel saved that on the row as `failed`, so after a quit the chat showed the user refusing a step they never refused. `shutdown` now marks each turn it interrupts, and every tool result that turn gets afterwards is saved as `failed` with `TOOL_STOPPED`, the same text the launch gives a row left on running. That covers a result that reports success too. One can only land in the moment between the interrupt and the tool's end, and the relaunch nudge already tells the agent to check what finished. A Stop pressed before the quit isn't marked, so its row reads as any Stop does. Claude Code's own transcript keeps its text, and the nudge tells the agent Kernel closed. Amends KERNEL-215.

Once `shutdown` has ended a process, its stream is left alone. The SDK keeps delivering lines it had read, then throws once the process exits, and that often comes after `stop()` has closed the database. `consume` ignores those lines and skips its end-of-stream work for a process Kernel ended while quitting. Nothing there changes what carries on, since `shutdown` already froze the journal and kept the queue. Before this, each quit logged "The database connection is not open" from that work.

A chat a quit cut off gets its nudge once the launch check (`claude auth status`) finishes, as KERNEL-215 decided, and `start()` still doesn't wait for it. The live relaunch test read the nudge right after `start()` returned, so it found none. It now waits for it. KERNEL-396.
