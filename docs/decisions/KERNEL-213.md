**Only four first-run failures block: Claude sign-in, the hook port, a missing git, and Kernel's own copy of Claude Code not starting.** Each `PreflightCheck` carries `blocking`. Kernel can't run an agent without those four, so they keep the user on the checks screen. Every other failure is a warning. A missing or signed-out `gh` only costs pull requests, offline gh is the same, an old git only loses conflict lists, and the `claude` on PATH is only for fixes typed in Terminal. Agent teams being off is a warning too, which amends D-027: it is a Kernel setting the user can turn off on purpose, and KERNEL-225 removes the check.

The claude check runs the binary sessions run: `packagedClaude()` in a packaged app, otherwise the SDK's `claude-agent-sdk-<platform>-<arch>` package, resolved from the SDK the way the SDK resolves it. Sign-in is read with that same binary. It shares the user's Claude credentials, so its `auth status` matches what agents will see. The `claude` on PATH is then checked only for existence, and a missing one points at the official installer (`curl -fsSL https://claude.ai/install.sh | bash`), which needs no Node. The issue named sign-in and the port as the only blockers, but a bundled binary that won't start means no session can, so it blocks as well. A healthy install never hits it. A binary that isn't there says "Reinstall Kernel". One that runs and fails offers its own `--version` as the command to try, so the row keeps a Check again button. The version call waits up to 60s, because the first run of a freshly installed binary can be slow while macOS scans it.

gh goes through `gh auth status --hostname github.com --json hosts` instead of `gh api user`. gh still checks the token with GitHub, but a check that can't reach GitHub comes back as an error entry with the login still in it, while a revoked token comes back as a 401. Kernel reads the first as offline (warning "Can't reach GitHub") and the second as signed out. `ghUser()` returns a login only when gh reports success, as before. A gh too old for `--json` on auth status falls back to the plain text, where exit 0 means signed in.

Git below 2.38 lacks `merge-tree --write-tree`, which `conflictFiles` uses, so the check warns from 2.38 down. A missing git offers `xcode-select --install`. On a Mac without the command line tools, running `git --version` for the check opens macOS's install dialog, which is the fix anyway. KERNEL-213.
