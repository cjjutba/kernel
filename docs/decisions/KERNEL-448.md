**The login shell read brings proxy, certificate, provider and Linear settings along with PATH. Amends KERNEL-247 and D-061.** Opened from Finder, Kernel got launchd's environment, so a proxy or a company CA set in `.zshrc` never reached agents, git or gh, and neither did Bedrock or Vertex. `refreshPath` now runs one `$SHELL -ilc` that prints PATH and a fixed list as `name=value` pairs between markers, NUL-separated: `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY` and their lowercase forms (curl and git read those), `NODE_EXTRA_CA_CERTS`, `SSL_CERT_FILE`, `CLAUDE_CODE_USE_BEDROCK`, `AWS_REGION`, `AWS_DEFAULT_REGION`, `AWS_PROFILE`, `CLAUDE_CODE_USE_VERTEX`, `ANTHROPIC_VERTEX_PROJECT_ID`, `CLOUD_ML_REGION`, `ANTHROPIC_BASE_URL` and `LINEAR_API_KEY` (`SHELL_VARS` in `shellPath.ts`). No other name leaves the shell. Each one takes the shell's value, else the value the app launched with, else is unset, and goes into `process.env`. That is KERNEL-247's "Mac's environment" layer, so `sessionEnv` and `codexEnv` both get them through `envFor`, and Kernel's own git and gh calls do too. KERNEL-247 still keeps `ANTHROPIC_*` and `CLAUDE_CODE_*` names from app variables, env files and room variables out of sessions. Only the Mac can pick Bedrock or Vertex, and the shell is part of the Mac. The shell starts with these names as the app launched, not with Kernel's current values. Otherwise a value from the last read would come straight back, and a line removed from `.zshrc` would apply until a restart. Nothing logs a value, and what `refreshPath` returns holds names only. The maintainer chose to import Bedrock and Vertex rather than leave them to the terminal. Preflight then shows "Using Bedrock from your shell" or "Using Vertex AI from your shell" in place of Signed in, with `AWS_REGION` or `CLOUD_ML_REGION` at the right. AWS keys in the environment are left out on purpose. Bedrock users with a profile get it through `AWS_PROFILE`. KERNEL-448.

**`GH_TOKEN` and `GITHUB_TOKEN` pass on only when gh has no stored login.** gh uses either one ahead of the keyring, so a token exported for another tool would change who opens and merges PRs, and could carry fewer scopes. After the shell read, if one is set, Kernel runs `gh auth token --hostname github.com` with both cleared. Exit 0 means gh has a stored login, and both are removed from `process.env`. Otherwise the token stays, since it's the only way gh can sign in. The command reads the keyring or gh's config without the network, and its output is dropped. Preflight's gh line says where the login comes from, using gh's `tokenSource`: "from the keyring", "from `GH_TOKEN` in your shell" or "from gh's config file". A token Kernel left out gets the note from SetupGhIdentity. One it passed on gets the note from SetupGhToken. Other tools that read `GITHUB_TOKEN` in an agent's shell lose it while gh has a stored login. That is the cost of gh using one identity everywhere. KERNEL-448.

**The shell read gives up after 10 seconds, not 5, and preflight says so when it does. Amends D-061.** SetupShellTimeout says 10 seconds, and a heavy `.zshrc` with nvm and a plugin manager can pass 5 on a cold start, which used to drop the shell's PATH without a word. Startup still waits on the read, so a hung shell now delays the window by up to 10.5 seconds. A shell that answers, which is nearly all of them, costs a fraction of a second as before. The timeout row comes first and is a warning, so Continue stays on. Its Check again is bordered, per KERNEL-437. Under the PNG's detail it adds one line on where to look: a slow command in `.zshrc`, or one that waits for an answer. A bash shell reads `.bash_profile` there instead. A shell that can't start at all shows no row, as before. KERNEL-448.

**The fallback folders cover nvm, fnm, asdf, mise and pyenv.** When the shell can't be read, `commonBins` used to cover Homebrew, npm and the Claude Code installer, so node from a version manager was missing. nvm has no fixed bin folder, so Kernel picks the newest installed version matching `~/.nvm/alias/default`, else the newest version. An alias nvm resolves itself, like `lts/*`, gets the newest. fnm's default alias appears under all three folders fnm has used. asdf, mise and pyenv add their shims folders. KERNEL-448.
