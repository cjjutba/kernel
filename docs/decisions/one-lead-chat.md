**A chat with Kernel has no modes. The Lead chooses for each request whether to answer, do the work itself, hand it to teammates, or both.** This replaces the Hand off and Build here split of KERNEL-770, and the parts of KERNEL-778, KERNEL-805, KERNEL-1050 and KERNEL-1051 that hung on it. The Lead is better placed than the user to say whether a change is one PR in one lane and short, or has parallel pieces, other lanes and long work, and a chat that could only do one forced the user to guess and switch. `Workspace.leadMode`, `lead.setMode`, `lead.sendAsHandoff`, `suggest_hand_off`, `start_build`, `BUILD_HERE_REFUSAL`, the composer's mode switch and ⌘⇧H, the "New chats start in" rows in Settings, Agents and the project's Agents page, `team.leadMode` and `[agents] lead_mode` are gone. An old `leadMode` on a saved workspace, `team.leadMode` in the app's settings file and `lead_mode` in a project file are ignored without an error, and the app's settings drop `team.leadMode` when they load.

**Every chat can edit files, in a folder of its own.** The Lead has Edit, Write and NotebookEdit whatever its agent file's tools line says, as Build here did, and `disallowedTools`, plan mode and the user's permission mode still decide what runs. Plan mode closes file changes, commits, pushes and pull requests for every Lead chat, as it did for Build here (KERNEL-1113). A Codex Lead runs `workspace-write` like a teammate, and read-only only in plan mode. A new chat is cut with `cutWorkspace` by Settings, Git and worktrees, Workspace type (a worktree, or the current checkout), the way a Build here chat was, and New chat's Branch row picks its base again. No new chat starts on the shared main folder, and nothing edits it (KERNEL-1050): a chat that already sits there keeps its place until its next send, which holds the message, makes the chat's working copy with the path of KERNEL-1051 and KERNEL-1053 (`Lead.send`, `ownFolder`, `retryCopy`), and then goes. A failed copy keeps the message held and shows Try again. Send as Hand off is gone, since there is no read-only mode to fall back to. `MainFolder` stays only to keep those older chats on the latest main, to restore an archived one, and to remove the folder with its project. Nothing creates it any more.

**One rule replaces `LEAD_RULE` and `LEAD_BUILD_RULE`.** It is about 660 words, under the 1,050 of the old Hand off rule. It tells the Lead to answer, do it itself when the work is one PR in one lane and short, hand off when there are parallel pieces, other lanes or long work, and mix by doing its small part and handing off the rest. Before it hands off work that depends on its own uncommitted edits it commits them and starts the teammate from its branch with `base_ref`, or opens its PR first, and it never edits a file a teammate it handed work to is changing. The shared lines stay, tightened: Team updates, teammates' questions, reviews, writing and other chats. `forProvider` still rewrites the tool names for Codex. A plan approval no longer demands a hand-off. The reply says the plan is approved and that the Lead carries it out, doing or handing off each step as its rule says, and keeps the note that teammates start from the base and won't see uncommitted edits. The Stop hook no longer reminds the Lead to hand off, and `handoff.reminder` and `build.refused` left the telemetry events. Only what the chat still owes (KERNEL-749) comes at Stop.

**A chat's own PR always takes the teammate path.** `ownsFolder(ws)` in `@shared/leadWorkspace` (a Lead chat that is not on the shared folder) replaces `buildsHere` everywhere it was read: an automatic review of the PR (KERNEL-778), Team updates and their routing to the chat's tab, base watch, auto-merge, the open-checkout rule, and the move to a fresh branch after a merge (KERNEL-778, KERNEL-990), which now applies to every chat. `link_issue` works in every chat. Old transcripts keep their `leadMode` dividers and `modeSuggestion` items as plain notes with no Switch button.
