**Files to copy takes patterns, and patterns only match files git ignores in the main checkout.** An entry with a glob character (`*`, `?`, `[`, `]`, `{`, `}`) is a pattern. Anything else is an exact path and works as it did before: whatever file is at that path gets copied, ignored or not, and a missing one is skipped. For patterns, Kernel runs `git ls-files -z --others --ignored --exclude-standard --directory` once in the room's folder and matches each path with Node's `path.matchesGlob`. A tracked file is never on that list, so `.env*` leaves a tracked `.env.example` to git. `--directory` reports a wholly ignored folder like `node_modules/` as a single entry, so git never lists its contents, and Kernel drops every entry ending in `/`. It also drops paths with a `node_modules` or `.git` segment, which git lists when a folder isn't ignored as a whole, and symlinks. A pattern that is absolute or has a `..` segment matches nothing. An exact path that resolves outside the room's folder is skipped, and a leading slash still reads as relative, as it always did. The result is sorted by path and stops at 500 files. A folder room that isn't a git repo gets its exact paths and no pattern matches. `resolveFilesToCopy` in `src/main/services/filesToCopy.ts` is the only resolver. The room setup step, `copyLocalFiles` (workspace create and restore) and `files.preview` all call it, so the preview lists exactly what a new worktree gets. `matchesGlob` follows the usual glob rule that `*` and `**` don't match a leading dot, so `*` misses `.env` and a user writes `.env*`. Electron 38.8.6 runs Node 22.22.0, where `matchesGlob` prints no experimental warning. A folder git doesn't track yet, holding only ignored files, comes back as `dir/` and also file by file, so `src/**/.env` still finds a `.env` in it. KERNEL-245.
