**Files to copy takes patterns, and patterns only match files git ignores in the main checkout.** An entry with a glob character (`*`, `?`, `[`, `]`, `{`, `}`) is a pattern. Anything else is an exact path and works as it did before: whatever file is at that path gets copied, ignored or not, and a missing one is skipped. For patterns, Kernel runs `git ls-files -z --others --ignored --exclude-standard --directory` once in the room's folder and matches each path with Node's `path.matchesGlob`. A tracked file is never on that list, so `.env*` leaves a tracked `.env.example` to git. `resolveFilesToCopy` in `src/main/services/filesToCopy.ts` is the only resolver. The room setup step, `copyLocalFiles` (workspace create and restore) and `files.preview` all call it, so the preview lists exactly what a new worktree gets. Electron 38.8.6 runs Node 22.22.0, where `matchesGlob` prints no experimental warning. KERNEL-245.

**A wholly ignored folder is walked only when a pattern names it, and node_modules and .git never are.** `--directory` reports a wholly ignored folder like `node_modules/` or `secrets/` as one `dir/` entry and doesn't list what is inside it. When a pattern's literal prefix, the segments before the first one with a glob character, is inside such a folder, Kernel lists that prefix file by file with `git ls-files -z --others --ignored --exclude-standard -- <prefix>`. So `secrets/*.env`, `certs/*.pem` and `.vercel/*.json` work. `**/*.env` has no prefix and never reaches into an ignored folder. A prefix with a `node_modules` or `.git` segment is never expanded, so `node_modules/*.js` matches nothing, and any path with either segment is dropped wherever it comes from. The result stops at 500 files. A pattern that is absolute or has a `..` segment matches nothing. Only a folder with its own `.git`, the test `inspectFolder` uses, gets pattern matches, so a folder room inside a parent repo doesn't pick up the parent's ignored files. A folder room that isn't a git repo gets its exact paths only. KERNEL-245.

**Exact paths follow symlinks, and pattern matches skip them.** People share one `.env` between clones with a symlink, and an exact path has always copied the file it points to, so it still does. A pattern match that is a symlink is skipped, because a pattern can reach files nobody looked at. An exact path that resolves outside the room's folder, or has a `.git` segment, is skipped, so the preview always equals the copy. A leading slash still reads as relative, so `/inside.env` is `inside.env`. KERNEL-245.

**`*` and `**` don't match dot files or dot folders.** `matchesGlob` has no `dot` option, so `*` misses `.env` and `**/*.json` misses `.vercel/project.json`. A pattern spells the dot out instead: `.env*`, `.vercel/*.json`. KERNEL-252's UI explains this next to the field. KERNEL-245.
