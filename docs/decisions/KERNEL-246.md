**Run output is buffered into whole lines, and a lone `\r` is not a line break.** Each stream keeps the text after its last newline and adds the next chunk to it, so a line split across chunks shows once. The stream decodes as UTF-8, so a character split across chunks stays whole too. A newline is `\n` or `\r\n`, as before. A spinner that only writes `\r` keeps adding to one line, so once the buffer holds `MAX_LINE` (65,536) characters, Kernel cuts exactly that many off the front and shows them as a line. The limit counts characters, not bytes. When the cut would split an emoji in half, Kernel cuts one character earlier. Whatever is left when the process closes goes out as the last line. KERNEL-246.

**A run script's URL is the first local URL it prints, and a restart owns its own.** Kernel strips color codes from each whole line and matches `http(s)://` on `localhost`, `127.0.0.1`, `0.0.0.0` or `[::1]` with a port. A URL with no port doesn't count, because the port is how Kernel tells one dev server from another. `0.0.0.0` becomes `localhost`, since a browser can't open it, and a trailing `.`, `,`, `;`, `:`, `!`, `)` or `]` is dropped. Only run scripts get a URL. Setup and archive output is never matched. `script.url` pushes null when a run starts and when it exits. A restart stops the old process first, and anything that process prints afterwards, its exit included, leaves the new run's URL alone. KERNEL-246.

**`resolvePreviewUrl` refuses a port form it can't fill.** It fills `$KERNEL_PORT`, `${KERNEL_PORT}`, `$PORT` and `$((KERNEL_PORT + n))` for n from 0 to 9, the workspace's block of ports. A form it leaves behind, like `$((KERNEL_PORT + 12))` or `${OTHER}`, makes it return null. The alternative was opening a half-filled address. The result must be an http or https URL with a host. KERNEL-246.

**Kernel hands only http and https URLs to the browser.** Both ways the renderer opens a URL with `shell.openExternal` check it with `isWebUrl` first. `system.openExternal`, which Open, PR links and toast actions use, throws for anything else. The window open handler gets every link with `target="_blank"`, including links in an agent's chat message, and it now opens only http and https. It still denies the new window either way. So a `file:///Applications/Calculator.app` link, a `javascript:` link or another app's scheme opens nothing. These two handlers are the only places Kernel calls `shell.openExternal`. A link that navigates the main window in place, with no `target`, is not covered here. KERNEL-246.

**`[[preview.urls]]` is one value, and an empty list unsets it.** The list is an array of tables, `name` and `url` each. Kernel drops an entry with no address on read and on write. A blank name is kept, because the UI may save a row before it is named. A patch replaces the whole list. A patch whose list is empty, or has only rows with no address, removes the key the same way `null` does. In the personal file that brings back the shared file's URLs, so removing your last row can't leave you with an override that hides them. To have no URLs in a room, clear the shared list. Fixture mode follows the same rule. KERNEL-246.

**Fixture mode derives `script.url` from the fixture's run output.** No fixture needs to list the URL by hand. `fixturePush` replays a fixture's events and adds the `script.url` the engine would push right after the first run output line with a local URL, plus a null before that run's exit. The Workspace fixture's table workspace prints `Next.js ready on http://localhost:4312`, so it is the one workspace with a URL. `RoomSettings.preview` is required, so `fixtures/platform.ts` got `preview: { urls: [] }` in its typed room settings, the only line this issue changes in a file the UI lane owns. KERNEL-246.
