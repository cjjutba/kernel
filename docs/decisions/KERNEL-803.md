**Sending a message puts it at the top of the view, and the reply fills in under it.** This amends KERNEL-605 (the chat follows its end) and KERNEL-629 (following waits for the reader's gesture): a send no longer pins the view to the end.

- On the reader's own send (`followsSend`), the view scrolls smoothly until the message sits 24px from the top. Padding under the thread, set from where the message and the end of the rows are, fills the rest of the view, so a short chat anchors too.
- After that nothing moves the view. The thread stays unpinned, so the reply streams in below the message, and the Scroll to bottom button shows once the end of the rows passes the bottom edge. The padding isn't part of the thread: following and the button measure to the end of the rows.
- The padding shrinks as the reply grows and outlives the turn (KERNEL-837): ending the turn used to remove it, and a reply shorter than the view then dropped the view to the bottom. It is cleared only by the next anchor, by the reader scrolling by hand, and by leaving the chat. A chat that opens has none, since nothing is anchored until a send arrives while it is open, and a turn that ends moves nothing.
- Team updates, Lead hand-offs, PR notes and teammate messages aren't a send and never move the view.
- The rules for the reader's own scrolling are unchanged: scrolling up unpins, Scroll to bottom and scrolling back to the end follow again. Scrolling down by hand into the padding follows again, as reaching the end always did.

- The scroll aims again while it glides (KERNEL-825): rows far above the message are measured after the glide passes them and shift it, so the target is retaken each frame until the message has sat 24px from the top for a few frames. The reader's own scrolling ends the aiming.
- The first message sent from New chat anchors the same way (KERNEL-825). `startChat` marks the new chat (`markJustSent`), the transcript that mounts for it takes the mark and runs the same `sendAnchor` step as a later send. A chat reopened with the reader's message last has no mark and opens as before.

- The reader's scrolling, Scroll to bottom and a jump from the chat rail end the anchor (KERNEL-837). The padding is dropped once the view sits clear of it, so removing it never moves the view, and Scroll to bottom leaves no blank gap to scroll into. Until then the message is held at its gap when content under it changes size, as the Working line leaving does.
- A queued message anchors when it posts, unless the reader scrolled by hand since the last anchor: then the view stays and Scroll to bottom shows. The padding is computed again when the window resizes or the composer grows. Switching tabs mid-turn and back keeps the message at the top, since the place a chat leaves remembers the anchored message while its turn runs. A message taller than the view anchors its top.
- The new-chat fix (KERNEL-837): the mark `startChat` leaves (`markJustSent`) is no longer used up by the transcript's first mount. It stays until the anchor has settled, and a mark nobody used expires after 15 seconds. A transcript that mounts again while the chat opens anchors the message too, instead of opening like a reopened chat, which restored a spot without the padding and left the message at the bottom. Plan with Kernel on a GitHub issue and New agent mark their chats the same way.

- Answers anchor like a typed send (KERNEL-838). Approve, Request changes, a question's answer and an agent proposal's decision are `user` rows with `approvalId` and no `from` (KERNEL-836), so `followsSend` counts them and they land 24px from the top in Lead and teammate chats. The row shows Copy and no Edit, since it is not a prompt. The plan, question and agent cards draw their own answer bubble only when the chat has no `answer-<approvalId>` row, which keeps older chats as they were, so an answer is never drawn twice. This replaces the KERNEL-789 glide: Approve no longer sends the view to the end, because that cancelled the anchor's aim. The plan bar still closes with its animation. A decision made from Inbox or Home moves nothing in a chat the reader isn't looking at, and that chat opens at its end.

Rule: `anchorPad` and `anchorSend` in `Transcript.tsx`. KERNEL-803.

- The top edge of the transcript fades over 24px, only while rows are scrolled off above it (the chat top fade). A row cut at the top edge reads like a bug, and the gap used to cut the previous reply's footer in half. The fade is a mask on the scroller, visual only, with no fade at the very top so the first message is never dimmed. The anchor gap is the fade's height, so a sent message sits just below it, solid.
