**Only one copy of Kernel runs at a time.** Two copies would share `kernel.db`, and the second copy's start runs `approvals.expireStale()`, which expires every approval the first copy is waiting on. A second launch (`open -n`, or a dev build next to the installed app) asks for the single-instance lock before anything else starts. If another copy holds the lock, the second launch quits, and the running copy brings its window forward or opens one. The lock is per userData folder, so a dev run and the installed app block each other, which is the point. Fixture runs skip the lock because they have no database and their own userData. KERNEL-208.

**The window shows only the app's own page, and the bridge answers only that page.** `will-navigate` and `will-redirect` cancel anything that isn't the app's URL. A dropped HTML file, a link or a redirect used to load in the window and get the whole bridge, terminals and room scripts included. Every IPC handler goes through one wrapper that checks the sending frame's URL against the app's. The check compares protocol, host and path and ignores the query and hash, because the renderer routes on the hash. `ELECTRON_RENDERER_URL` is read only when the app isn't packaged, so the environment can't point a shipped app at another page. KERNEL-208.

**Links leave the app only for https, and Open in editor never runs a file.** `setWindowOpenHandler` and `system.openExternal` open `https:` and refuse everything else, `mailto:` included, since nothing in Kernel uses it. `system.openInEditor` accepts only absolute paths inside a room's checkout or a workspace's worktree. It runs `code` and, when that fails, shows the file in Finder. The old fallback was `shell.openPath`, which runs a `run.command` or `.terminal` file, and git checkouts carry no quarantine flag to stop it. KERNEL-208.

**The page gets no permissions except writing to the clipboard.** The permission request handler refuses everything, with one exception: `clipboard-sanitized-write` from the app's own page. Electron routes `navigator.clipboard.writeText` through that permission, and the copy buttons (messages, plans, branch names, the hooks snippet) depend on it. Reading the clipboard stays refused. KERNEL-208.

**The shipped binary can't be used as Node.** `electronFuses` in `electron-builder.yml` turn off `runAsNode`, `enableNodeOptionsEnvironmentVariable` and `enableNodeCliInspectArguments`, and turn on `onlyLoadAppFromAsar` and `enableEmbeddedAsarIntegrityValidation`. Before this, any local process could run its own code under Kernel's signature and Automation grant with `ELECTRON_RUN_AS_NODE=1`. `resetAdHocDarwinSignature` is on because flipping a fuse edits the binary and voids its ad hoc signature, and macOS kills an arm64 binary with a void signature. Without it, an unsigned `pnpm dist:mac` build dies on launch with exit code 137. The release smoke test used `ELECTRON_RUN_AS_NODE`, so it moved to a `--kernel-smoke-test` argument. With that argument the app loads `better-sqlite3` and `node-pty`, prints ok and quits before it opens a window, takes the lock or touches the database. `scripts/release.sh` also runs it with `ELECTRON_RUN_AS_NODE=1` and a `-e` script, and fails the release if Node runs instead. KERNEL-208.

**Library validation is on for Kernel itself and off for everything inside it.** The issue asked to drop `com.apple.security.cs.disable-library-validation` if the native modules still load without it. They do. In a Developer ID build with the hardened runtime and without the entitlement, the main process loads `better-sqlite3` and `node-pty`, because electron-builder signs both with Kernel's team. The SDK's `claude` binary is different. It carries its own native addons (`clipboard-napi.node`, `audio-capture.node`, `computer-use-*.node`), extracts them and loads them, and they aren't signed with Kernel's team. The entitlement is gone from `build/entitlements.mac.plist`, which signs Kernel's main binary, the process with the bridge and the Automation grant. `build/entitlements.mac.inherit.plist` keeps it for Electron's helpers and for `claude`. electron-builder signs every file other than the app itself with `entitlementsInherit`, so the helpers can't be split from `claude` without a custom sign step. Amends KERNEL-30's entitlements, which used one file for both. KERNEL-208.
