## New

- Agents, the Lead included, can run on Codex with your ChatGPT plan as well as on Claude Code, with each role's provider, model and effort set in Settings, Models and effort, and several Claude and ChatGPT accounts to switch between in Settings, Providers. (#349)
- The workspace header has an Open in menu that opens the workspace in any editor or terminal on your Mac, or copies its path, and ⌘O opens it in the app you used last. (#379)
- Room setup finds rules in a repo's CLAUDE.md and AGENTS.md that work against Kernel, such as committing straight to main or never opening pull requests, and pairs each with what Kernel tells agents instead. (#398)
- Settings, Files to copy warns when a file it copies into each workspace looks like production, such as one holding a live key, and lets you stop copying it. (#401)
- Rowan can start work from a GitHub issue in a room that uses GitHub Issues. (#403)
- Issues, New workspace and Link issue follow each room's tracker, so a room on GitHub Issues lists its own issues and a room with no tracker says so. (#403)
- Your personal agents and the agents from your Claude Code plugins now join every room's team, and Rowan can hand them tasks. (#405)
- A room's team can be limited to some of the repo's agents with a roster in the repo's Kernel settings, and agents written as subagents with no pull request workflow start as helpers. (#406)
- In a repo with no GitHub remote, Kernel merges a workspace into its base branch on your Mac with the room's merge method, and refuses while that branch's folder has uncommitted changes. (#407)
- In a repo with no GitHub remote, the workspace panel shows whether a branch can merge into main: ready, behind main with an Update branch button, conflicts, merging, merged, or blocked by uncommitted changes in your main folder. (#407)
- Bypass permissions in Settings, Permissions now lets Claude and Codex agents work without stopping for the Always ask list, and still stops them at Never allow, network off and any push that might reach a protected branch. (#413)
- The card for a new agent shows which MCP servers it can reach and which it can't, with the reason, such as Needs sign-in or Off in this room. (#414)
- Permission requests now say why Kernel is asking, in one line under the command, such as that Codex runs it outside its sandbox. (#421)
- Settings, Permissions now picks the permission mode (Manual, Accept edits, Auto or Bypass permissions), and each room can override it and remove the tools agents saved with Always allow. (#422)
- On a first run Kernel asks which permission mode new chats start in, and new installs start in Auto where it is available. (#423)
- Settings, Room, General shows which issue tracker a room uses and lets you switch it between Linear, GitHub Issues and None. (#424)
- Claude agents in Bypass permissions now run their commands in a sandbox that limits writes to the workspace, the repo's git folder, temp files and package caches, and network access to GitHub and the npm registries. (#427)
- A room's Agents page in Settings can set how many workspaces the Lead keeps open in that room. (#435)

## Improved

- Rowan's questions keep each answer to a few words and put the explanation underneath, instead of a paragraph in the answer itself. (#366)
- Questions from agents now wait for Send after you pick an answer, show long options in full, and tag the recommended one. (#368)
- A pull request that is merging, running checks or resolving conflicts shows the same spinner in its workspace, the PRs tab, Team updates and the sidebar, and failed checks, conflicts and requested changes are red in each of them. (#370)
- Plan mode turns on and off in about a second. (#371)
- The Settings column now keeps the sidebar's width and can be dragged, and every draggable edge lights up when you hover it. (#372)
- The panel toggle now ends the chat header in grey instead of sitting inside the PR band, and ⌘⇧B shows or hides the right panel. (#375)
- A new chat with Rowan names its branch and worktree folder once, from the chat's first title, and the breadcrumb follows the chat's name the way the sidebar does. (#376)
- Open in editor opens the editor you have installed, such as Cursor or Zed, instead of only VS Code. (#378)
- The dark theme uses neutral greys with brighter text, so panels, rows and labels are easier to tell apart and read. (#380)
- The window buttons and the sidebar button line up with the top of each screen and stay in place when you hide or show the sidebar. (#380)
- Kernel keeps the Linear key from Settings, Integrations in the Keychain instead of a plain file. (#381)
- A new chat waiting for setup shows your message, how setup is going, and what to do if it fails, and you can stop setup or send your message anyway. (#387)
- Always ask before in Settings, Permissions no longer lists drizzle-kit push and pnpm db:reset by default, so if you never changed that list and want Kernel to keep asking before those commands, add them back there. (#399)
- New rooms pick their install command and run example for Python (uv, Poetry, pip), Ruby, Elixir, PHP, Rust and Go repos as well as JS ones, and ask before an install that would run the repo's own code. (#399)
- Agent files are read the way Claude Code reads them, so a file with a mistake in it shows on Team with what went wrong instead of disappearing, and an agent's disallowedTools now holds on Claude and Codex. (#402)
- Merge uses a method the repo allows when the one in Settings, Pull requests isn't allowed there. (#404)
- Create PR follows the repo's PR template and contributing guide, and asks for Conventional Commits only when the repo checks them with commitlint. (#404)
- Settings, Skills and MCP lists every MCP server a room's agents can reach, claude.ai connectors and servers added for that repo only included, and switching one off there also applies to agents on Codex. (#408)
- Agents read the issue they work on from Linear or GitHub Issues without a tracker MCP server, and a task the Lead hands off from an issue starts with its description and latest comments. (#412)
- Before Rowan starts work on an issue, Kernel looks for a pushed branch, an open pull request or another assignee and asks you first when it finds one, and new branches never take a name someone already pushed. (#412)
- Hiring, editing or retiring an agent no longer leaves uncommitted files in your repo, because the change stays on your Mac. (#419)
- Room setup shows whether a room's pull requests go to GitHub or merge on this Mac, and a Mac with only local rooms no longer gets GitHub CLI warnings. (#424)
- Always allow in this room now covers a chained command when every part of it is allowed, keeps MCP tools and web fetches allowed for the whole room instead of one workspace, and stops Auto mode from refusing a step you allowed. (#426)
- The workspace no longer shows a banner when a chat passes 150k tokens. (#428)
- A new chat with Rowan answers right away while setup runs in the background, unless you turn on Wait for setup before the first message in Settings, Git and worktrees. (#433)
- Archiving, restoring and other actions you can see happen no longer show a toast. (#434)
